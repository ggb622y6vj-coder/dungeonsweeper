# 現行仕様書

作成日：2026-11-01（日本時間）。**この資料は実装の記録であり、初代Wizardryの完全再現を保証する資料ではありません。** 現行挙動の正本はコード。102のアイテム・呪文同期データは `data/notion-items.json`／`data/notion-spells.json` を参照。

## 1. ゲームループ・階層

町（訓練所・酒場・鍛冶屋・寺院・図書館・迷宮入口）→探索→遭遇／宝箱／守護者→階段で上下移動→町。
1Fは8×8、2Fは10×10、3F以降12×12。上下左右の隣接移動、左右旋回、後退、左右横移動。盤面クリックは旗の操作で、任意マスへ移動する操作ではない。
開始位置と守護者位置は乱数。チェビシェフ距離2以内（縦横の最大差が2以下）には守護者を置かない。開始位置の周囲と、守護者までの生成経路は安全。罠数は1F=9、2F=15、3F=23。階層・盤面サイズに応じて増え、盤面の22%を上限とする。
守護者マスへ入ると確認。いいえで直前マスへ戻る。1〜9Fでは撃破後その場所が下り階段になる。各階に固有守護者がおり、最深部は10F（MAX_FLOOR=10）。階段・転移とも11F以降へは移動できない。
10Fの守護者「迷宮の主」（labyrinthlord）を随伴の敵も含めて撃破するとゲームクリア。下り階段は作らず、クリアログを表示する。ログ再生終了後に「迷宮踏破」の表示と町へ戻るボタンを出す。宝箱がある場合は開封か放棄を済ませてから帰還できる。探索も続行でき、帰還後は再び探索できる。再度10Fを攻略しても下り階段は作らない。
踏破記録は `ash-v1` の `cleared` として保存し、未設定の旧セーブではfalseとする。帰還・階層移動・再探索でも保持し、町に「迷宮踏破済み」を表示する。旧セーブに残る10F以降の下り階段も無効化する。
上り階段は一つ前の階へ。1Fからのみ町へ。階段で「いいえ」はその場に留まり、同じマスに居続けても再発火しない。
同じ探索中は各階の探索状況を維持。町へ帰ると全階の記録を破棄し、新しいランダム迷宮にする。スコアとスコア履歴は廃止済み。

## 2. 探索・罠・遭遇

数字は周囲8マスの残っている罠数。作動した罠は消費され、周囲の数字も減る。
未探索へ移動時の遭遇率16%。探索済みは10%＋周囲罠数×0.5ポイント。左右横移動はさらに1ポイント加算。通常マスのみで遭遇判定。
通常は敵奇襲10%、味方先制10%。後退時は敵奇襲12%、味方先制10%。守護者戦は通常開始。警戒結界は敵奇襲を通常開始へ置換。
遭遇バナーは0.5秒。「敵が現れた！」「敵の奇襲！」「敵はまだ気づいていない！」をログにも出す。
床罠は針25%（1人3d6+4）、爆発25%（生存者全員に同一の2d6+3）、毒霧20%（全員毒）、麻痺の針15%（1人麻痺）、転移15%（同じ階の安全な通常マス）。「！」を0.5秒表示し「罠だ！」→罠名と結果の順で表示。
毒は移動・戦闘ターン開始時にHP−2。探索中の毒ダメージログは出さない。麻痺は移動・戦闘ターン・逃走試行で自然回復しない。強壮・気付け薬・真回復、または町帰還で解除する（石化付与時・死亡時の異常リセットも維持）。付与値4の数値形式を維持し、旧セーブの麻痺値も治療まで保持する。HP0は死亡・行動不能。

## 3. パーティー・成長

新規ゲームは0人。訓練所で作成・登録した冒険者から0〜6人を編成。先頭3人が前衛、残りが後衛。0人では迷宮入場不可。酒場での編成とパーティー画面での順番変更も利用可能。酒場では状態が正常(ok)のメンバーのみ加入可能で、死亡/灰/ロスト/石化は（死亡）/（灰）/（ロスト）/（石化）付きで選択不可。保存時も再検証し、拒否時は「死亡したメンバーは加入できません。」を表示。
行動不能な前衛がいるときは、行動可能な後衛を繰り上げる（032）。行動不能は `dead / ash / lost / stone`、HP≤0、または麻痺の保存値>0。睡眠・毒・沈黙・恐怖のみでは後退しない。先頭から行動可能者を最大3人選んで前衛に詰め、残るメンバーは元の相対順を保つ。後衛に交代できる者がいなければ順番を変更しない。例：A,B,C／D,E,FでBが死亡するとA,C,D／B,E,F、続けてAが麻痺するとC,D,E／A,B,F。麻痺解除だけでは元の位置へ戻らない。

前衛から後衛へ移った者だけ「{名前}が後列に下がった。」を1行表示する。並べ替えは味方の1行動、敵1体の行動（複数回攻撃や全体攻撃を含む）、全員分の毒tickの直後、全滅を除く戦闘終了、床・宝箱罠、探索の呪文・薬、町帰還およびロード時の寺院搬送後に実施する。全滅時の遺体処理では並べ替えない。全PARTY_FIELDSとコマンドを一緒に動かし、予約者・味方の予約対象をメンバーIDで新しい添字へ付け替える。敵対象のuid・列keyは保持する。並べ替えによる予約の消去はなく、通常のターン終了時のコマンド初期化は従来どおり。

ログの各スナップショットはその時点の順番・名前・HP/MP・状態・AC・能力値を表示し、後退ログの時点で新しい並び順に切り替わる。順番変更は `ash-v1` に保存される。

表示能力：Lv、HP、MP、STR、AGI、AC、IQ、PIE、VIT、経験値、NEXT。正常時の状態表示はなし。異常時のみ色付きタグ。
迷宮から町へ帰還するとき、正常（`status==='ok'`）なメンバーだけ経験値に応じて複数回レベルアップし、レベルアップした場合に結果をポップアップする。同じタイミングで正常なメンバーのHP/MPを新しい最大値まで全快する。死亡・灰・ロスト・石化はレベルアップせず、XPとHP/MPを保持する。宿屋は設けない。本作独自の仕様。Lv上限30。HPは後述の再計算、MPは従来の職業別成長ダイス（`mpGrowth`）を加算し、`mpFromLevel` の開始レベルを維持する。ACはレベルアップで変化しない。
死亡状態は本作の暫定仕様。メンバーの `status` は `ok`（正常）・`dead`（死亡）・`ash`（灰）・`lost`（ロスト）・`stone`（石化）。HPが0になると正常から死亡へ移行し、死亡・灰・ロストは帰還後もHP0のまま、MPも回復しない。帰還時の毒・麻痺解除は全員が対象。状態タグはログのスナップショットに同期して「死亡」「灰」「ロスト」「石化」を表示する。正常以外のメンバーがいるパーティーは迷宮に入れず、通常の帰還時に自動で控えへ移る。
迷宮から町へ帰還すると、パーティー内の死亡・灰・ロスト・石化を自動で控えへ移し、搬送結果をダイアログで知らせる。死亡・灰は寺院で蘇生でき、成功後も控えに留まるため、酒場で加入する。ロストは恒久状態で蘇生・加入できない。搬送ダイアログを閉じた後にレベルアップ報告を表示する。全滅時は町帰還を通らず遺体を迷宮に残す。町にいる状態のセーブをロードした時、パーティーに死亡・灰・ロスト・石化が残っていれば（029以前の旧セーブ）、同様に控えへ移して搬送ダイアログを表示し、直ちに保存する（この場合レベル報告は出さない）。迷宮内のロードは対象外。酒場で在籍中の非正常メンバーを残したまま保存しようとすると「死亡したメンバーを外してください。」と表示する。寺院では町で操作待ちのときのみ、パーティーと控えの死亡・灰のメンバーを蘇生できる。費用は**本作の暫定式**。死亡の費用はmin(100×Lv, 25×Lv²) G（Lv1 25・Lv2 100・Lv3 225・Lv4以上100×Lv）、成功率はclamp(50＋3×VIT,50,95)%、灰の費用はmin(250×Lv, 60×Lv²) G（Lv1 60・Lv2 240・Lv3 540・Lv4 960・Lv5以上250×Lv）、成功率はclamp(40＋3×VIT,40,90)%（clampは下限・上限で制限し、死亡は50〜95%、灰は40〜90%）。VITは `m.vit ?? 10` で読み、レベルは成功率に影響しない。成功時は正常に戻り、HP・MPとも最大値まで回復する。失敗時は死亡→灰、灰→ロストとなり、HP0を維持する。費用は成否にかかわらず消費し、金貨不足時は実行できない。正常・ロストは蘇生対象外。結果の状態・HP・MP・金貨は既存の `ash-v1` に保存する。
旧セーブの状態未設定メンバーは、町なら正常、迷宮内でHP0以下なら死亡、その他は正常とする。状態未設定の控えは正常とし、設定済みの状態は保存・再読込・編成変更で保持する。
必要経験値は個体ごとに抽選・保存。次Lvの増分＝round(115×(次Lv−1)×職業係数×[0.9,1.1))。係数：戦士0.8、魔法使い1.2、僧侶1、盗賊0.85、侍1.40、君主1.50、忍者1.45、司教1.60。旧セーブには専用移行処理あり。

### 能力値増減・HP再計算（099）

1レベル上がるごとに STR・AGI・IQ（`intelligence`）・PIE（`piety`）・VIT をそれぞれ独立に抽選する。乱数が0.30未満なら+1、0.30以上0.40未満なら−1、それ以外は変化なし。範囲は3〜18で、上下限を超える増減は変化なし。複数レベル上昇も1レベルずつ「能力値 → 成長後VITによるHP → MP → 呪文習得」の順で処理する。習得判定にはその時点のIQ/PIEを使い、能力値が下がっても既習得呪文は失わない。

最大HPは毎レベル `max(旧最大HP+1, 候補)` に更新する。候補は職業のダイスを新レベル回（侍だけ新レベル+1回）振り、各項へVIT補正を加えて最低1に丸めた合計。戦士・君主は1d10、僧侶・侍は1d8、盗賊・司教・忍者は1d6、魔法使いは1d4。VIT補正は3で−2、4〜5で−1、6〜15で0、16で+1、17で+2、18で+3。新規の初期HPは従来のまま。これは本作の採用仕様で、原作そのものの完全再現を保証しない。

レベル報告はメンバーごとに1行へ集約し、HP / MP / STR / AGI / IQ / PIE / VIT の差を表示する。正は `+n`、負は `-n`、0は `±0`。習得呪文の行は従来どおりで、ダイスの抽選内訳は表示しない。

敵のレベル吸収と抵抗無効化の代償は、能力値5種を一切戻さず、レベル・XP・HP/MP上限の近似減少と現在HP/MPのクランプを従来どおり行う。旧 `hpGrowth` はこの近似減少のため保持し、レベルアップ時の加算には使わない。`baseStr/baseAgi` は互換用に保持するが、レベルアップ・吸収時の再計算には使わない。

旧セーブのVIT未設定（nullを含む）はパーティー・控え・遺体の全レコードで `vit ??= 10` により補完し、乱数や版数フィールドを使わない。設定済みの値は再読込・保存で変えない。STR/AGI/IQ/PIE未設定時の既存移行は維持する。VITは寺院の蘇生成功率に影響するが、費用には影響しない。セーブキー `ash-v1` と `rosterVersion:1` は維持する。

### 石化（033）

石化は `member.status='stone'` として保存する。付与時のHP・MP・XPを保持し、毒・麻痺・睡眠は解除する。自然回復せず、毒tickも停止する。付与ログは「{名前}は石になった。」。敵1体の行動終了後、032の自動後退を行う。状態タグ・後退はそれぞれのログのスナップショット時点で表示する。

石化者はコマンド・呪文・薬・盗賊の開封を実行できず、敵の単体／全体呪文・ブレス・複数回攻撃および床／宝箱罠の対象から外す。対象選択で除外し、汎用ダメージ処理には無効化を追加しない。生存判定からも除外するため、石化者以外が全員死亡・灰・ロストなら全滅する。石化者はHPとstoneを保ったまま遺体データに残り、030の回収で控えへ戻る。戦闘報酬XPは石化者へ配分しない。

帰還時も石化のまま、回復・レベルアップを行わず寺院（控え）へ搬送する。町の旧セーブのロード時にも029bと同じ搬送を行う。搬送ダイアログ・酒場・訓練所に（石化）を表示する。解除するまでは酒場で加入できない。

寺院の「石化解除」はmin(150×Lv, 40×Lv²) G。料金は本作の仕様で、成功率100%、正常（ok）かつHP・全呪文レベルのMPを最大値まで回復する。XP・レベルは変えず、自動加入しない。金貨不足では実行不可。石化を解除できるのは寺院だけである。真回復は石化を解除しない。真回復は石化していない生存する味方1人のHPを全快し、毒・麻痺・睡眠・沈黙・恐怖を解除するが、MPは変えない。強壮・気付け薬・解毒剤などでも石化は解除できない。新しい呪文・アイテムは追加しない。

石化を与える敵はガーゴイル（4F）命中時5%、石巨人（6F）8%、邪眼（8F）10%、地震雲（10F）5%。既存の毒・麻痺は維持する。同じ命中で麻痺と石化が発生した場合も、石化時に麻痺を解除する。敵CSVの「石化/命中時N%」を `statuses: [{type:'stone', chance:N/100}]` に変換し、図鑑の特殊能力に「石化」を表示する。

### 沈黙（036）

味方の沈黙は `ailments[i].silence` に残りターン数を保存する。付与・重ね掛けで3に戻り、戦闘ターン終了ごとに1減る。0になったとき「〇〇の沈黙が解けた。」を表示する。逃走失敗も1ターンとして数える。探索やターン開始時の毒tickでは減らない。戦闘終了（勝利・敵の退散・味方の逃走・全滅）時に全員0とし、帰還時も `freshAilments()` で解除する。戦闘中のセーブ・再読込では残りターン数を保持する。

沈黙中の `spellReason` は「沈黙している」を返し、戦闘コマンドの「呪文」はグレーアウトする。攻撃・防御・アイテムは使用できるため、032の自動後退の対象に含めない。寺院の治療・搬送対象にも含めない。状態タグ「沈黙」はログのスナップショットに同期して表示する。

強壮と気付け薬は麻痺・睡眠・沈黙・恐怖を治し、真回復でも解除できる。沈黙中の本人は治療呪文を唱えられないが、気付け薬は使用できる。薬の追加、価格・宝箱表の変更はない。

### 恐怖（037）

味方の恐怖は `ailments[i].fear` に残りターン数を保存する。付与・重ね掛けで3になり、沈黙と同じ戦闘ターン終了時に1減る。0で「〇〇は落ち着きを取り戻した。」と表示する。逃走失敗も1ターン、敵の初手奇襲や探索のtickでは減らない。戦闘終了（勝利・敵の退散・逃走成功・全滅）時に全員0とし、全滅時の遺体記録にも残さない。帰還時は `freshAilments()` で解除する。戦闘中のセーブ・再読込では残りターン数を保持する。

恐怖中は近接・遠距離とも「戦う」がグレーアウトし、「恐怖で攻撃できない」と理由を表示する。予約済みの攻撃も実行時に止める。防御・呪文・アイテム・僧侶の解呪は使用可能。盾役を果たせる一時異常なので032の自動後退の対象外で、寺院搬送・治療の対象にも含めない。状態タグ「恐怖」（`.ailment-fear`）は `displayVitals` のログスナップショットに同期する。

強壮（説明「麻痺・睡眠・沈黙・恐怖を治す」）・真回復・気付け薬で解除する。恐怖中の本人も治療呪文を唱えられるが、沈黙が重なっている場合は唱えられない。気付け薬は恐怖だけの対象にも使用でき、沈黙と恐怖を同時に治せる。新アイテム・味方の恐怖付与呪文は追加しない。大減退／超減退は敵AC＋3の効果を持つ。

敵は亡霊（6F）・地獄の犬（7F）・魔界の猟犬（9F）が命中時15%、死神（10F）が20%で付与する。CSVの状態異常列 `恐怖/命中時N%` を `statuses: [{type:'fear', chance:N/100}]` に変換し、`monsterOnHit` の既存判定経路を使う。他の特殊能力は維持する。図鑑の特殊能力欄に恐怖タグと確率（15%など）を表示する。

simは恐怖中でも通常の治療・攻撃呪文選択を行い、通常選択で決まらなければ使用可能な呪文（恐怖治療・ダメージ・防御補助の順で優先）を選ぶ。MP不足・沈黙などで呪文を使えなければ防御する。職業は `jobOf(i)` で判定する。

## 4. 装備・アイテム

各メンバー10枠。武器・防具は1点につき1枠、薬は同じIDのスタックにつき1枠を消費。装備は武器1、頭1、胴体1、足1。装備一覧の空欄は「−」。職業制限あり。
鍛冶屋で購入・売却。装備中の品は売却・譲渡不可。探索中のアイテム譲渡と順番変更が可能だが、戦闘・ログ再生・確認中などでは不可。
遠距離武器（短弓・長弓・合成弓）は戦士・盗賊用で後衛からも攻撃可。近接武器は味方前衛のみ、敵前方2列まで。遠距離は敵全列。
薬：傷薬＝回復相当1d8回復、解毒剤＝毒解除。MP・習得不要、使用すると1個消費。装備品の各数値はDATA_CATALOG参照。

### 薬のスタック（107）

対象は薬5種のみ。1枠の最大数は傷薬10、解毒剤10、気付け薬5、上傷薬5、霊薬3。武器・防具の最大数は1。使用枠数は装備品数＋薬のIDごとの「個数÷最大数の切上げ」の合計で、傷薬15個＋剣1本なら3枠。上限10枠でも同じ薬の最後のスタックに空きがあれば入手・譲渡・取出しができる。スタックも満杯なら新しい枠が必要。

所持品・譲渡一覧・ボックス・薬選択は、薬を最大数ずつのチャンク行にまとめ、複数個だけ「傷薬 ×3」のように表示する。行順は各チャンクの先頭が内部配列に現れる順、操作対象はその先頭の添字。使用・売却・譲渡・預入れ・取出しは毎回1個だけ。所持品は使用枠数＋空き行で10行を表示する。戦闘の薬予約は `{slot,target,id}` を維持し、解決時にslotのIDが異なれば同じIDの最後の添字を消費する。残っていなければ不発。

保存形式 `ash-v1` と内部のID配列は変更しない。読込時は使用枠数が10以下になるまで末尾から1個ずつ取り除き、削除した装備の参照を補正する。10枠以内なら要素数が10を超えても保持する。

### アイテムボックス（106・107）

町のアイテムウィンドウにだけ「アイテムボックス」の入口を表示する。ステータス画面・鍛冶屋の「アイテム・売却」のどちらから開いても、対象メンバーはそのままでパーティー共通のボックスを使う。閉じると背後のアイテムウィンドウへ戻る。

容量は全カテゴリ合計100枠（装備品数＋薬のスタック数）。武器・頭・胴体・足・アイテム（薬）の5タブに分け、各タブでボックスと対象メンバーの所持品を装備1点または薬のチャンク単位で表示する。ボックスの使用枠数（n/100）と対象メンバーの使用枠数（n/10）を表示する。

預ける／取り出す操作は町で操作待ち（idle）のときだけ可能。預けるには対象の所持品が存在し、装備中ではなく、ボックスに空き枠または同じ薬のスタックの空きが必要。装備中の品も表示するが「装備中」と明記して預けるボタンを無効にする。取り出すにはボックスに対象の品が存在し、対象メンバーに空き枠または同じ薬のスタックの空きが必要。どちらも満杯なら理由を通知して状態を変えない。預けた際は後続の武器・防具の装備参照を詰め、取り出した品は所持品の末尾へ加える。

ボックスは `s.itemBox`（アイテムIDの文字列配列）として `ash-v1` とJSON書き出し・読み込みに保存する。新規開始・冒険データのリセットでは空、旧セーブで未設定なら空として読み込む。迷宮の再生成・階層移動では保持する。JSON読み込みでは任意項目とし、存在する場合は文字列配列かつ100件以下であることを検証する（107ではvalidateSaveDataを変更しないため、ボックスの要素数が100を超えるJSONは読み込み不可。通常の自動保存・再読込は保持する）。

## 5. 戦闘と列

通常遭遇は同階の非守護者から1〜3列を抽選。同じ敵が複数列になることもある。1列は同種で、頭数はその敵の群れ範囲。敵のHPは非表示。
行動可能なメンバー順にコマンドを決める。戦う・守る・呪文・アイテム、僧侶・君主には呪いを解く。後衛の近接装備では戦うを出さない。呪文選択ウィンドウでは呪文のみを決定し、対象は元の画面で選ぶ。対象候補が1列なら選択画面を省略。
全員決定後は行動確認表をパーティー表示上へ出す。「この行動で戦う」「戻る」。処理後は前衛が戦う、後衛が守るへリセット（過去の「全員攻撃へ戻す」要望とは差がある）。
味方全員→敵全員の順で処理。速度による交互行動は未実装。味方先制では最初の敵ターンを省略。敵奇襲では入力前に敵が行動。
敵列の内部row/keyは変えず、全員rewardedとなった列を列一覧から除外し、表示indexを詰める。撃破ログ前はスナップショットにより元の位置に残る。
選択した列の敵が行動時に全滅していた場合、到達可能な最前の生存列へ無言で切り替えて攻撃する。近接は現在の前2列、遠距離武器は全列が対象。到達可能な生存列がない場合のみ「攻撃対象の列は全滅している。」と表示する。現状、列内では最初の生存個体を選ぶ（ランダム選択ではない）。

### 味方物理攻撃の現在の式

職業の攻撃回数は戦士1+floor(Lv/5)、侍・君主1+floor(Lv/6)、忍者1+floor(Lv/8)、その他1。武器最低回数との大きい方へ武器効果の追加回数を加え、上限10とする。
STR補正はSTR≤5ならSTR−6、STR≥16ならSTR−15、他0。STR18は+3。
職業命中補正＝戦士・僧侶・侍・君主なら2+floor(Lv/3)、他はfloor(Lv/5)。
現在のコードの閾値＝clamp(21−敵有効AC−職業命中補正−武器命中補正−STR補正＋3×現在の列index,1,19)。0〜19の乱数が閾値以上なら命中。
1命中ダメージ＝max(1,武器ダイス＋STR補正)。合計後に旗効果。列indexは残っている列の並びで0から数え、前列消滅時は詰める。1列目の補正は0、2列目は命中率−15ポイント、3列目は−30ポイント（閾値の上限・下限に達しない場合）。原作への一致は未保証。
敵物理攻撃は別式：1d20で20は命中、1は失敗、他は出目＋敵hit＋Lv差補正＋味方AC≥20で命中。Lv差補正は `clamp(trunc((敵Lv−被弾者Lv)/3),−3,+3)`（0方向へ切捨て）。CSVのhitを基準にLv差3ごとに±1、最大±3を加える本作独自の調整で、原作の敵Lvを直接使う式の再現ではない。命中率は5〜95%、ACはダメージ減算に使わない。味方の物理命中式・図鑑表示・セーブ形式は変更しない。
守るは被ダメージを半分（切上げ）。味方AC＝職業基本AC−装備AC合計−補助呪文。戦闘補助と帰還まで持続する鉄壁の重ね掛けは最大効果を使用。

### 逃走・報酬

ボス・誤旗デバフ時は逃走不可。それ以外の逃走率は本作の暫定式：50＋5×（生存かつ非毒・非麻痺の味方平均Lv−生存かつ非睡眠の敵平均Lv）＋味方人数補正（1人15、2人10、3人5、その他0）を10〜95%に制限する。有効な味方が0人なら10%。失敗は敵ターン（味方先制権があればそれを消費）。
撃破時は経験値・金貨・ドロップ回数を戦闘内へ蓄積し、敵が全員いなくなった後に配分。合計XPが正の場合、勝利確定時の生存者数で分割し、各生存者に `Math.max(1, Math.floor(合計XP / 生存者数))` を付与。死亡・灰・ロスト・石化には付与せず、報酬ログは1人あたりのXPを表示。合計XPが0なら付与しない。逃げた敵・解呪で消えた敵は報酬なし。
自動の敵識別は遭遇時と毎ターン開始時、各列について生存メンバー最大IQ×3%（最大100%）で抽選する。成功後は戦闘中保持し、呪文由来の印は付けない。敵一覧・対象選択・攻撃ログは識別状態に従う。

### 呪いを解く（暫定）

僧侶・君主の特殊行動（司教は不可）。MP不要、選択した1列の生存する不死それぞれに判定。対象候補（生存する不死のいる列）が1列なら選択画面を省略してその列を自動選択する。2列以上なら列を選ぶ。成功率は `clamp(5%, 95%, 50% + 5%×術者Lv − 10%×敵Lv + 5%×12)`。敵Lvの係数は術者Lvの2倍で、敵Lvが1上がるごとに成功率が10ポイント下がる。補正K=12は、出現階の適正パーティLv（1Fから順に3,5,7,9,11,12,14,15,17,19）での不死Lv中央値を使う。現CSVの不死Lvを昇順にすると `2,4,5,6,7,8,9,11,13,15,15,18,18,20`、中央2値は11と13で中央値12。6F亡霊Lv11への適正Lv12での成功率は60%で、旧式の55%から+5ポイント。成功すると消滅、XP・金貨・ドロップなし。全員解呪のみなら宝箱なし。

### 窒息（043）

魔法使い（job 1）のLv9で確定習得、消費MP5、戦闘専用、敵全体が対象。`threshold-death` の `value=7` に従い、`monsterLevel(e) <= value` かつ不死・構造体・守護者でない生存個体を、系統別呪文抵抗の判定後に即死させる（即死効果自体の確率判定はない）。成功時は「息絶えた」、無効時は「には効かなかった」を表示する。死亡処理 `killByMagic(e)` はHPを0にしてログのスナップショットを記録し、`killReward` で経験値・金貨・ドロップを通常どおり蓄積する。経験値は勝利時に配分し、解呪の無報酬処理とは異なる。

大窒息も同じ死亡処理を使用する。列対象・確率は維持し、不死・構造体・悪魔・守護者を無効とする。原作参考資料の [MAKANITOの項](https://www.zimlab.com/wizardry/walk/wizardry-123-game-calculations.htm) は不死とLv8以上を無効としている。本作の習得Lv9・MP5・構造体と守護者の除外は本作向けの仕様。

習得一覧はメンバーの `known` に保存される。ロード時、Lv9以上の魔法使いの既存一覧（パーティー・控え）へ窒息を重複なく補完する。他の呪文の再抽選、セーブキー `ash-v1` の変更はしない。習得一覧自体が欠けるパーティーメンバーは従来の習得移行処理で補完する。

シムは従来の魔法使いAI開始条件（MP6以上）を維持し、実効コストを払えて、実際に有効な生存個体が全列合計3体以上いる場合に優先使用する。構造体も数えず、沈黙・未習得・旗による必要MP増加も確認する。恐怖時の代替呪文選択でこの条件を迂回しない。現行データでは5F以降の全敵に無効。

### 沈黙（036）

僧侶（job 2）のLv3で確定習得、消費MP4、戦闘専用、敵1グループ（列）を対象とする。個体ごとに誘睡と同じ `clamp(49+5×(術者Lv−敵Lv),0,94)` %で判定し、ボス・守護者には無効。成功した敵は `e.silence=true` となり、戦闘終了まで継続する。沈黙中の敵が行動抽選で呪文を選ぶと通常攻撃に置き換える。ブレス・召喚・逃走には影響しない。数式・習得レベル・MPは本作の仕様で、原作の計算式との一致は保証しない。

敵の沈黙は生存かつ石化していない味方全員に、個別に `clamp(50+5×(敵Lv−味方Lv),5,94)` %で沈黙を判定する。詠唱ログは「〇〇は沈黙を唱えた。」、各対象には「〇〇は沈黙した。」または「〇〇には効かなかった。」を表示し、HPダメージは与えない。使用者は闇の司祭（4F、行動30%）と魔女（8F、行動25%）。他の術者は変更しない。

敵CSVの呪文から生成する `spellInfo.effect` は `damage` または `silence`。沈黙は `dice:null`、`target:'all'` とする。逃走・召喚・呪文・ブレスの行動確率の合計が1以下である検証を維持する。図鑑では「沈黙（全体）」の形式で表示する（行動確率は表示しない）。

敵CSVの `出現階層` は「9F・10F」のように「・」区切りで複数の階を書ける。compile は昇順の `floors` と互換用の `floor`（最初の階）を出力し、守護者は1階のみ許可する。通常の敵の遭遇は `floors.includes(階)` で選び、図書館では最初の階の見出しの下に置いて詳細の出現階を「9F・10F」と表示する。サッキュバス・ダイダラボチは9F・10F。

simは沈黙中の僧侶・魔法使いの呪文方針をスキップし、射程内に攻撃対象があれば攻撃、それ以外は防御する。僧侶は治療を優先した後、沈黙していない非ボスの術者が同じグループに2体以上いれば沈黙を検討する。習得・MP・ボス戦制限を確認し、敵の沈黙はharnessで本体の処理をそのまま実行する。

## 7. 宝箱

未探索マスの遭遇戦で報酬対象の敵を倒すと出現。敵撃破とログ再生が終わるまで操作ボタンを出さない。即開ける・放棄・使える場合仕掛解除・盗賊の開封。後回しにはできない。
罠はfixChestTrapが一度設定。仕掛解除は95%で正しく判別し解除はしない。通常開封は罠を作動させ、生存していれば報酬。盗賊・忍者のうち行動可能な先頭のメンバーが開封を担う。成功率は盗賊85%・忍者75%、失敗時は罠作動・箱消滅。ボタンは担い手の職業名で「盗賊が調べて開ける」「忍者が調べて開ける」と表示し、担い手がいなければ隠す。

通常戦闘の直接装備ドロップは倒した敵ごとに5%でdrop:trueの武器から。階層ごとの宝箱テーブルはまだない。

### 盗賊・忍者の床罠解除（075・095）

パーティーステータスの盗賊・忍者の「アイテム」横に「罠解除」を表示する。迷宮内で操作待ち・本人が行動可能・未使用・正面が範囲内の未探索マスの場合のみ使用でき、画面を閉じて実行する。盗賊・忍者1人につき遠征中1回、帰還時にリセットする。使用済みはメンバー自身に保存し、旧セーブで未設定なら未使用とする。正面の旗を外し、罠があれば取り除いて解除済みとし、罠の有無にかかわらず探索済みにして回数を消費する。移動・遭遇・宝箱・階段／昇降機／ボス確認・遺体回収・床罠発動は行わない。

## 8. 旗

怪力・堅牢・呪禁をループ切替し、設置時の種類をマスに保存。切替しても既設旗は変わらない。地図と視界で色を反映。

正旗は発動時だけ「○○の旗がはためいた！」。誤旗のみ戦闘開始時「誤った旗がパーティーを惑わせた！」。ログ色：怪力橙・堅牢緑・呪禁紫。

### キーボード操作の基盤（038）

`dist/keynav.js` を `index.html` の最後に読み込む。操作対象は、開いた順で最前面のダイアログ → 味方対象選択 → 戦闘コマンド欄（逃走を含む）→ 町 → 探索の優先順。戦闘の入力者・対象選択段階・ログ再生状態が変わる場合も既定位置へ移る。探索の確認・宝箱・帰還表示への切替も検出する。画面の `hidden` と `visibleCombat` に沿ったDOMを使い、未来の戦闘結果を参照しない。

W／↑・S／↓・A／←・D／→は要素の中心座標から指定方向の半平面にある距離最小の項目へ移り、端では停止する。ただし移動方向と垂直な範囲が現在の項目と重なる（同じ行・列の帯にある）項目があれば、その中で距離最小を優先する（040：町の全幅「迷宮への入り口」が2列グリッドの左右移動を奪わないため）。同距離はDOMの収集順。選択した要素を `scrollIntoView({block:'nearest', inline:'nearest'})` で表示する。対象はボタン・`data-*-choice`・タブに加え、入力欄・select・summaryなど。非表示・閉じたdetails内部・閉じたダイアログ・inertを除く。disabledは方向移動の候補に含めるが決定できない。ネイティブdisabledの解除はせず、無効ボタン上に論理フォーカス（`.kfocus`）を置き、DOMフォーカスは画面のコンテナへ置く。無効理由のtitleをPCヒントと読み上げ用statusで案内する。Tab／Shift+Tabは無効項目を飛ばす。図書館タブはA/D・左右キーで循環切替し、Home／Endは先頭／末尾タブへ移る。S／↓でリスト先頭へ降り、リスト先頭のW／↑で選択中タブへ戻る。リスト内のW/S・上下キーは項目順に移動し、末尾で停止する。Q/Eは画面内のどこからでも前／次タブへ切り替える（入力欄の編集中を除く）。

Space／Enterは選択項目の `click()` を1回実行する。押しっぱなしの決定・戻るは繰り返さない。Escは `data-key-back` の閉じる／キャンセル／戻るボタンを実行し、ダイアログを閉じると開く直前の項目に復帰する。入れ子のダイアログも開いた順で扱い、再描画時はid・data属性・登録者IDで元の項目を探す。対象が消えた場合は `data-key-default` の既定項目へ戻る。INPUT／TEXTAREA／SELECT／contenteditableに入力中はゲーム移動を行わず、Escはまず入力欄から閉じる等のボタンへ抜ける。名前欄だけはEnterで登録する（生成済みならその能力値を使い、未生成なら生成して登録）。名前欄のEscは「生成・再生成」へ抜け、次のEscで登録画面を閉じる。Ctrl／Alt／Meta付きとIME変換中のキーは処理しない。

`.kfocus` は3pxの金色アウトラインと暗い外縁。キー操作時だけ表示し、pointerdownで解除する。町の「設定」でキーヒントを表示／非表示にでき、`ash-keyhint` に `on`／`off` を保存する（未設定は表示）。`ash-v1` とは独立し、冒険データの形式・移行処理は変更しない。ヒントは幅701px以上かつ `(hover:hover) and (pointer:fine)` の端末のみ。390px・タッチ端末では表示しない。

探索中（dialog・戦闘・宝箱・階段確認がない間）は W／↑前進、S／↓後退、A／←左旋回、D／→右旋回、Q／E左右カニ歩き。Fで正面の旗を設置／解除、Gで旗種切替、Mで地図、Cでステータスを開く。RとTは割り当てない。プロンプト中は方向キーで選択肢を移動し、Space／Enterで決定する。地図dialogは閲覧専用で、Esc／Mで閉じる。長押しリピートは無視する。

### 戦闘・確認・報告のキー操作（041）

戦闘コマンドはWASDで選び、Space／Enterで決定する。無効なコマンド・呪文にも論理フォーカスを置けるが、決定は無効で理由をキーヒントに表示する。Escはコマンド欄の「戻る」（前の入力者、または列・呪文対象の取消）。全員入力後は「この行動で戦う」が既定。列・呪文・薬の一覧はW/Sで順に移り、端で停止する。2列の対象選択はA/Dでも移動できる。薬ダイアログはキー操作時に一覧ボタンを追加表示し、既存selectを残す。入力欄・selectのキー保護は038と同じ。

味方カードは実際の配置の同じ行・列へWASDで移る。死亡・灰・ロスト・HP0のほか、石化は真回復を含むすべての味方対象呪文・薬のキー候補から外す。ポインターで石化カードを選んでも何も起きず、メッセージは出ない。Space／Enterで確定、Escで取消。探索の対象バーも同様。戦闘ログ再生中はキー決定を受け付けない。

ボス／階段／宝箱の確認中は確認内だけを操作し、A/DまたはW/Sで循環する。既定はボス「いいえ」、階段「はい」、宝箱は先頭の行動可能な盗賊・忍者の「調べて開ける」（いなければ直接開ける）。Escはボス／階段で「いいえ」、宝箱では何もしない。放棄は明示的に選んで決定する。クリア表示は宝箱の処理後にSpace／Enter／Escで町へ戻る。レベルアップと寺院搬送報告はSpace／Enter／Escで閉じる。

ステータスのメンバーカードをWASDで移動し、Space／Enterでその持ち物を開ける。Tabでカード内の呪文などのボタンにも移り、持ち物の装備変更等は既存ボタンをSpace／Enterで実行する。

### 町・施設のキー操作（040）

町の既定項目は「迷宮への入り口」。パーティー0人で無効な場合も論理フォーカスを置き、Sで訓練所へ移れる。施設と詳細はdata-key-default／data-key-backを使い、Escで最前面の画面だけを閉じる。登録抹消とデータリセットの確認は「キャンセル」を既定とし、Dで実行ボタンを選んで決定する。Space／Enter／Escの長押しは一回だけ処理する。

酒場の「登録・転職・編集」は訓練所を重ねて開く。訓練所は「新規作成」と「転職・編集」の2タブを持ち、Q／Eと左右キーは既存のタブ操作に従う。新規作成タブで登録すると控えに入る。転職・編集タブでは転職・名前の変更・登録抹消だけを行う。加入・離脱・順番変更は訓練所にない。訓練所を閉じると、酒場が開いていれば登録者一覧をメンバーIDで読み直す。未確定の編成スロットは維持し、抹消したメンバーのスロットだけを空きにする。酒場のselectによる編成と、ステータス画面の順番変更は現行どおり残す。

### 薬・呪文の味方対象選択

味方1人を対象にする呪文は選択後、薬は所持品から選択、または薬ダイアログの「パーティー欄で対象を選ぶ」から、ダイアログを閉じてログ下のパーティー欄で対象を選ぶ。薬ダイアログで薬を変更した場合も選択モードへ進む。対象候補は `HP>0` かつ `status` が `ok` または `stone` の味方（`validAllyTarget`）。死亡・灰・ロスト・HP0は候補に入らない。毒・麻痺の味方は選べる。石化の味方は候補一覧には残るが、真回復を含むすべての味方対象呪文・薬で選べない。石化を解除する呪文はない。戦闘・探索とも、石化の味方カードはグレーアウト（不透明度0.4・`cursor:not-allowed`・強調なし、`.untargetable`）し、クリック・タップしても何も起きない（メッセージなし、MP・所持品を消費しない）。キーボード選択もスキップする（049、`beginAllyTargetPick` の `canWork`）。万一 `castMagic` がその経路で実行された場合は、真回復を含むすべての呪文で「〇〇では{名前}の石化を治せない。」と表示し、MP・アイテムを消費せず、対象のHP・状態を変えない。戦闘中に予約済みの真回復が、対象の石化によって拒否になる場合も同様に唱えず消費しない。蘇生は行わない。石化の解除は寺院のみ。

選択中はパーティー欄の下に案内バーを表示する。探索中はパーティー欄と移動操作の間、戦闘中は戦闘コマンド欄の下に表示し、パーティー欄とコマンド欄の位置を変えない。候補カードを枠線と軽いパルスで強調し、非候補を減光する。最初の候補へフォーカスし、タップ・クリック・Enter・Spaceで決定、Escまたはキャンセルで終了する。カードのタップ領域は44×44px以上。通常の能力値ダイアログ表示と探索移動は選択中は無効。再描画してもモードを維持し、ログ再生中は決定・キャンセルを受け付けない。

探索中は決定時に従来の呪文・薬の効果と消費を実行し、ログのスナップショット順に表示する。キャンセル時は呪文・薬の選択を保持して元のダイアログへ戻り、MP・所持品は変わらない。町での薬はパーティー欄が非表示のため従来のダイアログを使う。

戦闘中は決定時に呪文／薬の対象を予約し、次の行動可能メンバーへ進む。消費・効果はターン実行時。キャンセル・Esc・「戻る」では予約や入力位置を変更せず、対象選択中の呪文を解除してコマンド入力へ戻る。全員決定後の行動確認表は従来どおり。

対象選択はパーティー枠に統一する。薬ダイアログには薬の選択と「パーティー欄で対象を選ぶ」のみを表示し、味方対象呪文は選択後に探索・戦闘ともパーティー枠から対象を選ぶ。対象選択モードは保存しない。アイテム譲渡・装備の対象選択は従来どおり。

## 10. 訓練所の生成・登録

名前は1〜20文字（前後空白・HTMLに使う記号・制御文字を除く）。職業は戦士・僧侶・魔法使い・盗賊。登録確定前の再生成はセーブ対象外。登録時にUUIDを持つ独立したキャラクターとして控えに保存し、二重登録を防止。

基本STR/IQ/PIE/AGIは戦士12/8/8/10、魔法使い8/12/8/9、僧侶10/8/12/9、盗賊10/10/8/14。生成時はこの値を下回らず上限18。3〜9点を乱数で自動配分し、戦士はSTR、魔法使いはIQ、僧侶はPIEの選択重みを3、他を1とする。盗賊はSTR/IQ/PIE/AGIの重み2/2/1/2。上限に達した能力は抽選候補から外す。原作の完全再現ではなく、本作向けの生成式。

VITは既存4能力の基礎値・ボーナス配分と独立に `10 + floor(Math.random()*4)`（整数10〜13）で生成する。登録候補の能力値グリッド・前回生成との差分、登録一覧、ステータスにVITを表示する。

HPは従来の職業初期値±3、MPは魔法使い20±2・僧侶15±2・戦士と盗賊0。ACは既存バランス維持のため職業別基礎ACを固定し、装備のAC補正を減算する。ACの直接乱数化はしない。Lv.1・XP0で、必要経験値は従来の職業係数と乱数幅で一度生成して保存。初期習得呪文も従来の職業ルールを使用。

訓練所は「新規作成」と「転職・編集」の2タブを持つ。新規作成タブで登録した冒険者は控えに入る。転職・編集タブは全登録者の職業・Lv・能力値・参加状態を表示し、各行の操作は転職・名前の変更・登録抹消だけである。加入・離脱は酒場で行う。順番はステータス画面の順番変更で変え、酒場のスロットでも並びを決められる。登録抹消は別の確認画面で確定し、キャンセル時は変更しない。最後の1人も抹消可能。名前の変更は前後の空白を除いた1〜20文字とし、`<>&"'` と制御文字（セーブ検証と同じ）を含む名前は拒否する。パーティ在籍・控えのどちらでも変更でき、ash-v1 に保存する。名前の表示は既存の textContent 経路を維持する。町の迷宮再生成処理は従来通り。

## 11. 図書館

町で操作待ちのときに、パーティ0人でも開ける。モンスター・アイテム・呪文の3タブを持ち、上部に収集数／総数を表示する。モンスターは主出現階（データの先頭階）ごとの数字のみの下位タブ（1〜10）に分け、開いた直後は1を選ぶ。項目カードはPC幅で2列、700px以下では1列とし、進捗とタブ行は全幅のまま。アイテムは「武器・頭・胴体・足・薬」の下位タブに分け、開いた直後は武器を選ぶ。薬の独立した収集数／5は薬タブ内に表示する。

未遭遇・未入手の項目は「？？？」のみ。モンスターは遭遇時に `seen`、呪文「識別」の成功時に成功個体の種別へ `identified`（撃破の有無を問わない）を記録する。自動識別（IQ×3%）と撃破では `identified` は付かない。遭遇・撃破済みで未識別の種別は不確定名と撃破数のみ（同名の行が並ぶことを許す）。収集率「モンスター n/95」は識別済み（`identified`）の種類数で数える。旧セーブは `monsterIdentifyVersion` がなければ1回だけ `count>0` の記録を識別済みとして移行する。識別済みモンスターには確定名を見出しにして不確定名をその下に小さいサブテキストで（ラベルなし）表示し、続けて種族、出現階（「4F」形式）、HPのダイス式、物理ダメージのダイス（攻撃回数は別項目）、攻撃回数、特殊能力、使用呪文、経験値（CSV値）、撃破数（「n体」）の順に表示する。特殊能力のうち状態異常（毒・麻痺・石化・恐怖・睡眠・沈黙）はパーティー画面と同じ `ailment-tag ailment-{kind}` のタグに確率を添え、その他の能力（ブレス・アイテム奪取・レベル吸収・即死・仲間呼び・後衛攻撃・逃走）と耐性（炎半減など）は中立色の `ailment-tag ailment-other` タグで表示する。命中補正・ACは表示しない。初撃破階は表示しない（記録の `firstFloor` はセーブ互換のため保持）。守護者と迷宮の主には印を付ける。敵の数値非表示方針は、町の図書館で撃破済みを閲覧する場合のみ例外とする。入手済みアイテムには名前、職業、攻撃・hitBonus・最低攻撃回数またはAC・薬の効果、価格・売却価格、店売り／迷宮限定と迷宮での出現開始階を表示する。武器の近距離／遠距離は名前の横に中立色タグで表示し、種類欄と価格の「基準価格」表記は表示しない。名前と詳細はtextContentで構築する。全42呪文を `job` により「魔法使い」「僧侶」の下位タブへ分け、呪文タブを開いた直後は魔法使いを選ぶ。下位タブ切替時は一覧を先頭へ戻す。各職業内は習得レベルの昇順（同レベル内はデータ順）で、レベルごとにh3「Lv.N」を表示する。登録冒険者の誰かが一度でも習得した呪文だけ消費MP・使用場所・効果を呪文データから表示し、未発見の呪文は他タブと同じく「？？？」のみで名前・詳細を隠す。各項目はクリック／Space／Enterで詳細ダイアログを開き、Escで元の項目へ戻る。従来の一覧内の詳細表示も維持する。

記録は既存の `ash-v1` に `library: {monsters: {id: {count, firstFloor}}, items: {id: true}}` としてロスターとは独立して保存する。既存セーブは空から始め、所持品・初期装備・過去の踏破からの遡及登録は行わない。勝利確定時にその戦闘で実際に倒した個体をidごとに加算し、召喚個体も含む。逃走・解呪で消えた個体、および味方の逃走・全滅で終わった戦闘の途中撃破は記録しない。初撃破階は最初に記録した実際の階を保持する。

アイテムは購入成功時、宝箱・直接ドロップで所持品に追加した時点で登録する。薬も記録する。所持枠不足・職業不適合で受け取れなかった品は登録しない。売却・使用・全滅・キャラクター抹消・帰還・階層移動・再探索で記録は消えない。既存の明示的な「冒険データをリセット」では図鑑も消去する。


## 12. モンスターの呪文抵抗（063）

敵データCSV末尾の「魔法使い呪文抵抗」「僧侶呪文抵抗」は0〜95の整数%で、コンパイル結果は `mageResist` / `priestResist` の小数。空欄・範囲外はコンパイルエラー。初期値は出現階の最小値を基本値（1〜2F 0%、3〜4F 5%、5〜6F 10%、7〜8F 20%、9〜10F 30%）とし、悪魔は両系統+20、不死は僧侶+10、竜は魔法使い+10、構造体は魔法使い+15、守護者はさらに両系統+10。迷宮の主は両系統70%。上限95%。072で追加したキューズドバンブー・テングダケ・デクノボーはNotionの未設定値を0%として取り込む。この補正表は本作の暫定バランス設定。

敵へ向けた戦闘呪文（damage・sleep・silence・debuff・death・threshold-death）は対象個体ごとに、系統（魔法使いjob 1／僧侶job 2）に対応する抵抗値で `Math.random() < 抵抗率` を先に判定する。抵抗時は効果を適用せず「{表示名}は呪文をはね返した！」と記録する。抵抗されなければ既存効果（属性半減、レベル差、種族・ボス無効を含む）へ進む。敵が唱える呪文、識別、回復、味方補助、開放は対象外。戦闘画面・図書館には抵抗率を表示しない。セーブ形式変更なし。

### 079 C: 敵の呪文抵抗を操作する呪文

魔法使いの抵抗減少（nofice、Lv9、MP5、判定習得）は敵1列の各生存個体の魔法使い・僧侶呪文抵抗を百分率で半減し、端数を切り捨てる。同一個体へ重ね掛けしない。抵抗無効化（mahaman、Lv13、MP10、判定習得）は両抵抗を0にし、半減より優先する。両呪文とも守護者に適用し、抵抗ロールを行わず、戦闘中持続する。内部抵抗値は表示しない。

抵抗無効化は詠唱時に術者のLvを1下げる（Lv1では使用不可）。対象が既に抵抗0でも成立し、MPとレベルを消費する。既存ドレインと同じく、経験値を低下後レベルの必要累計値に戻し、職業別成長ダイスの平均を四捨五入してHP/MP上限を減らし、現在値を上限まで補正する。能力値5種・習得済み呪文・装備は保持する。

## 13. 転職（094・095：基本4職と上級4職）

町の訓練所から、パーティー・控えの正常なLv10以上の冒険者を別の職業へ転職できる。無料・回数無制限で、転職先で装備できる武器を所持していることが必要。同職への転職は不可。基本4職へはどの職業からでも転職でき、上級4職は直前の職業が以下の条件を満たす場合だけ選べる。新規作成は戦士・魔法使い・僧侶・盗賊（0〜3）のままで、上級職は転職専用。

| 上級職（番号） | 必要な前職 | 装備互換 | 新規呪文習得の系統・有効習得Lv |
| --- | --- | --- | --- |
| 侍（4） | 戦士または魔法使い | 戦士 | 魔法使い系、max(0, floor((Lv−2)/2)) |
| 君主（5） | 戦士または僧侶 | 戦士・僧侶 | 僧侶系、max(0, floor((Lv−2)/2)) |
| 忍者（6） | 戦士または盗賊 | 盗賊 | 新規習得なし |
| 司教（7） | 魔法使いまたは僧侶 | 魔法使い・僧侶 | 両系統、floor((Lv+1)/2) |

転職画面の職種ボタンは職業名だけを表示する。転職できるボタンは金色の枠と明るい背景で光って見え、選択中（aria-pressed）の見た目とは別である。転職できないボタンは無効のままで、理由は title に残す。前職条件を満たさない候補の理由には必要な前職の名前が入る。候補と比較は状態を変更せず、専用の確定ボタンでID・条件・武器を再確認する。キャンセル／Escでは変更しない。

転職後はLv1・XP0、新職の係数で必要XPを再生成する。HP上限・STR・AGI・IQ・PIE・VIT・所持品・習得呪文を保持し、MP上限は旧値から1割（切り捨て）を引いた値と新職の基準値の大きい方、現在HP/MPは全快。上級職のMP基準値は侍・君主・忍者0、司教18。`baseStr/baseAgi` は互換のため現在のSTR/AGIへ合わせるが、成長・吸収での再計算には使わない。侍・君主のMP成長はLv3→4から（`mpFromLevel:4`）、司教・基本職は従来の成長開始、忍者はMP成長0で引継ぎ上限を維持する。転職直後にHPは再抽選せず、新職でのレベルアップ時に第3節のHP再計算（旧上限+1保証）を行う。

装備可否は `canEquipJob` に集約し、102以降はアイテムの `classes` に上級職を含む全許可職を明示する。上表の互換を基本としつつ個別アイテムの職業リストを優先し、これを装備・鍛冶屋購入と表示・戦利品配布・転職時の付け替えで共用する。薬は全職使用可能。転職時の武器は現在のものが適合すれば保持、適合しなければ所持品の先頭から適合する武器だけを選ぶ。不適合な防具は部位ごとに外し、所持品は消費・追加しない。所持品が空の読込救済だけ、侍・君主には剣、忍者には短剣、司教にはメイスを使う。

呪文の使用は習得済みID・状態・場面・MP・対象で判定し、現職の系統は要求しない。引き継いだ呪文は転職直後から使用できる。新規習得は現職に対応する系統と有効習得Lvで判定し、魔法使い系はIQ/30、僧侶系はPIE/30を使い、以前の未習得呪文も再抽選する。侍・君主はLv3まで新規習得なし、Lv4から有効習得Lv1。司教はLv1で有効習得Lv1、Lv3で2。ただし転職時には呪文を追加せず、新職でレベルアップしたときに習得する。習得0件なら術者職でも呪文コマンドは表示しない。

両系統を習得していれば呪文ダイアログに系統タブを表示する。初期選択の優先は魔法使い・侍・司教が魔法使い系、僧侶・君主が僧侶系。戦士・盗賊・忍者で両系統なら魔法使い系。片系統のみならその系統を表示し、タブは隠す。切替で呪文選択と対象候補を消去し、開き直すと初期選択へ戻る。

特殊能力は現職で判定する。君主は僧侶と同じ解呪、忍者は盗賊と同じ床罠解除と宝箱解除を持つ（宝箱成功率だけ75%）。前職が盗賊でも現職が盗賊・忍者でなければ罠系能力は使えない。司教の鑑定・忍者の即死は追加しない。物理攻撃の回数と命中成長は第5節、罠の扱いは第7節を参照。

メンバー内の `careerHistory` に旧職・旧Lv・新職を追記し、転職確定時に `classChanged=true` を保存する。ステータス画面には前職を表示しない。履歴の読込修復では、実在する整数のfrom/to・from≠to・整数のfromLevel（10〜LEVEL_CAP）を満たす要素だけを残す。配列でなければ空配列、有効と不正が混在すれば不正要素だけを除去する。有効な履歴が残っていれば `classChanged` をtrueに補完し、一度trueになった値は履歴が空になってもfalseに戻さない。

旧セーブ向けの呪文自動補完（`ensureMagic`・`ensureMakanito`）は、`classChanged===true` または履歴1件以上なら適用しない。未転職の既存4職の補完結果（控えとパーティーの従来の差を含む）は維持する。転職で魔法使いになったメンバーの識別・判別はLv2へのレベルアップで習得する。上級職へ自動変換したり、読込のたびに呪文やXPを再抽選したりしない。

`classChanged` はメンバー内の任意の真偽値項目で、`ash-v1`・`rosterVersion:1` は維持する。パーティー・控え・並べ替え・全滅時の遺体・回収を通して職業・履歴・classChanged・習得呪文・装備を保持し、繰り返し読込でも変化させない。

## 14. セーブデータのJSON書き出し・読み込み（101）

町の「設定」のキーヒント切替の下に、書き出し／読み込みボタンを置く。操作待ち（`idle()`）のときだけ実行し、結果は設定内の `#savenotice` に表示する。自動保存の `ash-v1`、`rosterVersion:1`、起動時の読み込み・移行処理は従来どおり。

書き出しは `saveExportEnvelope()` で `{format:'dungeonsweeper-save', formatVersion:1, exportedAt:ISO日時, data:rosterSaveState()}` を生成し、インデント付きJSONをBlobと一時URLでダウンロードする。ファイル名は端末の現地時刻による `ds_YYYYMMDD_HHMMSS.json`。URLは使用後に解放する。冒険データ全体（控え・遺体・階層アーカイブ・図鑑を含む）が対象で、端末設定 `ash-keyhint` は含まない。通常のID補修を除きゲーム状態を変えず、localStorageへは書き込まない。

読み込みは5MiB以下のファイルをJSONとして解析し、プレーンなエンベロープ・format・formatVersion（1のみ）・dataを検査する。`validateSaveData(data)` は入力を変更せず真偽値を返し、以下を検査する。

- `rosterVersion===1`、ロスター配列と各レコード／membersのオブジェクト型、空でない一意の文字列ID、文字列name、整数job（0〜7）・level（1〜30）、有限数hp/mp、inventory配列、0以上の整数equipped、armor/ailmentsのオブジェクト型。
- `partyIds` は重複なし・全IDがロスターに存在する文字列配列で最大6人。`corpses` はオブジェクトの配列。
- 整数floor（1〜10）・size、cells配列の長さがsizeの二乗かつ64/100/144で、各セルはオブジェクト。goldは0以上の有限数。
- 任意のguardiansDefeated/elevatorFloors/logsは存在すれば配列。floorsは存在すればオブジェクトで、各値もオブジェクト、各値にcellsがあれば配列で長さ64/100/144。その他の項目は前方互換のため通す。

さらに `restoreRoster(structuredClone(data))` を試し、復元結果のcells長とmembers配列を確認する。確定前は `s` とlocalStorageを変更せず、候補はUI用一時変数だけに保持する。確認ダイアログには書き出し日時（現地時刻・欠落や無効値は「日時不明」）、登録人数、パーティ人数、地下N階、上書きの説明を表示する。動的文字列はtextContentのみで設定する。キャンセルを既定／戻る操作とし、キャンセル・閉じるでは候補とファイル入力を空にする。

「上書きする」で現在の `ash-v1` の生テキストを `ash-v1-backup` に退避（元がnullなら省略）し、候補dataを `ash-v1` に保存する。退避失敗なら書き込みを中止。保存失敗は確認画面内の `#importnotice` に通知する。読み戻しでrosterVersionとロスター長を確認し、不一致・解析失敗なら元の生テキストへ戻す（元がnullならキーを削除）。復元失敗も通知する。成功後はページを再読み込みし、既存の起動処理で反映する。書き込むキーはこの2つだけで、`ash-keyhint` は読み込みでも変更しない。合併・複数スロット・クラウド同期・暗号化は扱わない。
