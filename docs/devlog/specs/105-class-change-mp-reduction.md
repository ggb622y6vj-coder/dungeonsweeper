# 指示書105: 転職時にMP上限が若干減少する

## ユーザーの依頼（原文）

「転職した際にMPの最大値が若干減少するようにしてください。」

（減少量の解釈は Muse が提示し、ユーザーが承認した：引き継ぐ最大MPの10%（切り捨て）を差し引く。実装は Codex で行う。）

## 現行挙動（確認済み）

- 転職の確定計算は dist/recruits.js の classChangePreview()。MP上限は `maxMP: Math.max(m.maxMP, c.mp)` で、旧値と転職先職業の基準値（CLASSES の mp。魔法使い20・僧侶15・司教18、それ以外0）の大きい方になり、減ることはない。
- 転職後は現在HP/MPとも新しい上限まで全快する（next.hp=m.maxHP、next.mp=m.maxMP）。
- MP上限は保存値への加算でだけ成長する（レベルアップ時に mpGrowth を加算。HPのような再計算式はない）ため、転職時の一度の減少はそのまま持続する。追加の補正フィールドは不要。
- 転職確認画面（dist/training.js）の前後比較表は classChangePreview の結果（next.mp / next.members.maxMP）を表示するため、減少は自動的にプレビューへ反映される。
- 仕様書（docs/SPECIFICATION.md 第13節）には「MP上限は旧値と新職の基準値の大きい方」と記載されている。

## 実装内容

- classChangePreview() の MP上限の計算を次に変える：
  - 減少量 = `Math.floor(旧maxMP / 10)`（10%・切り捨て）
  - 新maxMP = `Math.max(旧maxMP - 減少量, 転職先の基準値 c.mp)`
  - 例：最大MP 33 → 30（減少3）。最大MP 9 以下では減少量0で変わらない。最大MP 0 の場合は基準値が下限になる（戦士→魔法使いは従来どおり20）。
  - 転職先の基準値が引き継ぎ値を上回る場合は従来どおり基準値まで上がる（僧侶15→司教は18）。
- 現在MPは従来どおり新しい上限まで全快する（変更しない）。
- 転職を繰り返した場合は、その都度その時点の最大MPから1割（切り捨て）を引く（追加の回数管理はしない）。
- パーティー在籍・控えのどちらへの転職でも同じ計算を使う（classChangePreview は共用されているため、追加の分岐はしない）。
- docs/SPECIFICATION.md 第13節の MP引き継ぎの文を、新しい計算（旧値から1割を引いた値と新職の基準値の大きい方）に書き換える。

## テスト

- tests/class-change.cjs（必要なら elite-jobs.cjs にも）に次の確認を追加する：
  - 最大MP 33 の冒険者を転職させると最大MPが30になり、現在MPも30で全快すること
  - 減少量の切り捨て（最大MP 19 → 減少1 → 18 など境界の確認）
  - 最大MPが小さい場合に減少量0で変わらないこと（最大MP 9 → 9）
  - 転職先の基準値が下限になること（最大MP 15 の僧侶 → 司教で18、最大MP 0 の戦士 → 魔法使いで20）
  - 控えの冒険者の転職でも同じ減少が効くこと
  - 転職プレビュー（classChangePreview の戻り値）と確定後の値が一致すること

## 制約

- dist のファイル数は増やさない。セーブ形式（ash-v1）には触らない。新しい保存フィールドを追加しない。
- HP上限・能力値・習得呪文の引き継ぎなど、MP上限以外の転職仕様は変えない。
- 検証：node tests/game.cjs 全件、関係するブラウザテスト、python3 scripts/compile-monsters.py --check、sim selftest、MANIFEST 一致。
