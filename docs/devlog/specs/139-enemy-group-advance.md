# 指示書139: 敵グループの列移動（原作 advance）

日付: 2026-11-25
ブランチ: hold/139

## 1. 概要と根拠

初代 Wizardry（狂王の試練場）の戦闘には、ラウンド終了時に敵グループが前へ出る仕組みがある。根拠は Data Driven Gamer による Apple II 版データの解析（The Bestiary of Wizardry）:

- 各モンスターの「強さ」= 残りHP − 3 ×（魔法使い呪文Lv + 僧侶呪文Lv）
- グループの強さ = OK 状態の個体の強さの合計
- 全グループの強さを計算した後、後ろの組から比較する（4組目と3組目、次に3組目と2組目、…）。確率 = 20% ×（後列の強さ ÷ 前列の強さ）+ 31% で、後列のグループが1つ前へ出る（2グループの順位が入れ替わる）

この仕組みにより、呪文を使う敵（強さが低くなる）は後ろに残りやすく、HPの高い近接系が前に出てくる。

## 2. 仕様

### 2.1 タイミング

- `attack()` のラウンド処理の最後、戦闘が継続する場合に1回だけ判定する。エンカウント直後（第1ラウンドの開始前）には行わない。
- 配置場所: 既存の `tickBattleSilence()` / `tickBattleFear()`、`resetCommandEntry()` / `resetPartyCommands()`、attackRows の再マップが終わった後、`render()` の前。戦闘が終了する経路（敵の全滅、味方の全滅、逃走の成立などで `s.enemy` が無くなる場合）では行わない。

### 2.2 強さの計算

- 個体の強さ = その個体の現在HP − 3 ×（種族マスターの `mageSpellLevel` + `priestSpellLevel`）。127で導入された戦闘中の現在呪文Lv（低下後）ではなく、マスター値を使う。
- グループの強さ = 「行動可能」な個体の強さの合計。行動可能の定義は131の行動可能数と同じ（hp>0 かつ 睡眠・麻痺・石化・恐怖のいずれでもない）。行動可能でない個体は数えない。
- グループの強さは0未満にならない（合計が負なら0とする）。

### 2.3 確率と入れ替わり

- 表示順（`enemyGroups()` の index）の後ろの組から順に、隣り合う組のペア（後列, 前列）を比較する。組が n 組ならペアは (n, n−1), (n−1, n−2), …, (2, 1) の順に処理し、各ペアの判定にはその時点の表示順を使う（入れ替わりが起きたら、次のペアは入れ替わり後の並びで判定する）。
- 確率 p = 0.31 + 0.20 ×（後列の強さ ÷ 前列の強さ）。ただし:
  - p は 0〜0.95 に収める。
  - 前列の強さが0で後列が0より大きい場合、p = 0.95。
  - 両方0の場合、比率を1として p = 0.51。
- 判定に成功したら2グループの表示順を入れ替え、ログに「○○が前に出た。」と出す。○○は前に出た（後列だった）グループの表示名で、左上の一覧（sceneEnemyRow）で使う名前と同じものを使う。
- 組が1組だけの場合は何もしない。

### 2.4 入れ替わりの実装上の意味（重要）

- 敵グループの row/key は安定IDであり、表示順とは別である（AGENTS.md のルール）。入れ替わりで変えるのは表示順（`enemyGroups()` の並び）だけとする。
- 変えてはいけないもの: 各個体の row 値、`s.enemy.spellLevels` のキーと値（グループに紐づくもの）、`s.attackRows`（予約済み攻撃の対象IDはグループに付いたまま動く）。
- 表示順は `enemyGroups()` が units 配列の初出順から導出する。入れ替わりは units 配列の並び替えで実現すること（2グループの初出位置が入れ替わるようにする）。召喚で末尾に追加された個体も rowKey でグループに属するため、並び替えで所属は変わらない。
- 入れ替わりの結果は、左上の一覧（sceneEnemyRow）、敵アイコン（drawEnemies）、到達可否（reachableEnemyGroups）、命中補正（グループ index 基準）に、次ラウンドから反映される。ログ再生のスナップショット（visibleCombat）でも、advance のログ行以降は入れ替わり後の並びが見えること（attack() 内で計算して log() すれば自然にそうなるはずだが、テストで確認すること）。

### 2.5 適用範囲

- 通常戦闘・守護者戦のどちらにも適用する。召喚された個体は所属グループの一員として扱い、独立したグループは作らない。
- セーブ形式の変更はない（units 配列の順序はそのまま保存される）。

## 3. テスト

新規 node テストを tests/ 配下に追加し、tests/game.cjs へ登録する:

- 強さの計算: 呪文Lvを持つ種はHPから引かれること、行動不能な個体は数えないこと、合計が負なら0になること。
- 確率の境界: 前列0・後列>0 で95%、両方0で51%、上限95%のクランプ。
- 入れ替わり: 乱数を固定して成功時に表示順だけが入れ替わり、row 値・spellLevels・attackRows が変わらないこと。3組以上で後ろのペアから処理されること。
- 組が1組では何も起きないこと。エンカウント直後（第1ラウンド開始前）には判定されないこと。
- ログ「○○が前に出た。」が出ること。

既存テストの追従が必要な場合は、新仕様への期待値更新として行い、検証の強さは落とさない（ラウンドをまたぐ戦闘テストでは advance の乱数を固定する等の対応がありうる）。
