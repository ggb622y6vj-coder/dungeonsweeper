# 指示書145: 探索中の呪文発動完了でステータス画面も閉じる

日付: 2026-11-26
担当: Codex（gpt-6.2-sol・medium）

## 背景

指示書138で、パーティー欄（#statsdialog）の呪文ボタンから呪文画面（#magicdialog）を開いた場合、発動後はパーティー欄に戻る形にした。実装上は `commitMagicChoice`（dist/spells.js）が発動後に `#magicdialog` だけを閉じるため、下に開いていたパーティー欄が残り続ける。

オーナーから「探索中、呪文を使った後、ステータス画面が出続けている。直してください」との報告があった。薬の使用完了時（指示書143で確認済みの挙動）は全ダイアログが閉じて迷宮画面に戻る。呪文もこれに揃える。

## 変更内容

探索中（戦闘でないとき）に呪文の発動が完了したら、パーティー欄も閉じて迷宮画面に戻る。

- 対象は `commitMagicChoice` の探索側の完了経路。「発動する」ボタンからの直接発動と、対象選択（`pickFieldSpell` の onPick）経由の発動の両方がここを通る。
- 発動完了時に `#magicdialog` に加えて `#statsdialog` も閉じる。パーティー欄が開いていない経路（メイン画面から直接呪文画面を開いた場合）では従来どおりの挙動になる（閉じる操作は無害）。
- 反呪文の結界で打ち消された場合も発動処理自体は完了しているので、同じく閉じる。

## 変えないこと

- 対象選択のキャンセル時の復帰（指示書138）: パーティー欄と呪文画面の両方が復帰する挙動はそのまま。
- 戦闘中の経路（`inBattle` の場合は `confirmCommand` へ進む）はそのまま。
- 発動できない場合の早期リターン（`spellReason` 等で弾かれた場合に何も閉じない）はそのまま。
- 宝箱の「仕掛解除」など、`commitMagicChoice` を通らない詠唱経路は対象外で不変。
- 薬・アイテム側の挙動は不変。

## テスト

- ブラウザテストのうち「発動完了後にパーティー欄へ戻る」ことを前提にしている検証があれば、新仕様（発動完了後はパーティー欄・呪文画面とも閉じている）に合わせて更新する。キャンセル時の復帰の検証は変えない。検証の強さは落とさない。
- `node tests/game.cjs` を実行し全 PASS を確認する。
