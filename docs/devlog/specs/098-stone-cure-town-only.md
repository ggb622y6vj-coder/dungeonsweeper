# 指示書098 — 石化は町（寺院）でのみ治療可能にする

## ユーザー要望

> 石化が町に帰るまで治療できないようにする

経緯：実装担当の比較実験（Codex と Grok Build に同じ仕様を別ブランチで実装させる）の題材として、ユーザーがこの変更を選んだ（2026-11-10）。本仕様書は両担当に共通で、解釈の余地はこの文書で固定する。

## 現行挙動（変更前、コードで確認済み）

- 石化は `member.status='stone'`。付与経路は敵の命中時効果（ガーゴイル等）とブレス付随で、本変更では触らない。
- ダンジョン内で石化を治せるのは真回復（madi）のみ。`dist/spells.js` の restore 処理が対象の `status` を `ok` に戻す。再抽選（reload）・一掃（sweep）はデータ上 restore だが id で特別処理されており、石化は治さない（変更不要・変更禁止）。
- 真回復だけが石化メンバーを対象に選べる。`castMagic` のガード（`x.effect!=='restore'` の例外）と、対象選択（`beginAllyTargetPick` の `canWork`／キーボード候補の restore 例外）がそれを許している。他の呪文・薬は石化メンバーを選べず、万一実行されても「{呪文名}では{名前}の石化を治せない。」と表示して消費しない。
- 町では寺院の石化解除が実装済み（費用 min(150×Lv, 40×Lv²) G、成功率100%）。帰還時に石化メンバーは寺院へ搬送される。この町側の流れは完成しており、本変更では一切触らない。

## 変更内容（固定事項）

1. 真回復で石化を治せなくする。真回復の石化以外の効果（生存する味方1人の HP 全快＋状態異常〔毒・麻痺・睡眠・沈黙・恐怖〕の解除）は変更しない。
2. 石化メンバーは、真回復を含むすべての味方対象呪文・薬で対象に選べない（対象選択でグレーアウト／キーボード選択でスキップ）。現行で他の呪文・薬がそうなっている扱いに真回復をそろえる。
3. 万一 `castMagic` が石化メンバーを対象に実行されても、真回復を含むすべての呪文で「{呪文名}では{名前}の石化を治せない。」と表示し、MP・アイテムを消費せず、対象の HP・状態を一切変えない。現在のガードの文言と挙動をそのまま真回復にも適用する形が想定だが、挙動が同じなら実装方法は問わない。
4. 戦闘中に予約済みの真回復が、対象の石化によって上記の拒否になる場合も、従来の他の呪文と同じ扱いにする（唱えられず消費しない）。
5. 変更しないもの：石化の付与・表示・自動並び替え・セーブ形式（`ash-v1`）、寺院の石化解除（費用・成功率・搬送・ダイアログ）、再抽選・一掃、薬の石化拒否（現行どおり）、`validAllyTarget` の定義。
6. 真回復の説明文は変更しない。石化は `status` であり「状態異常（ailments）」とは別扱いという整理のため、`dist/spells.js` の説明文、`SPELLS.md`、`data/notion-spells.json`、Notion の呪文 DB はすべて触らない（ユーザー指示：Notion DB は変更しない）。
7. `docs/SPECIFICATION.md` を新しい挙動に合わせて更新する（石化の節と「石化を解除する呪文は真回復のみ」という趣旨の記述を、寺院でのみ解除できる内容へ）。

## テスト

- `tests/petrify.cjs` は現行の「真回復で石化が治る」前提を広く固定している（対象選択で真回復だけ canWork が true、詠唱で解除、戦闘中の予約など）。これらを新仕様へ書き換える：真回復でも対象に選べない、実行しても拒否文言が出て MP を消費せず石化が続く、戦闘中の予約でも同様。
- 寺院で石化解除できることの既存カバーは維持する。なければ追加する。
- 期待値を緩めたりテストを削除したりしない。石化に関する検証の総量を減らさない。
- 新規テストファイルを増やす場合は `tests/game.cjs` への登録を忘れない。

## 検証

- `node tests/game.cjs` 全件合格
- `python3 scripts/compile-monsters.py --check` 合格
- sim selftest 合格
- ブラウザテストは検証担当（Muse）が別途実行するので、実装担当は実行しなくてよい。

## 制約

- セーブキー `ash-v1` を維持する。敵の HP・能力値をプレイ画面に出さない。ダイスの内部計算をログに出さない。
- バランス数値（石化の付与率、寺院の費用・成功率など）は変更しない。
- この指示書は比較実験用で、Codex 用ブランチと Grok Build 用ブランチの両方に同じ内容で置かれる。main への統合は、比較とレビューの後にユーザーが勝者を選んでから別途行う。
