# 指示書131：出現列数の原作方式化（随伴連鎖＋未設定時ランダム）と敵表示の変更

- 日付：2026-11-23
- 基準 main：675f60b（指示書130 統合・ライブ検証記録まで完了）
- ブランチ：hold/131
- 発端：ユーザーの4点の依頼（2026-11-23）。(1) 敵の出現列数を原作準拠にする、(2) 敵の表示は1列目と2列目のアイコン1体ずつだけにし個体数は出さない、(3) 左上の列表示の最後に行動可能なモンスターの数を表示する、(4) 列数の上限を増やし8体くらいまで出るようにする。
- 解釈の確定（ユーザー承認 2026-11-23）：随伴が未設定の場合はこれまで通りランダムに列を続ける。随伴率の抽選に失敗した場合はそこで編成を終える（原作どおり）。4点目は独立した上限ではなく、列上限の引き上げの結果として実現する。

## 1. 目的

通常遭遇の列の決め方を、130の「列数を先に決める混合方式」から、原作（Wizardry #1）の連鎖方式を土台にした規則へ置き換える。あわせて戦闘画面の敵表示を簡素化し（アイコンは最大2つ）、左上の列表示に行動可能数を追加する。随伴設定そのもの（データ・12種の設定例）は130のまま変更しない。

## 2. 編成規則の変更（dist/monsters.js の monsterFormation）

### 2.1 通常遭遇

1. 先頭の列は現行どおり、現階層の出現プール（撃破済みの守護者を含む encounterPool）からランダムに1種を選ぶ。
2. 列の上限は **min(4, 階層+1)** 列とする（1F 最大2列、2F 最大3列、3F以降 最大4列）。階層は現行どおり clamp 済みの floor を使う。
3. 次の列は、直前の列の種を見て決める。
   - 有効な随伴設定がある場合（partnerId が非 null、partnerRate > 0、随伴先が現階層の非守護者プールに存在する）：随伴率で抽選する。成功すれば随伴先が次の列になり、失敗すれば**そこで編成を終える**。
   - 随伴設定がない、または現階層では無効な場合：encounterPool からランダムに1種を選び、それを次の列として連鎖を続ける（その種から改めて本項の判定を行う）。
4. 上限に達したら編成を終える。
5. 守護者の重複排除（123）は現行どおり最後に適用する（守護者は最大1列。2列目以降に現れた守護者は通常プールから置換する）。置換は編成確定後の処理であり、連鎖判定には影響しない。
6. 廃止するもの：通常遭遇の「列数を先に 1〜3 等確率で決める」抽選と、その前提でのランダム補充（130の nextRow による失敗時ランダム補充を含む）。

### 2.2 守護者戦

1. 専用随伴のある守護者（現行データでは necromancer / vampire / labyrinthlord）：[守護者, 随伴先] を確定する（率は見ない。130どおり）。3列目以降は、随伴先の種から §2.1 の3の規則（随伴抽選→失敗で終了、未設定・無効ならランダムで継続）を上限まで適用する。
2. 専用随伴のない守護者：現行編成の完全なまま（[守護者, ランダム, 50% でランダム]、上限の対象外とする。130の暫定措置を維持）。

### 2.3 生成側の追従（dist/game.js の encounter）

- `formation.slice(0, 3)` の切り捨てを撤廃する（編成自体が上限を持つため）。
- 宝箱の基準種（formation[0]）、列ごとの呪文 Lv の独立（127）、召喚の上限、逃走・先手の仕様は変更しない。
- セーブ形式は変更しない（編成は戦闘開始時に生成され、保存されるのは生成済みの units のみ）。

## 3. 敵表示の変更（dist/game.js の drawEnemies）

1. アイコンを描くのは **1列目と2列目だけ**とし、各列で表示対象（rewarded でない個体）の先頭の1体だけを描く。3列目以降の列と、2体目以降の個体は描かない。
2. レイアウトは現行の列ベースを踏襲する：描く列（最大2列）について、現行と同じ要領で縦に並べ、アイコンは横方向の中央に1つ置く。高さ計算は描画する列数を分母にする。
3. 睡眠中の個体には現行どおり Zzz を出す（代表個体が睡眠中なら、その列のアイコンに出る）。
4. data-enemy-uid は代表個体の uid をそのまま付ける（現行の属性形式を維持する）。
5. ログ再生中のスナップショット（visibleCombat）経由の描画であることは現行どおり。

## 4. 左上の列表示に行動可能数を追加（dist/game.js の scene 内 .scene-enemies）

1. 各列の表示を「○列：名前 ×総数（行動可能数）」の形式にする。区切りは現行の「 ×」表記を維持し、その直後に半角括弧で行動可能数を付ける。例：「1列：ゴブリン ×3（2）」。
2. 総数は現行どおり、その列の rewarded でない個体数。
3. 行動可能数とは、その列の総数のうち、hp > 0 で、睡眠・麻痺・石化・恐怖のいずれでもない個体の数とする。沈黙・毒は行動を妨げないので行動可能に数える。
4. 行動可能数は常時表示する（総数と同数でも省略しない）。
5. 計算は表示用スナップショット（visibleCombat から得た enemyGroups）に対して行い、ログ再生中の表示とも一致させる。
6. 敵個体が実際に持ちうる状態フィールドは実装時に現行コードで確認し、存在しない状態は数に影響しないこと（現行で敵が持ちうる行動不能は睡眠のみだが、定義は上記の集合で固定する）。

## 5. テスト

### 5.1 新規テスト tests/formation-chain.cjs（tests/game.cjs へ登録する）

乱数を固定して以下を検証する。

1. 列数の上限：1F では最大2列、2F では最大3列、3F では最大4列までしか編成されない（未設定の種だけのプールで上限まで達することも確認する）。
2. 随伴の成功と失敗：随伴設定のある種が先頭の場合、固定乱数で成功すれば随伴先が2列目になり、失敗すれば1列で編成が終わる。
3. 未設定時のランダム継続：随伴未設定の種が先頭でも、ランダム抽選で列が続き、上限まで達しうる。ランダムで引いた種に随伴設定があれば、その次の列はその設定で判定される。
4. 現階層で無効な随伴（随伴先がその階のプールにいない）場合は、ランダム継続にフォールバックする。
5. 守護者戦：専用随伴のある守護者は2列目が随伴先で確定し、3列目以降は随伴先の種の設定で判定される（成功で連鎖、失敗で終了）。専用随伴のない守護者は現行編成（2列目まで確定、3列目は50%）のままである。
6. 撃破済みの守護者が通常遭遇に混ざる場合も、守護者は最大1列までしか現れない（123の重複排除の維持）。

### 5.2 既存テストの追従

1. tests/partner-formation.cjs：130の随伴判定（設定値・有効性・フォールバック）の検証は維持するが、列数の前提（先に1〜3列を決める）が変わるため、編成の列数に依存する期待は新規則へ書き換える。検証の強さは落とさない。
2. tests/encounter-adjustments.cjs：123の連続抽選の再現区間が新規則でも成立するか確認する。新規則では未設定の種からランダム継続するため、連続抽選の消費順が変わる場合は、その区間の前提（随伴率を0にする対象2種）は維持したまま、再現に必要な範囲だけ追従する。元の期待値と検証意図は変えない。
3. ブラウザテスト：敵表示に関する既存テスト（戦闘画面のアイコン数や列表示を前提にしているもの）があれば新表示へ追従する。新規に、3列以上の戦闘でアイコンが2つだけ描かれること、左上の列表示が「×総数（行動可能数）」形式になること、睡眠中の個体がいる列で行動可能数が総数より少なくなることを確認するテストを追加する。
