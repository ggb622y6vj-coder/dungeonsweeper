# 061 [light] モンスターの出現階を複数指定できるようにする（Notion 同期）

## 背景
- Notion の「出現階」が複数選択に変わりました。サッキュバスとダイダラボチは 9F・10F に変更されています（差分：/workspace/notion-monster-diff2.md）。
- 今は CSV の `出現階層` に 1 つの階しか書けません。compile-monsters.py は `floor` を数値 1 つにしています。遭遇の抽選（dist/monsters.js の `d.floor===floor`）、図書館の階見出し、MAX_FLOOR の計算も、この 1 つの値を使っています。

依存：なし。062 より先に行います。058〜060（hold）と同時に進める場合は、図書館の部分をマージするときに調整します。

## 仕様
- CSV の `出現階層` に「9F・10F」のように複数の階を書けるようにします（区切りは「・」）。
- compile では `floors:[9,10]`（昇順）を出力します。互換のため `floor`（最初の階）も残します。
- 遭遇の抽選では、通常の敵を `d.floors.includes(floor)` で選びます。守護者は 1 つの階だけを許可し、compile で assert します。
- 「各階に守護者 1 体・通常の敵がいる」という assert は `floors` を使って判定します。
- MAX_FLOOR などの最大階の計算は、`floors` の最大値を使います。
- 図書館では、最初の階の見出しの下に表示します。詳細の出現階は「9F・10F」と表示します（060 実装後は nF 表記。060 前なら「地下9・10階」）。
- CSV の更新：サッキュバスとダイダラボチを「9F・10F」にします。

## OKの判定方法
1. `python3 scripts/compile-monsters.py` を実行し、サッキュバスとダイダラボチが `floors:[9,10]` になっていること。
2. 9F で遭遇を大量に回すテスト（tests/monster-floors.cjs）：サッキュバスとダイダラボチが 9F と 10F の両方に出ること。8F には出ないこと。
3. 守護者に 2 つの階を書くと、compile がエラーになること。
4. 図書館：2 体が 9F の見出しの下にあり、詳細に両方の階が表示されること。
5. 全テストが通ること：tests/*.cjs、ブラウザテスト（実行しなかったものは明記）、compile --check、scripts/sim/selftest.cjs。
