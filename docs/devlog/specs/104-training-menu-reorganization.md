# 指示書104: 訓練所メニューの整理

## ユーザーの依頼（原文）

「訓練所のメニューの整理をお願いします。まず順番変更はステータス画面からできるので、訓練所では削除してください。また、訓練所のウィンドウの中で機能別に「新規作成」「転職・編集」タブを作り、「新規作成」タブにはキャラの新規作成機能を、「転職・編集」タブにはキャラの転職・名前の変更・キャラの削除が行えるようにしてください。パーティーから外すのは、酒場の機能にします。
また、転職したキャラのステータス画面に「前職:」と書くのをやめてください。
また、転職の画面で職種を選ぶ時、ボタンの中に書いてあるテキストは全部いらないので消してください。転職の画面で必要なのは、そのキャラが転職できる職種のボタンが光っていて、転職可能であることがわかるだけでいいです。

Grok Buildで実装してみてください」

（Codex は ChatGPT の5時間枠が枯渇していた時間帯の依頼のため、本指示書の実装は Grok Build で行う。）

## 現行構成（確認済み）

- 訓練所ダイアログ（dist/index.html の #training、処理は dist/training.js）は1画面に「新規作成」（名前・職業・生成／再生成・プレビュー・登録）と「登録メンバー・パーティ編成」（順番変更ボタン＋登録メンバー一覧）が並ぶ。一覧の各行には 加入／離脱、前へ／後ろへ（パーティ在籍者のみ）、転職、登録抹消 のボタンがある。
- 順番変更は専用ダイアログ（#trainingorderdialog）でも行え、ステータス画面（#statsdialog の #partyreorder）にも同じ機能がある。
- 酒場（#taverndialog、dist/party.js）はスロット選択式の編成画面で、加入・離脱は既にここでも行える。酒場の「登録・加入・外す・抹消」ボタンは訓練所ダイアログを開く。
- 名前の変更機能は現在存在しない（本指示書で新設する）。
- ステータス画面の前職表示は dist/game.js の renderStats() が careerHistory から出力している。
- 転職画面の職種ボタン（dist/training.js の renderClassChange）には「職業名：特徴説明 転職可能／理由」のテキストが入っている。

## 実装内容

1. **訓練所から順番変更を削除する**：「順番変更」ボタン（#trainingreorder）と順番変更ダイアログ（#trainingorderdialog）一式、登録メンバー行の「前へ」「後ろへ」ボタンを削除する。ステータス画面の順番変更は現行どおり残す。
2. **訓練所にタブを導入する**：訓練所ダイアログ内に「新規作成」「転職・編集」の2タブを作る（既存の .library-tabs の様式と role=tablist／tab／tabpanel の作法に倣い、キーボード操作の既存作法を壊さない）。
   - 「新規作成」タブ：現在の新規作成UI（名前・職業・生成／再生成・プレビュー・登録）。
   - 「転職・編集」タブ：登録メンバー一覧。各行の操作は「転職」「名前の変更」「登録抹消」のみとする。
3. **加入・離脱は酒場の編成に一本化する**：登録メンバー行の「加入」「離脱」ボタンを削除する（パーティーから外す操作は酒場の編成で行う。酒場の編成ロジック自体は変えない）。これに伴う文言を実態に合わせて直す：酒場の「登録・加入・外す・抹消」ボタンの表示、訓練所の件数表示の編成に関する案内、パーティ0人時の案内文（#emptyparty）、docs/SPECIFICATION.md の該当記述（蘇生後の加入先など）。
4. **名前の変更を新設する**：「転職・編集」タブの各行に「名前の変更」ボタンを置き、既存のダイアログの作法に倣った入力手段で名前を変更できるようにする。検証は新規作成と同等（1〜20文字）とし、101のセーブ検証と同じ禁止文字（`<>&"'` と制御文字）を含む名前は受け付けない。パーティ在籍・控えのどちらでも変更でき、ステータス画面や戦闘表示に即時反映され、ash-v1 に保存される。
5. **ステータス画面の「前職：」表示を削除する**：renderStats() の前職の行を出力しない。careerHistory のデータ自体は保持し、転職条件などの内部利用は変えない。
6. **転職画面の職種ボタンを簡素化する**：ボタン内のテキストは職業名のみにする（特徴説明 CLASS_FEATURES と「転職可能」／理由の文言をボタンから除き、不要になる CLASS_FEATURES は削除する）。転職できる職種のボタンには、光って見える専用の見た目（金色の枠と明るい背景など、既存の選択中表示と区別できるもの）を与える。転職できないボタンは従来どおり disabled とし、理由は title（ツールチップ）に残す。選択中（aria-pressed）の見た目は維持する。プレビュー（比較表・使えなくなる装備・注意書き）と通知文は現行どおりとする。
7. **仕様書の更新**：docs/SPECIFICATION.md の訓練所・酒場・転職まわりの記述を新しい構成に合わせて更新する。

## テスト

- 既存の該当テスト（training-browser、class-change、elite-jobs、town-keys など）を新しい構成に追随させる。
- 新規に確認を追加する：タブの切り替えで各機能が使えること、訓練所に順番変更のUIがないこと、名前の変更ができること（検証で弾かれるケースを含む）、ステータス画面に「前職：」が出ないこと、転職の職種ボタンが職業名のみで転職可のボタンに専用の見た目が付くこと。

## 制約

- dist のファイル数は増やさない。セーブ形式（ash-v1）とデータ構造は変えない（careerHistory は保持）。
- 転職の条件・効果、登録抹消、酒場の編成ロジック自体は変えない（入口と表示の整理、および名前の変更の新設のみ）。
- 検証：node tests/game.cjs 全件、関係するブラウザテスト、python3 scripts/compile-monsters.py --check、sim selftest、MANIFEST 一致。
