# 指示書118 仕様: 透視の階またぎ持続、宝箱ボタンの表記統一、呪文リストのレベル順

- 日付：2026-11-19
- ブランチ：hold/118（基準 main 55fc4d5）
- 経緯：ユーザーの報告・依頼3件。（1）呪文「透視」が階を移動すると持続歩数の途中で切れてしまう。（2）宝箱のボタンの表記「カルフォ」を呪文本来の名前「仕掛解除」に直す。（3）呪文リストを習得レベル順に並べ替える。実装担当は Codex（ユーザーが指定）。

## 1. 透視（milwa）の残り歩数を階移動で引き継ぐ

現状：透視は `s.milwaSteps = 30` の歩数制で、移動のたびに減る。しかし階を移動すると次の3か所で 0 に戻るため、途中で切れる。
- `fresh()` の引き継ぎ：`milwaSteps: floor===s.floor ? (s.milwaSteps||0) : 0`（階が変わると 0）
- `travelElevator()`（dist/game.js）の `s.milwaSteps=0`
- `descendPitfall()`（dist/traps.js）の `s.milwaSteps=0`

変更：
- 階が変わっても残り歩数をそのまま引き継ぐ（`fresh()` の引き継ぎは無条件に `s.milwaSteps||0`）。
- `travelElevator()` と `descendPitfall()` の `s.milwaSteps=0` を削除する。
- 変えないもの：移動ごとの減算、町に戻ったときの解除（enterTown のリセット）、4F 反呪文ゾーンでの解除（dispelAntimagicEffects、指示書117）、大透視（s.light）の挙動（もともと階移動で切れない）、セーブ形式。
- テスト：`tests/travel-characterization.cjs` が「階が変わると milwaSteps はリセットされる」という現行挙動を固定している箇所がある。これはユーザーの仕様変更依頼による意図的な変更なので、該当する期待値とコメントを新しい仕様（階をまたいでも保持される）に合わせて更新する。テストの削除や検証の弱体化はしない。

## 2. 宝箱ボタンの表記を「仕掛解除」に統一

- dist/index.html の `#chestcalfo` ボタンの表示テキスト「カルフォ」を「仕掛解除」に変更する（呪文データ上の正式名は「仕掛解除」）。
- ゲーム内（dist/）の他の表示に「カルフォ」の表記はない（要素 id や呪文 id は表示ではないので変更しない）。docs/ の用語は対象外。
- ボタンの動作（calfoCaster による詠唱者の決定、`castMagic(i,'calfo',null)`）は変更しない。宝箱前の呪文リストの絞り込み等、表示以外の変更はしない。

## 3. 呪文リストをレベル昇順に並べ替える

- `renderMagic()`（dist/spells.js）が `#magiclist` に出す呪文行を、呪文レベル（x.level）の昇順に並べ替える。同レベル内は現在の定義順を維持する（安定ソート）。
- 系統タブ（魔法使い／僧侶）ごとの表示は今までどおりで、並び替えは各タブの中で行う。
- renderMagic は詠唱用と閲覧用（spellBrowse）で共用されているため、両方に同じ並びが適用される（意図どおり）。
- 先頭行に付く `data-key-default` は並び替え後の先頭（最下位レベル）になる。それ以外の行の内容・無効化条件・理由表示は変更しない。

## テスト（新規）

- `tests/118-milwa-spelllist-browser.py` を新規追加する（115〜117 のブラウザテストの様式に従う）。検証内容：
  1. 透視の残り歩数を設定した状態で、階段（travelFloor）・昇降機（travelElevator）・落とし穴（descendPitfall）で階を移動しても残り歩数が保持され、発動中の魔法欄に透視が残ること。移動で歩数が減り、0 になると消えること。
  2. 宝箱のある状態で `#chestcalfo` ボタンの表示が「仕掛解除」であり、「カルフォ」という表示が画面内に存在しないこと。ボタンを押すと従来どおり仕掛解除が唱えられること（罠の識別ログが出る等、既存の挙動で確認）。
  3. 複数レベルの呪文を習得したメンバーの呪文ダイアログで、行がレベル昇順に並ぶこと（両系統を持つメンバーではタブごと）。
- 既存テストは、`tests/travel-characterization.cjs` の milwaSteps 期待値（上記1）以外は原則変更しない。他に新仕様で壊れるものがあれば最小限の追従修正にとどめ、報告に明記する。
