# 080 図書館のタブ分けと並び替え

状態: 実施中（hold/080、未push）

## ユーザーの依頼（原文）
> 実装の依頼です。実装時のCodexのトークン消費を考え、どのモデルでどの順番に実装すればいいか考えてください。全ての変更が完了したら、ブランチにPushしてください。その後、chatgtpにレビューをまとめてもらうようにしてください。
> - 図書館の「呪文」の魔法使い・僧侶の各タブで習得レベル順に順に並ぶようにし、それぞれのレベルに見出しウィつけてください。そして、各呪文データの「習得レベル」欄を削除してください。
> - 図書館の「アイテム」ですが、呪文と同じく、「武器・頭・胴体・足」でタブ分けをしてください。よって、それぞれの武器データの「種類」は消してください。「武器」の性能欄にある「近距離・遠距離」ですが、これは武器の名前の横にタグ付けみたいな形で表示してください。よって、性能欄の「近距離・遠距離」の表示は消してください
> - 図書館の「アイテム」の「装備できる職業」は「職業」に直してください。また、価格欄の「基準価格」という文言は消してください
> - 図書館の「モンスター」ですが、見出し以外の内容を2列にできますか。そして、他と同様に階ごとにタブを配置はしてください。表記は「1・2・3……」でいいです。Fとかつけないでください。

## 実施方針（トークン消費と順番）
- 変更はすべて dist/library.js と dist/index.html（タブボタンと CSS）に集中する。関心の近い順に Codex を2回実行する。細かく分けすぎると実行ごとにリポジトリ文脈の読み込み（毎回数万トークン）を払い直すため割高で、1回にまとめると指示が長くなり取り違え時の再実行コストが大きい。
  - 実行1: 変更1（呪文）と変更2・3（アイテム）。「サブタブ化と詳細欄の整理」という同じ型の変更。
  - 実行2: 変更4（モンスター）。タブ化に加えて2列レイアウトという別種の変更を含む。
- モデルはアカウント既定を使う。CLI からはアカウントで使えるモデルの一覧を確認する手段がなく、未確認のモデル名を指定して失敗すると試行自体が無駄になる。既定モデルは 073〜079 でこのリポジトリの実績があり、DOM 契約の多い変更では安定性を優先する。

## 解釈メモ（実施者の判断、報告で明示する）
- アイテムのタブは「武器・頭・胴体・足」に加え、現行で別枠表示している「薬」を5番目のタブとして残す（薬の行き場がなくなるため）。薬タブの詳細も他と同様に「種類」欄を消し、「使用できる職業」は「職業」に統一する。
- モンスターの階タブは、現行の見出し分けと同じ主出現階（データの先頭階）で分ける。表記は数字のみ（例: 3）。タブはデータに存在する階（1〜10）分を用意する。
- 呪文のレベル見出しは現行表記に合わせて「Lv.5」の形にする。
- モンスターの2列は項目カードの配置のこととし、PC幅で2列・スマートフォン幅では1列に戻す（既存のブレークポイントに合わせる）。

## 変更1: 呪文タブ（レベル順と見出し）
- 魔法使い・僧侶の各タブで、呪文を習得レベル（spell.level）の昇順に並べ替える。同レベル内は現行のデータ順を維持する。
- レベルが変わる位置に「Lv.N」の見出し（h3）を入れる。
- 各呪文の詳細から「習得レベル」欄を削除する（他の欄は現行どおり）。

## 変更2・3: アイテムタブ（分類タブと表示整理）
- 現行の見出し分け（武器／防具（頭）／防具（胴体）／防具（足）／薬（別枠））をやめ、サブタブ「武器・頭・胴体・足・薬」に分ける。既存の呪文サブタブ（#library-spell-tabs）の仕組み・見た目に合わせ、選択中タブの aria-selected と tabIndex も同様に扱う。
- 各アイテムの詳細から「種類」欄を削除する。
- 武器のみ: 「性能」欄から「近距離／遠距離」の表示を消し、代わりに項目名の横へタグとして「近距離」または「遠距離」を表示する（タグの見た目は既存のタグ類に合わせる）。
- 詳細の「装備できる職業」（薬は「使用できる職業」）を「職業」に改める。
- 「価格」欄の「（基準価格）」の文言を消す（例: 「1900 G / 売却 950 G」）。「購入価格なし」の扱いは現行どおり。
- renderLibrary の既存の呼び出し（引数2つまで）は壊さないこと。アイテムのサブタブ状態の引き渡しは既存の引数順と両立させる。

## 変更4: モンスタータブ（階タブと2列）
- 現行の階見出し（h3「NF」）をやめ、階ごとのサブタブ（表記は数字のみ）を配置する。選択した階の主出現階がその階のモンスターだけを表示する。
- モンスターの項目カードを2列に配置する（PC幅）。スマートフォン幅では1列。タブ行や進捗表示は従来どおり全幅。
- 識別済み・目撃のみ・未遭遇の表示規則、守護者や迷宮の主のマーク、詳細欄の内容は現行どおり変えない。
