# 指示書140: 睡眠の回復判定を原作準拠にする（味方・敵）

日付: 2026-11-25
ブランチ: hold/140

## 1. 背景と根拠

現行の睡眠は、味方と敵で扱いが食い違い、どちらも原作と異なる:

- 味方: 敵の睡眠呪文でカウンタ2が付くが、減らす処理がどこにもない。強壮（dialko）か薬でしか解けず、戦闘終了後も眠ったまま探索へ持ち越す（実質「治すまで永続」）。
- 敵: 誘睡（katino）でカウンタ2が付き、自分の行動のたびに減って、ちょうど2回行動を休めば確実に起きる（レベル無関係・確率なし）。

原作 Wizardry #1（Pascal ソースコード解析、Snafaru の計算式集「RECUPERATION FROM SPELL EFFECTS」）では、睡眠に固定期間はなく、ラウンドごとにレベル連動の回復判定で目覚める:

- 味方: 10% × キャラクターレベル（上限50%）
- 敵: 20% × モンスターLv（上限50%）

本指示書では、この回復判定を味方・敵の両方に入れる。

## 2. 味方の睡眠

1. ラウンド終了時の処理に、眠っている味方ごとの回復判定を追加する。配置は沈黙・恐怖のカウント処理（tickBattleSilence / tickBattleFear）と同じ場所・同じ呼び出し箇所（attack() の末尾と、flee() で両者が呼ばれている箇所）。
2. 確率 p = min(0.5, 0.10 × そのメンバーのレベル)。成功したら sleep を 0 にし、ログ「○○は目を覚ました。」を出す。
3. カウンタを減らす方式にはしない。失敗しても sleep の値は変えない（判定はラウンドごとに繰り返される）。
4. 強壮や薬による回復は従来どおり。戦闘終了後に眠ったまま探索へ持ち越す現行の扱いは変更しない（判定は戦闘中のみ）。

## 3. 敵の睡眠

1. 誘睡などで付く e.sleep は「眠っているか」の印として扱い、固定カウンタとしては使わない（付与時は従来どおり max(既存値, 2) でよいが、以後減らさない。戦闘中の旧セーブで e.sleep が残っていても、0より大きければ眠っているとして扱う）。
2. 眠っている敵の行動順では、まず回復判定を行う: 確率 p = min(0.5, 0.20 × その敵のモンスターLv)。
   - 成功: sleep を 0 にし、ログ「○○は目を覚ました。」を出して、そのまま通常の行動を行う。
   - 失敗: ログ「○○は眠っている。」を出し、その行動は休む（現行と同じ）。
3. 守護者（boss）が睡眠にかからない現行仕様は変更しない。
4. 誘睡（katino）の説明文を新しい仕組みに合わせて変更する（dist/spells.js の MAGIC と data/notion-spells.json の両方）:
   - 変更前: 「選択した列の敵に睡眠判定。成功率は術者と敵のレベル差で変動、2回の敵行動を停止」
   - 変更後: 「選択した列の敵に睡眠判定。成功率は術者と敵のレベル差で変動。眠った敵は行動ごとに20%×敵Lv（上限50%）で目覚める」
   - かかりやすさの式自体（49 + 5×(術者Lv − 敵Lv)、0〜94）は変更しない。

## 5. テスト

新規 node テストを tests/ 配下に追加し、tests/game.cjs へ登録する:

- 味方: 乱数を固定し、Lv1（10%）では境界の前後で起きる/起きないこと、Lv5以上では上限50%で判定されること、失敗しても sleep が減らないこと、目覚めたときにログが出ること。
- 敵: 眠った敵が判定成功で目覚めてそのまま行動すること、失敗で行動を休むこと、Lv1（20%）と Lv3以上（上限50%）の境界、守護者には従来どおり睡眠が効かないこと。
- 既存テストに「敵は2回休めば起きる」「味方は治すまで起きない」前提のものがあれば、新仕様への追従として期待値を更新してよい（検証の強さは落とさない）。
