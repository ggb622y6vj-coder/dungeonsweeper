# 指示書149: モンスター画像の表示位置を下げる／クイック攻撃で後衛の盗賊・忍者が自動で隠れる・奇襲する

## 目的

2件の小改修をまとめて行う。

1. 戦闘画面のモンスター画像の表示位置を少し下げ、地面の上に立っている感じを出す。
2. クイック攻撃を選んだとき、後衛にいる盗賊・忍者が近距離武器を装備している場合に、「隠れる」→「奇襲」を自動で行うようにする（現状は通常攻撃ができないため「守る」になっている）。

## 仕様

### 1. モンスター画像の表示位置

- dist/index.html の `.enemy-sprite` の `bottom` を 25% から 20% に変更する（下げる量はオーナー確認済みの見本どおり）。
- 画像の読み込みに失敗したときのフォールバック枠（dist/game.js の drawEnemies が出す SVG の rect と text）も、同じ量だけ下げる。viewBox の高さ400に対する5%は20単位なので、rect の y を 140 から 160 に、text の y を 224.5 から 244.5 にする。枠の大きさ（width 108、height 121）は変えない。
- 画像の大きさ（enemySpriteSize）、横位置、列一覧や遭遇通知との重なり順は変えない。守護者待機画面の表示も変えない。

### 2. クイック攻撃での自動「隠れる」「奇襲」

対象はクイック攻撃（dist/game.js の quickAttack()）の割り当てだけを変える。手動のコマンド選択は一切変えない。

- 対象メンバー: パーティー内の位置が後衛（添字 i>=3）で、canUseStealth(i) が真（盗賊・忍者）で、装備武器が近距離（equippedWeapon(i)?.range が 'ranged' でない）メンバー。
- 割り当て: 対象メンバーは、潜伏していなければ s.commands[i]='hide'（隠れる）、潜伏していれば s.commands[i]='ambush' かつ s.attackRows[i] を先頭の敵グループの key（通常の「戦う」と同じ対象）にする。
- 対象でないメンバーは現行どおり: canWeaponAttack(i) が真なら先頭グループへ 'fight'、そうでなければ 'guard'。前衛の盗賊・忍者と、遠距離武器の盗賊・忍者は現行どおり 'fight' になる。
- クイック攻撃が使える条件も広げる: 現行は canWeaponAttack が真のメンバーが1人でもいないとボタンが無効で quickAttack() も即時終了するが、対象メンバー（後衛・盗賊忍者・近距離）がいる場合も使えるようにする。判定は game.js 側に小さなヘルパーを置き、quickAttack() の冒頭と dist/combatui.js のクイック攻撃ボタンの disabled／title の両方で使うこと。
- 実行時の細部は既存の仕組みに任せる: 「隠れる」の成功率は従来どおり90%で、失敗したら次のクイック攻撃でまた「隠れる」になる。奇襲を実行すると潜伏が解けるので、次のクイック攻撃では「隠れる」に戻る（隠れる→奇襲の繰り返し）。恐怖・睡眠中は canUseStealth が偽になるため対象から外れ、現行どおり 'guard' になる（手動選択で「隠れる」が表示されないのと同じ扱い）。

## テスト

- 画像位置: 位置や寸法を固定している既存テスト（tests/monster-sprites.cjs、tests/css-structure.cjs、ブラウザテスト等）があれば、新しい値へ追従させる。検証の強さは落とさないこと。
- クイック攻撃: tests/quick-attack-browser.py に次のケースを追加する。
  - 後衛の忍者・盗賊＋近距離武器で、1回目のクイック攻撃で「隠れる」になる（乱数を固定して潜伏成功を確認する）。
  - 潜伏した状態で2回目のクイック攻撃をすると「奇襲」になり、先頭グループが対象になる。
  - 後衛の盗賊・忍者＋遠距離武器では従来どおり「戦う」になる。
  - 前衛の盗賊・忍者＋近距離武器では従来どおり「戦う」になる。
  - 物理攻撃できるメンバーがおらず、後衛の盗賊・忍者＋近距離武器だけがいる場合でもクイック攻撃ボタンが有効になる。
- 既存の検証をすべて通す: node tests/game.cjs（現在276 PASS）、python3 scripts/compile-monsters.py --check。ブラウザテスト全件は Muse が実施するので、報告書では未実施と明記する。
