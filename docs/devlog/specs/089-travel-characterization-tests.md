## 実施内容

### 1. 特性テスト tests/travel-characterization.cjs の新設

階層移動3経路（travelFloor=階段、travelElevator=昇降機、descendPitfall=落とし穴）について、現行コードの挙動をそのまま記録し、将来の変更で挙動が変わったら検出できるようにする。既存テストは変更しない。tests/game.cjs の require 一覧へ追加する。

記録する観点（各移動の前後でスナップショットを取る）：
- 移動後の階・位置（pos と、開始マス／守護者マス／昇降機マス／通常マスの別）
- 開始マスと守護者マスの open 状態、守護者マスの type
- milwaSteps、pendingBoss、pendingStairs、pendingElevator、clearNotice、relic、scan
- ログキュー（logQueue）の内容と順序（移動直後）と、再生後（drain 後）の s.logs の順序
- 各関数の戻り値
- render() の呼び出し回数（ラップして数える）

対象ケース：
- 階段：未生成の階へ降りる／保存済みの階へ上がる（守護者撃破済みで到着位置が守護者マスになる場合を含む）／町から同じ階へ戻る（到着ログなし・milwaSteps がリセットされない）／守護者未撃破で降りようとして拒否される（戻り値 false と拒否ログ）
- 昇降機：未生成の階への初回訪問（開始マスの階段が未探索に戻る＝076・087 の仕様）／保存済みの階への再訪（階段マスの open 状態が保存どおり保持される）／同じ階への移動は false
- 落とし穴：未生成の階への落下（表示待ちログが fresh() を跨いで欠落・重複しない）／保存済みの階への落下（表示待ちログがある状態で、到着ログを含む順序が保たれる）／着地マスの条件と previousPos、milwaSteps と scan の扱い
- セーブ互換：floors を含む ash-v1 セーブを保存→読み込みし、読み込み結果（floors・scan・cells・位置・階）が保存時と一致すること、読み込み後に移動した結果が読み込みなしで移動した場合と一致すること
- 乱数はシード固定（ハーネスの rng）で再現可能にする。個別の抽選を固定したい箇所は既存テストと同様に Math.random を差し替える
