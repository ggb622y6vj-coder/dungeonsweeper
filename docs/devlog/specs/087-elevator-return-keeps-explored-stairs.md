# 087 昇降機で戻ったとき、探索済みの階段は見えたままにする

## ユーザーの要望（原文）

> 昇降機で移動して戻ってくると、探索済みにした階段の部分が未探索に戻っています。探索済みにした階段は見えたままにしてください。未探索の階段は見えなくて当然なんです。

## 背景と原因

- 076 では、昇降機で到着したときに開始地点（上昇する階段）のマスを未探索に戻す処理を `travelElevator()` に入れた。対象は「生成直後の階」と「保存済みの階へ戻る場合」の両方で、保存済みの階では、実際に階段を踏んで探索済みにした状態まで巻き戻してしまう。
- 076 の報告時には「過去に階段を踏んだことがある階でも閉じる仕様」と実施者が伝えたが、ユーザーから今回、その解釈は誤りで「探索済みにした階段は見えたまま、未探索の階段は見えないまま」が正しい仕様と訂正された。
- 原因は `travelElevator()` の到着処理が、保存状態から復元した階でも無条件に `s.cells[s.start].open=false` を実行すること。新規生成の階で階段が探索済みで作られるのは `fresh()` の生成上の都合であり、その場合だけ閉じるのが正しい。

## 実装

`dist/game.js` の `travelElevator()` を変更する。

1. 到着階が今回の移動で新規生成された場合（保存状態がなく `fresh(n)` を呼んだ場合）に限り、従来どおり開始地点を未探索に戻す（076 の挙動を維持）。
2. 到着階が保存状態から復元された場合は、階段マスの探索状態を保存どおりに保持する。探索済みなら見えたまま、未探索なら見えないまま。
3. 到着地点（昇降機マス）を探索済みにする処理、`s.start!==s.pos` のガード、その他のマスの保持は変えない。階段移動（`travelFloor`、076 Amendment 1 の到着時に開始地点を開く処理）も変えない。

## 対象外

- セーブ形式には新しい項目を追加しない（保存済みの探索状態そのものを使う）。
- 076 の新規生成時の仕様、昇降機の解放条件・配置、再抽選（reload）の挙動は変えない。

## 検証

- 回帰テスト：(a) 新規生成の階へ昇降機で到着すると階段は未探索のまま（076 の維持）、(b) 階段を実際に踏んで探索済みにした階へ昇降機で戻ると階段は見えたまま、(c) 階段が未探索のまま保存された階へ昇降機で戻ると階段は未探索のまま。
- 既存の `tests/elevator.cjs` には旧仕様（保存済みの階でも到着時に階段を閉じる）を前提に、往復復元の比較で階段マスだけを未探索へ正規化している箇所がある。本仕様に合わせて、保存どおり完全復元される前提へ更新する。
- node テスト全件、ブラウザテスト全件（1280px / 390px）、`scripts/compile-monsters.py --check`、sim selftest、MANIFEST 照合。
- 実経路の確認：ブラウザ実操作で、階段を探索済みにした階から昇降機で往復し、地図上で階段が見えたままであること。新規の階へ昇降機で到着したときは階段が見えないこと。
