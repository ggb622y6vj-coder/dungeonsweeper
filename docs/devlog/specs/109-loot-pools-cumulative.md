- Muse の回答：minFloor は直接ドロップ（探索済みマスの5%）・旧セーブ宝箱・図鑑表示・Notion 同期でも使うため項目自体は残すが、新しい宝箱抽選からはフィルタを外し、出現の制御はプールだけで行うことを提案。
- 2026-11-12 21:55 ユーザー「その内容で109を進める（実装はCodex）」

## 変更内容

### 1. プールの差し替え（データ）

- `data/loot-tables.json` を Notion DB「宝箱抽選テーブル」（data source 63946033-84f9-47ec-a909-8b50129293ce）の新しい内容に差し替えた（Muse が名前→ID 変換で生成し、検証済み。本指示書と同時にコミットされる）。
- 変更点はプールのみ（グループ・当選率は不変）：
  - T1：変更なし（35件）
  - T2：32件（T1 の上位武器12件を追加）
  - T3：43件（T2 の装備16件＋基本武器9件を追加）
  - T4：25件（基本武器9件を追加）
  - T5：26件（基本武器9件＋T4 の装備11件を追加）
- 「基本武器9件」= 長剣・戦斧・大剣・樫の杖・ルーンの杖・星鉄の杖・鉄のメイス・戦槌・聖銀のメイス。深い階でも手堅い装備が出る累積型の構成。
- 同名アイテム「魔弓」は T3 = magicbow、T4/T5 = makyuu として変換した。

### 2. dist/loot.js の追随と minFloor フィルタの撤廃（Codex）

- `LOOT_TABLES` を新しい `data/loot-tables.json` と完全一致させる（既存のデータ検証テストが照合する）。
- `rollChestItems` から minFloor による絞り込みを撤廃する。当選した枠は、指定プールの全件から等確率で1品を選ぶ。プールが空ならその枠はなし（現行どおり）。
- `floor` 引数は呼び出し側の互換のため残してよいが、抽選には使わない。
- 出現の制御はプールの収録内容だけで行う。これが本指示書の要点であり、minFloor は他の仕組み（直接ドロップ・旧形式の宝箱・図鑑）のためにデータとして残る。

### 3. テストと仕様書の追随（Codex）

- `tests/chest-loot.cjs`：等確率検証の母集団を「minFloor で絞った候補」から「プール全件」に改める。浅い階でもプール内の品は出ること（例：1F で G6 の C 枠 T5 から品が出る）を確認するケースを含める。PASS 行の文言（uniform floor filtering 等）も実態に合わせる。
- `docs/SPECIFICATION.md`：宝箱の説明から `minFloor ≤ 現在階` で絞る旨を外し、「出現の制御はプールの収録内容だけで行う」旨に直す。

## 変えないもの

- グループ表・当選率・宝箱の発生条件・金貨・旧形式（rewardVersion なし）の宝箱の開封方式。
- minFloor のデータ項目そのものと、それを使う他の仕組み（chestItemPool、dropMedicine、図鑑表示）。
- セーブ形式。
