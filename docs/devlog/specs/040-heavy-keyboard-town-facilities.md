# 040 [heavy] 町と施設のキーボード操作

## 共通ルール
- 作業ツリーは担当者自身のもの。push はオーナー指示があるまでしない。既存テストのチェックは削除・緩和しない。
- タッチ／マウス操作と 390px レイアウトを壊さない（既存ブラウザテスト全件PASS）。
- テキスト入力（#recruitname など INPUT/TEXTAREA/SELECT）にフォーカスがある間は、Esc 以外のキーをゲームが奪わない。
- Ctrl/Alt/Meta 付きのキーは無視する（ブラウザのショートカットを妨げない）。
- 完了条件: node tests 全件・compile-monsters --check・selftest・ブラウザテスト全件（1280/390）PASS、JSエラーなし。新規テストはキーボードだけで操作する Playwright（page.keyboard のみ、click・evaluate での直接操作は禁止。evaluate は状態の確認だけに使う）。
- 038 完了後に着手。

## 目的
町メニューと全施設をキーだけで使えるようにする。

## 変更内容
- 町メニュー（2列）: 038 の位置移動でそのまま上下左右に動く。既定フォーカスは「迷宮への入り口」。
- タブのある画面（図書館など）:
  - タブの列にフォーカスがあるときは A/D でタブを切り替え、S でリストの先頭へ降りる。
  - リストの先頭で W を押すとタブに戻る。
  - Q/E を「前のタブ／次のタブ」の近道にする（どこにフォーカスがあっても使える）。
- 酒場（登録・加入・外す・削除確認）、寺院（蘇生・灰・石化解除・運び込み報告）、訓練所（並び替え・名前入力）、商店（売買・分配・在庫）、図書館（モンスター・アイテム・呪文の一覧と詳細）について、それぞれ以下を付ける。
  - 既定項目（data-key-default）
  - 戻る（data-key-back）。各閉じるボタン。
  - 確認 dialog の既定は「いいえ」にする。削除やリセットを Space の連打で実行しないため。
- 名前入力（#recruitname）:
  - フォーカス中は文字入力を優先する。Enter で確定（登録ボタンと同じ）。
  - Esc で入力欄から出て、隣のボタンへフォーカスを移す。2回目の Esc で dialog を閉じる。
- 長いリスト: フォーカス移動に合わせて自動スクロールする。
- 並び替え（順番変更）:
  - Space で1人目をつかむ（.kfocus と別の「選択中」表示）。
  - W/S/A/D で移動先を選び、Space で入れ替える。Esc でやめる。

## OKの判定方法
Playwright（tests/town-keys-browser.py、1280 と、390 に物理キーボードを付けた想定）。キーだけで以下ができること。
1. 酒場: 名前入力 → 登録 → 加入 → 外す → 削除（確認の既定が「いいえ」で、Space だけでは削除されない。D→Space で削除）。
2. 寺院: 死亡者の蘇生と石化解除（032/033 のテスト状態を流用）。
3. 訓練所: 並び替えで A と B を入れ替える（s.members の順で確認）。
4. 商店: 購入・売却・分配。所持金と持ち物が増減する。
5. 図書館: 全タブを Q/E と A/D で巡回、各リストの最後の項目まで S で到達、詳細表示。
6. 各画面で Esc を押すたびに1段ずつ戻り、最後は町メニューに戻る。390 のタッチ操作のテストは既存どおりPASS。
