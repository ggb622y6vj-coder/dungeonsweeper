# 指示書148: 5Fの象限ギミック（地図が反応しない／魔法が使えない）と命の泉

## 目的

5Fに、3Fの「地図が反応しない」ゾーンと4Fの「反呪文の結界」の両方を象限単位で出現させる。また、5Fの数字0マスの1つを「命の泉」とし、パーティー全員のHPかMPを選んで全回復できる場所を1つ置く。

## オーナー決定事項

- 象限の状態は5F生成時に象限ごとに抽選する。確率は「地図が反応しない」25%、「魔法が使えない」25%、通常50%（4面ダイスで1=地図、2=魔法、3〜4=通常）。
- 「地図が反応しない」象限は3Fのゾーンと同じ扱い、「魔法が使えない」象限は4Fの反呪文の結界と同じ扱い。
- 透視の間、象限の枠を出す（3F・4Fと同じ仕組み・同じ色。マス目のパネルに出て、地図ダイアログでもそのまま見える）。
- 命の泉は一度使うと消え、町に戻って迷宮が再生成されるまで使えない。

## 仕様

### 1. 象限と状態の抽選

- 5Fは12×12。象限は西（x<6）／東（x>=6）と北（y<6）／南（y>=6）の組み合わせで4つに分ける。x=i%12、y=Math.floor(i/12)。
- 状態は `s.floorZones` に配列で保持する。並びは [北西, 北東, 南西, 南東]、値は 'blind'（地図が反応しない）／'anti'（魔法が使えない）／null（通常）。
- 抽選は fresh(5) の生成時に象限ごとに行う。各象限で1d4を振り、1→'blind'、2→'anti'、3〜4→null。
- 状態はその階が残る間は固定する。rememberFloor の保存項目に floorZones を追加し（5F以外は null）、enterFloor の復元で戻るようにする。rememberFloor のコメントにあるとおり、tests/travel-characterization.cjs の保存項目の期待値も合わせて更新する。
- 町に戻って迷宮が再生成されれば（s.floors が空になって fresh し直せば）引き直しになる。既存の再生成の仕組みに任せ、特別な処理は足さない。
- 既存セーブで生成済みの5F（floorZones がない）は、全象限通常として扱う。泉も置かない。再生成されるまでそのまま。

### 2. 効果の接続（既存の判定へ寄せる）

- `isMapBlind()` に、5Fで現在地の象限が 'blind' の場合を追加する。これにより盤面のブラインド描画と、地図ダイアログの「地図が反応しない！」通知（syncMapBlindNotice）が既存のまま効く。
- `isAntimagicZone()` に、5Fで現在地の象限が 'anti' の場合を追加する。これにより、入ったときの持続魔法の無言解除（dispelAntimagicEffects）、味方の詠唱の打ち消し（spells.js の castMagic）、敵の詠唱の打ち消し（monsters.js）、発動中の呪文欄の「反呪文の結界」表示（spells.js）が既存のまま効く。
- 3F・4Fの判定と挙動は一切変更しない。出入りのログも出さない（3F・4Fと同じ）。

### 3. 透視の枠

- 透視（hasLight()）の間、5Fでは象限の境界に枠を出す。'blind' 象限は既存クラス zoneframe（紫・実線）、'anti' 象限は既存クラス antiframe（赤・破線）を使う。
- 辺の規則: マス i について、i の象限の状態と隣接マス j の象限の状態が異なり、かつ i の象限に状態があるとき、i の j 側の辺に i の象限の状態の枠を出す。隣り合う象限同士が同じ状態なら、その間の辺には出さない。盤の外側に接する辺には出さない。
- 実装は render() の枠決定に5F用の分岐を足す形とし、既存の mapZoneFrame（3F・4F用）の挙動は変えない。ブラインド描画時も枠は出す（3Fと同じ）。

### 4. 命の泉

- 配置: fresh(5) の生成時、候補 = 罠でなく type が '' で num(i)===0 のマス（開始マスと守護者マスは type を持つため候補に入らない）。候補から1つを無作為に選び、そのセルに fountain=true を付ける。候補がなければ泉は置かれない。
- fountain はセル属性として保持し、s.floors への保存・復元にそのまま乗る（回転床の spin と同じ扱い）。
- 発動: 歩行でそのマスに入ったときに限る（cell() の経路。転移・落とし穴・浮上穴・昇降機・階段などの到着では発動しない。回転床と同じ歩行限定）。発動した歩行ではエンカウント判定を行わない。
- ダイアログ: 新規 `<dialog id="fountaindialog">` を作る。見出し「命の泉」、本文「澄んだ水が満ちている。パーティー全員のHPかMPを全回復できる。」、ボタンは「HPを全回復」「MPを全回復」「使わない」の3つ。
- 効果: status が 'ok' のメンバー全員が対象。HPを選ぶと hp が各自の最大値に、MPを選ぶと mp が各自の最大値になる。'ok' でないメンバー（死亡・石化など）は対象外で、復活しない。状態異常は治さない。
- 使用すると fountain=false になり泉は消える。ログは HP のとき「命の泉の力で、全員のHPが全回復した！」、MP のとき「命の泉の力で、全員のMPが全回復した！」。
- 「使わない」を選ぶと何も消費せず泉は残る。そのマスから出て入り直すと、再度ダイアログが出る。
- 発動中は s.pendingFountain=true とし、守護者の pendingBoss と同じ扱いで、cell() / move() / flag() / idle() のガードと render() のボタン無効条件に加える。ダイアログを閉じたら false に戻す。ensureProfile で初期値（??=false）を入れ、enterFloor と enterTown でリセットする。
- 盤面の見た目は変えない。泉のマスも通常の0マスとして表示する（専用アイコンは出さない）。

## テスト

- 新規 node テスト tests/floor5-zones.cjs を追加し、tests/game.cjs の require 一覧に登録する。内容:
  - 生成: Math.random を固定して fresh(5) を行い、floorZones が1d4の結果どおり（1→'blind'、2→'anti'、3・4→null）になること。
  - 象限の境界: x=5と6、y=5と6で象限が切り替わること。
  - 判定: 5Fで 'blind' 象限にいる間 isMapBlind() が true、'anti' 象限にいる間 isAntimagicZone() が true、通常象限では両方 false。3F・4Fの既存判定が変わらないこと。

  - 保存: rememberFloor → enterFloor の往復で floorZones と fountain が保持されること。floorZones のない旧形式の階データは全象限通常として扱われること。
