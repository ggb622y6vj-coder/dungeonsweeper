# 088 床の罠と宝箱の罠に「落とし穴」を追加する

## ユーザーの要望（原文）

> 床の罠と宝箱の罠に「落とし穴」を追加してください。効果はパーティーを強制的に下の階に転移させるものです。転移する下の階のマスはランダムになります。10Fでは不発に終わってください。実装が終わったらNotionの罠のページに書き加えておいてください。

## 仕様（実施者が決めた解釈）

### 共通の転移処理

- 下の階への転移は共通処理として実装する。現在の階を保存し（`rememberFloor()`）、下の階が保存済みならその状態を復元、未生成なら `fresh()` で生成する（階段・昇降機の移動と同じ扱い。守護者を倒していなくても落ちられるのが罠の性質）。
- 転移先のマスは、下の階のマスからランダムに選ぶ。候補は転移の罠と同じ条件（特殊マス・罠・旗・宝箱のないマス）。候補が無い場合はその階の開始地点に落ちる。到着マスは探索済みにし、周囲の罠数の警告ログを出す（転移の罠と同じ）。
- 保存済みの階へ落ちた場合は到着ログ「地下N階に到着した。」を出す（077 の扱いに合わせる）。
- 落下にダメージはない。

### 床の罠（dist/traps.js）

- `FLOOR_TRAPS` に `{id:'pitfall', name:'落とし穴', weight:5}` を追加する。重みは合計100を維持し、並びは 針25・爆発25・毒霧20・麻痺の針15・落とし穴5・転移10 とする（転移15→10。既存テストの抽選境界が変わらないよう、落とし穴は転移の前に置く）。
- 発動時：10F では不発（ログ「落とし穴の罠は不発に終わった。」）。それ以外は共通処理で下の階へ落ちる（ログ「落とし穴の罠！ 一行は下の階へ落ちた。」）。
- `triggerFloorTrap()` の戻り値は転移の罠と同様に、落とし穴のときも truthy を返し、そのマスでの後続処理（エンカウント判定など）を打ち切る。

### 宝箱の罠（dist/spells.js の fixChestTrap、dist/game.js の triggerChestTrap / openChest、dist/party.js の thiefOpenChest）

- 宝箱の罠の抽選に `pitfall` を追加する。罠なし60%は維持し、針18%・毒11%・麻痺7%・落とし穴4%とする。
- 通常開封で落とし穴が発動した場合、一行は中身を受け取る前に落ちるため、その宝箱は失われる（宝箱のあったマスから宝箱を取り除いてから転移する）。`triggerChestTrap()` は転移した場合に truthy を返し、`openChest()` はその場合に戦利品取得を行わない。
- 10F では不発となり、開封は通常どおり戦利品取得へ進む。
- 盗賊の「解除して開ける」に失敗して落とし穴が発動した場合も宝箱は失われる（既存の失敗時ルールどおり）。転移後に現在位置のマスを誤って消さないよう、削除は転移前の階・位置に対してのみ行う。
- 鑑定（calfo）の結果表示に「落とし穴」を追加する。

## 対象外

- セーブ形式の変更（新しい保存項目は追加しない）、罠の配置数・配置条件の変更、落下ダメージの追加はしない。
- 図書館への罠一覧の追加はしない（現状、罠は図書館に載っていない）。

## 検証

- 新規テスト `tests/pitfall.cjs`（game.cjs から require）：重みの合計100と落とし穴の存在、床の罠で下の階へ落ちること（到着マスが通常マスで探索済み、罠マスは消費済み）、10F で不発のこと、保存済みの下の階へ落ちると保存状態が復元されること、宝箱の落とし穴で転移し宝箱が失われ戦利品を得ないこと、10F の宝箱では不発で戦利品を得ること、宝箱の抽選境界、盗賊の解除失敗で落とし穴が発動しても転移先のマスを誤って消さないこと。
- node テスト全件、ブラウザテスト全件（1280px / 390px）、`scripts/compile-monsters.py --check`、sim selftest、MANIFEST 照合。
- 実経路の確認：ブラウザ実操作で床の罠と宝箱の罠の落とし穴を発動させ、下の階のランダムなマスに着くこと。
