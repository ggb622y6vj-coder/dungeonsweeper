# 065 [light] スマホ表示では戦闘中に地図ボタンを隠す

## 背景
- ユーザーの要望：「スマホの画面の時、戦闘中は地図のボタンは非表示にする」。
- 今の実装（origin/main 6c4ac79 で確認）：
  - 地図ボタンは `#maptoggle`（dist/index.html）です。
    - 幅 701px 以上では `#maptoggle{display:none}` になり、地図は常に右側の `#mapdock` に表示されます。
    - 幅 700px 以下の `@media(max-width:700px)` では、`#mapdock` が非表示になり、`#maptoggle` が画面右下に固定ボタンとして出ます。z-index は 50、420px 以下では 20 です。390 幅はこの「スマホ表示」に入ります。
  - 表示は dist/game.js の render() で決めています：`$('#maptoggle').hidden=s.area!=='dungeon'`。このため、迷宮の中にいれば戦闘中もボタンが出たままです。
  - 戦闘中かどうかは `visibleCombat()` で判定します（`displayCombat===undefined?s.enemy:displayCombat`）。戦闘のログ再生中（勝利後の演出を含む）も「戦闘中」として扱われ、敵の絵が出ている間ずっと真になります。
  - M キー（dist/keynav.js 266 行）の条件は `!active` で、`active` は `s.enemy`・`logBusy()` などを含みます。そのため、M キーでは今も戦闘中に地図は開けません（推測ではなく、コードで確認しました）。

## 仕様
1. render() の条件を `$('#maptoggle').hidden = s.area!=='dungeon' || !!visibleCombat();` にします。
   - 701px 以上ではもともと CSS で非表示なので、見た目は変わりません。このため、画面幅の判定を JS で書き足す必要はありません。
2. 念のため、`#maptoggle` のクリック処理の先頭に「`visibleCombat()` が真なら何もしない」を追加します。隠れたボタンをスクリプトや残ったフォーカスから押された場合に備えるためです。
3. 戦闘が始まる時点で `#mapdialog` が開いていることは、通常ありません（移動したときに戦闘が始まるため）。もし開いていた場合は、戦闘が始まるときに閉じます。
4. 戦闘が終わり、勝利・逃走後のログ再生も終わって `visibleCombat()` が偽になった次の render で、ボタンをもう一度表示します。
5. ボタンにフォーカスがある状態で非表示になった場合、フォーカスは keynav の既存の処理に任せます（戦闘中はコマンド欄に移ります）。
6. 判断した点（ユーザーの確認は不要と判断しました）：
   - 「戦闘中」には次の時間を含めます：敵との遭遇直後、コマンド入力、ターンのログ再生、勝利・全滅の演出が終わるまで。
   - 守護者を前にした確認（pendingBoss）、宝箱、階段の確認は戦闘ではないので、ボタンを隠しません。

## OKの判定方法
新しいブラウザテスト：tests/mobile-map-battle-browser.py
- 幅 390・タッチありの場合：
  - 探索中は `#maptoggle` が見えている。
  - 戦闘を起こすと、敵の表示から終了まで見えない（`is_visible()==False`）。
  - 戦闘中に M キーを押しても `#mapdialog` が開かない。
  - 勝利してログが終わると、ボタンがまた見え、押すと地図が開く。
  - 逃走でも同じように再表示される。
- 幅 1280 の場合：
  - `#mapdock` は戦闘中も表示されたまま（今と同じ）。
  - `#maptoggle` は常に見えない。
- 既存のテストがすべて通ること：tests/*.cjs と、ブラウザテスト（keynav・battle-keys・explore-keys など）。
- ライブ版で 390 と 1280 の幅を目で確認すること（スクリーンショットを添付）。
