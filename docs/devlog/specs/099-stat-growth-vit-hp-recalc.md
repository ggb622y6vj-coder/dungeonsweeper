## 数値の扱い（重要）

試案の確率・初期値・移行規則は「仮置き（未承認）」と明記されているが、ユーザーが本指示書の作成と実装を指示したため、**試案の仮置き値をそのまま採用**して固定する。採用値：

- 能力値の成長抽選：+1 が 30%、−1 が 10%、変化なしが 60%。範囲 3〜18（上下限では変化なしとして扱う）。
- 新規キャラクターの VIT：`10 + floor(Math.random()*4)`（10〜13）の独立抽選。
- 既存セーブの VIT 補完：`10` で一度だけ。ランダム補完はしない。
- 新規キャラクターの初期 HP：現行のまま変更しない。
- レベルアップの処理順：能力値 → HP（成長後の VIT）→ MP → 呪文習得。
- レベル吸収：HP/MP の既存の近似減少は維持し、能力値は戻さない。
- VIT は寺院の成功率・費用に影響しない。`growthVersion` のような版数フィールドは導入しない（VIT 補完は冪等な `??=` で足りるため）。

## 現行挙動（変更前、コードで確認済み）

- `levelUp()`（dist/game.js:206）：1レベルごとに `maxHP += dice(hpGrowth)`、`maxMP += dice(mpGrowth)`（mpFromLevel でゲート）、`str/agi` を `base + floor((Lv-1)/5)`（上限18、base が無ければ職業別フォールバック表）で再計算し、`learnMagic` を呼ぶ。報告行は HP/MP/STR/AGI の増分。
- 能力値は `str / baseStr / intelligence / piety / agi / baseAgi`（dist/recruits.js の生成：職業別基礎値＋ボーナス配分）。IQ・PIE は生成後固定。
- `lowerMemberLevel()`（dist/monsters.js:2。敵のレベル吸収と mahaman の代償の両方が使う）：レベル・XP・maxHP・maxMP を近似量だけ減らし、`str/agi` を基準値から再計算する。
- 転職（classChangePreview）：`baseStr/baseAgi` を現在値に合わせ直す。HP・MP・能力値は保持。
- 移行：`migrateStrength/migrateAgility`（dist/game.js）が ensureProfile でパーティ・控えに適用される。遺体レコードは別ループで処理される。
- HP 成長ダイス `hpGrowth` は CLASSES にあり、レベル吸収の近似量計算でも参照される。

## 変更内容（固定事項）

1. **VIT の追加**：メンバーレコードに整数 `vit` を持たせる。
   - `generateRecruit`：既存の能力値生成（基礎値・ボーナス配分）は一切変更せず、`vit = 10 + floor(Math.random()*4)` を独立に決める。
   - 移行：`vit` が無いレコードには `10` を一度だけ設定する（パーティ・控え・遺体の全レコード。再読込・再保存で変わらないこと）。
2. **レベルアップの能力値抽選**：`levelUp()` の1レベルごとに、対象メンバーの `str / agi / intelligence / piety / vit` の5種それぞれへ独立に抽選する。`Math.random()` が 0.30 未満で +1、0.40 未満で −1、それ以外は変化なし。結果は 3〜18 に収める（範囲外になる場合は変化なし）。`levelUp` 内での `str/agi` の基準値再計算は廃止する。
3. **HP 再計算**：能力値の確定後、そのレベルの最大 HP を `max(旧最大HP + 1, 候補)` とする。候補は純粋な補助関数で計算する：
   - 職業ダイス（CLASSES の id で対応）：戦士・君主 1d10、僧侶・侍 1d8、盗賊・司教・忍者 1d6、魔法使い 1d4。抽選回数は新しいレベル回（侍のみ +1 回）。
   - 各ダイスに VIT 補正を加える：VIT 3→−2、4〜5→−1、6〜15→0、16→+1、17→+2、18→+3。各項は最低 1 に丸め、合計が候補。
   - 補助関数（例：`vitBonus(vit)`、`hpCandidate(job, level, vit)`）は dist/balance.js に置き、乱数は `Math.random` 経由にしてテストで差し替え可能にする。
   - `levelUp` での `hpGrowth` 加算は廃止する。ただし `hpGrowth` のデータ自体はレベル吸収が参照するため残す。
4. **MP 成長と呪文習得**：現行どおり（MP は hpGrowth ではなく mpGrowth、mpFromLevel ゲート維持）。順序は「能力値 → HP → MP → 習得」とし、習得判定は成長後の `intelligence / piety` を使う（現行の learnMagic はメンバー値を参照するため、順序を守れば自動的にそうなる）。既に習得した呪文は能力値が下がっても失わない。
5. **レベルアップ報告**：現行の集約形式（メンバーごと1行）を維持し、表示項目を `HP / MP / STR / AGI / IQ / PIE / VIT` の増減に拡張する。増減の表記は、正は `+n`、負は `-n`、0 は `±0` とする。習得呪文の行は現行どおり。
6. **レベル吸収**：`lowerMemberLevel()` から `str/agi` の再計算を削除する（能力値は一切変更しない）。レベル・XP・maxHP・maxMP の処理と現在値のクランプは現行どおり。敵の吸収と mahaman の代償の両方に同じ変更が効く。
7. **転職**：VIT はレコードごと保持される（追加の処理は不要だが、preview・確定の両経路で落ちないことをテストで確認する）。転職直後に HP 再抽選はしない。`classChangePreview` の `baseStr/baseAgi` の現在値合わせは互換のため現行どおり残す。
8. **表示**：
   - ステータス画面（renderStats）に VIT の行を追加する。
   - 訓練所の登録候補プレビュー（能力値グリッドと前回生成との差分表示）に VIT を追加する。
   - 訓練所の一覧行（STR/IQ/PIE/AGI を並べる行）に VIT を追加する。
   - スマートフォン幅でも横にはみ出さないこと（既存グリッドの流用で足りる想定）。
9. **仕様書**：`docs/SPECIFICATION.md` の能力値・レベルアップ・HP・レベル吸収に関する記述を新方式に更新する。
10. **変更しないもの**：経験値式と xpTargets、Lv30 上限、STR 命中・ダメージ式、AGI 行動順、識別式、蘇生・石化・寺院、セーブキー `ash-v1` と `rosterVersion:1`、Notion（本指示では触らない）。

## テスト

試案の完了条件（G）に対応させる。固定乱数（Math.random の差し替え）で決定的に検証すること。

- 新規生成で VIT が 10〜13 の整数で記録され、既存4能力の生成（基礎値・ボーナス配分）が変わらない。
- 旧セーブ相当のレコード（パーティ・控え・遺体）で VIT が一度だけ 10 で補完され、再読込・再保存で VIT・HP・XP・呪文・転職履歴が変わらない。
- 能力値抽選：上昇・低下・変化なし、上限18・下限3 のクランプを5種すべてで確認。
- レベルアップ順序：複数レベル同時上昇でも1レベルずつ処理され、HP 候補が成長後の VIT で計算されることを、順序で結果が変わるケースで確認。
- HP 候補：8職のダイスと回数（侍のみ +1）、VIT 補正の閾値（3/4〜5/6〜15/16/17/18）、各項の最低1、`max(旧+1, 候補)` を確認。
- 転職：最大 HP 200 のメンバーが転職しても HP は 200 のまま（再抽選なし）。新職でレベルアップすると +1 保証が働く。VIT が保持される。
- レベル吸収：抽選で成長した能力値が吸収で戻らない。レベル・XP・HP/MP の従来処理は維持（既存テストの期待値が変わる場合は仕様変更に必要な箇所だけ直す）。
- 既存の `tests/training.cjs` の「Lv6 で STR が +1」前提の検証は、新方式の検証に書き換える（検証を弱めない）。
- 新規テストファイルを作る場合は `tests/game.cjs` へ登録する。

## バランス試算（報告書に添付）

- 8職 × VIT（10・13・16・18）について、新方式での Lv30 時点の最大 HP の期待値（解析計算またはモンテカルロ）を出し、現行方式（初期 HP＋hpGrowth 加算）の Lv30 期待値と比較する表を実装報告書に含めること。現行の初期 HP が高いため序盤は +1 成長に留まりやすいことなど、読み取れる傾向を一言添える。
