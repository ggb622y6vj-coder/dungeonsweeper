# 指示書107: 薬のスタック所持

## ユーザーの依頼（原文）

「アイテムのうち、武器・防具(頭・胴体・足)以外のいわゆるアイテムはスタックして持てるようにしてください。最大数はそのアイテムごとによります。アイテムにスタックできる最大数を設定して、Notionにも反映させてください。」（2026-11-12、サイドチャット「迷宮スイーパー開発」）

解釈は Muse が提示し、ユーザーが承認した（2026-11-12）。実装担当はユーザーが Codex を指定した。

## 解釈（承認済み）

- 対象は薬5種のみ（現行の「アイテム」は薬だけ）：傷薬・解毒剤・気付け薬・上傷薬・霊薬。武器・防具は対象外。
- 所持品の内部形式（IDの配列）は変えない。同じ薬は自動でまとまり、所持枠の数え方を「個数」から「スタック数＋装備品数」に変える。
- スタック最大数：傷薬10・解毒剤10・気付け薬5・上傷薬5・霊薬3。武器・防具は1（スタック不可）。
- スタックが上限に達した薬をさらに手に入れた場合、空き枠があれば新しいスタックが始まる。空きがなければ従来どおり受け取れない。
- 使う・売る・渡す・預ける・取り出すは1回につき1個。
- アイテムボックス（106）にも同じ数え方を適用する（容量100はスタック数＋装備品数）。
- セーブ形式（ash-v1）は変えない。古いセーブもそのまま読める。
- Notion のアイテムDBに「スタック最大数」の欄を追加し、全81件に値を入れる（薬は上記、装備は1）。ゲーム側の定義と同期テストで突き合わせる。欄の追加と値の設定・スナップショット再生成は Muse が行う（本指示書の Codex 担当はゲーム側とテスト側）。

## 現行挙動（コードで確認済み・2026-11-12、main a152a94）

- `dist/items.js` の MEDICINES が薬の正本（5件）。冒頭コメントは「1個につきアイテム1枠」。
- 所持品 `s.inventory[i]` は ID の配列で、上限は要素数10。装備位置（equipped / armor）はこの配列への添字。
- 個数で判定している箇所：`lootRecipient`（items.js。dropWeapon / rewardChest / dropMedicine が使う）、`buy` と `renderShop` の購入可否（game.js）、`transferItem` / `renderTransfer`（party.js）、アイテムボックスの `depositItem` / `withdrawItem` と容量表示（game.js、106）、読み込み時の `ensureProfile` の `slice(0,10)` 切り捨て（game.js）。
- 薬の使用は `medicineSlots(i)` が薬のある枠を列挙し、`useMedicine` が枠を1つ splice して消費する。戦闘中の使用予約 `s.itemPlans[i]` は {slot, target, id} を保持する。
- アイテムボックス `s.itemBox` も ID の配列（最大100要素）。106で図鑑と同じ分類（`itemBoxCategory`）のタブ表示。

## 実装内容

### 枠数の数え方（共通ヘルパー）

- `stackMaxOf(id)`：薬は定義の `stack`、それ以外は1。
- `usedSlots(ids)`：装備品は各1枠。薬は ID ごとに `ceil(個数 / スタック最大数)` 枠。
- `canAccept(ids, id, cap)`：薬で、現在の個数をスタック最大数で割った余りが0でない（最後のスタックに空きがある）なら枠を使わず受け取れる。それ以外は `usedSlots(ids) < cap` のときだけ受け取れる。
- MEDICINES の各定義に `stack` を追加する（傷薬10・解毒剤10・気付け薬5・上傷薬5・霊薬3）。items.js の冒頭コメントも実態に合わせて更新する。

### 入手・購入・移動の判定差し替え

- `lootRecipient(w)`：装備可否の条件は現行どおり。枠の条件を `canAccept(s.inventory[i], w.id, 10)` に変える（フォールバック側も同じ）。
- `buy` / `renderShop`：`s.inventory[i].length>=10` を `usedSlots(s.inventory[i])>=10` に変える（店で売るのは装備のみ）。
- `transferItem` / `renderTransfer`：宛先の判定を `canAccept(s.inventory[to], id, 10)` に変える。表示の「(n/10)」は `usedSlots` の値にする。渡す対象の一覧は下記の表示行（スタック単位）を使う。
- アイテムボックス：`depositItem` のボックス側判定を `canAccept(s.itemBox, id, 100)`、`withdrawItem` の所持側判定を `canAccept(s.inventory[i], id, 10)` に変える。容量表示は `usedSlots` で数える。満杯時の通知文言は現行の趣旨を維持する（例：「ボックスがいっぱいです」は枠ベースの表示に合わせる）。

### 表示行（スタック単位の行合成）

- 所持品ダイアログ（`renderInventory`）とアイテムボックスの両タブグループ（106）で、表示行を合成する：装備品は1点ごとに行、薬は ID ごとにスタック最大数ずつの塊（チャンク）を行にする。行の並びは配列内の出現順（最初の出現位置）で安定させる。
- 薬の行には個数を出す（例：「傷薬 ×3」。1個のときは「×1」を出さない）。
- 各行のボタン（使う・売却・渡す・預ける・取り出す）は1個に対して作用する。内部的には、そのチャンクに属する先頭の配列添字を代表枠として既存処理（useMedicine / sell / removeInventorySlot 経由）に渡す。薬は装備されないため、代表枠の splice で装備添字がずれることはない。
- 所持品ダイアログの見出し「(n/10)」とボックスの容量表示は `usedSlots` の値にする。所持品ダイアログの空き行の描画（10行固定）は、表示行＋空き行で合計10行になるようにする。

### 薬ダイアログと戦闘中の使用予約

- `medicineSlots(i)` はチャンク単位で返す（{slot: チャンク先頭の添字, item, count}）。薬ダイアログの一覧表示は「枠N」ではなく個数表示（「傷薬 ×3」）にする。
- 戦闘中の使用予約は現行どおり {slot, target, id}。解決時にその枠の ID が変わっていたら、同じ ID の最後の添字を探して消費する（102の consumeArmor が予約枠をずらす既存パターンと整合させる）。見つからなければ使用は不発（現行の検証で弾く）。

### 読み込み時の切り捨て

- `ensureProfile` の `slice(0,10)` を、枠数が10以下になるまで末尾から1要素ずつ取り除く処理に変える（`usedSlots` 基準）。取り除いた要素が装備添字に関わる場合は、後段の既存の正規化（equipped の範囲外修正など）と矛盾しないようにする。薬だけを大量に持つ古いセーブ（例：傷薬15個＋剣1本＝枠2）が切り捨てられないことをテストで固定する。

### Notion 同期テストの拡張（Codex 担当分）

- `tests/notion-items.cjs` に、スナップショット各行の「スタック最大数」が、薬は MEDICINES の `stack`、それ以外は1と一致することの検証を追加する。
- スナップショット `data/notion-items.json` の再生成は Muse が Notion 側の設定完了後に行う。Codex の実行時点ではスナップショットに「スタック最大数」が無い場合がある。その場合はテストが「スナップショット未更新」で落ちることを実施報告に明記し、捏造した値でスナップショットを書き換えないこと。

### 仕様書

- `docs/SPECIFICATION.md` にスタックの規則（対象・最大数・枠の数え方・ボックスへの適用）を追記する。

## テスト（Codex が追加・更新する）

- 新規 node テスト `tests/item-stacking.cjs`（tests/game.cjs に登録）：
  - usedSlots / canAccept の数理：傷薬10個＝1枠、11個＝2枠、薬と装備の混在、上限ちょうどのスタックへの追加可否
  - 入手：スタックに空きがあれば枠なしで受け取る／スタック満杯＋空き枠なしでは受け取れない（lootRecipient が -1）
  - 使用：チャンクから1個消費し、チャンクが空になったときだけ枠が減る
  - 渡す：宛先のスタックに空きがあれば枠なしで渡せる／満杯＋枠なしでは渡せない
  - ボックス：預ける・取り出すの枠数判定（106のテストと矛盾しないこと）
  - 読み込み：傷薬15個＋剣1本のセーブが切り捨てられずに読める／枠数超過の異常セーブは末尾から削られる
- ブラウザテスト `tests/item-stacking-browser.py`：所持品ダイアログで「傷薬 ×3」のようにまとまって表示されること、薬ダイアログの個数表示、ボックスでのまとめ表示と預け入れ・取り出し。
- 既存の回帰：node tests/game.cjs 全件（106の item-box テストを含む）、ブラウザテスト全件、python3 scripts/compile-monsters.py --check、sim selftest、MANIFEST 一致。テスト側の前提（個数＝枠数）が変わる既存テストは、仕様変更に合わせて追随させる（期待値を緩めるためではない）。

## 制約

- dist のファイル数は増やさない。セーブ形式（ash-v1）・検証（validateSaveData）には触らない（配列形式が不変のため）。
- 薬の効果・価格・出現率は変えない。装備の装備規則・売却価格は変えない。
- 敵のHP・能力値をプレイ画面に出さない、ダイスの内部計算をログに出さない（従来ルール）。
