# 082 罠の「階段までの道」保護を1Fのみに限定する

状態: 作成済み（実装待ち）

## ユーザーの要望（原文）

> 階の生成機能ですが、どうやら次の階段までの道ができるように、罠はその道筋を避けてマップを生成する仕組みがあるそうです。これは、難易度に直結するので、この仕組みは1Ｆだけにして、それ以降の階層ではこの仕組みを無効にしてもらえますか

（2026-11-07 16:13 JST）

## 現行仕様の確認（実施者がコードで確認済み）

- `dist/game.js` の `fresh(floor)` は、開始地点から守護者マス（撃破後に降り階段になるマス）まで単調に進むランダムな道筋を引き、その道筋の全マスと開始地点・その周囲を `safe` 集合に入れ、罠は `safe` の外にだけ配置している。これにより全階で「罠のない道」が必ず存在する。
- 道筋の終端である守護者マス自体も `safe` に含まれ、罠が置かれることはない。
- `tests/game.cjs` には「1〜3Fとも開始エリアと守護者までの道が安全」という現行仕様のテストがある。

## 解釈（実施者の判断。報告でユーザーに明示する）

- 無効化の対象は「開始地点→守護者までの道筋の保護」のみとする。
- 開始地点とその周囲（開始エリア）の安全は全階で維持する。これは道筋とは別の、出現直後の安全策であり、要望の対象外と解釈した。
- 守護者マス自体への罠配置は全階で引き続き禁止する。罠が守護者マスに置かれると、隣接マスの数字に数えられるのに踏んでも発動せず旗でも処理できない「幽霊の罠」になり、昇降機解放条件（全マスが罠か開放済み）なども壊れるため。

## 変更内容

- `fresh(floor)` の道筋計算（開始地点から守護者まで歩いて `safe` に加える処理）を、1F（floor===1）のときだけ実行する。
- 2F以降は `safe` を開始地点・その周囲・守護者マスだけとし、道筋だったマスにも罠が配置されうるようにする。
- 罠の総数（trapCount）・盤面サイズ・その他の生成仕様は変えない。
- `placeCorpses(safe)` は同じ `safe` を受け取るため、2F以降は遺体で押し出された罠の再配置先にも道筋のマスが含まれうる（開始エリアと守護者マスは引き続き除外）。これは本変更の意図に沿う。

## テストの更新

- `tests/game.cjs` の生成テストを新仕様に合わせる。
  - 1F: 従来どおり、1000枚すべてで開始エリア＋守護者までの罠なし道が存在すること。
  - 2F・3F: 罠の総数と開始エリア（開始地点・周囲・守護者マス）の安全は1000枚すべてで維持されること。一方、従来の貪欲な道探索（罠のない単調路をたどる方法）が1000枚すべてでは成功しないこと（＝保護が外れていることの統計的な確認。保護が残っていれば必ず1000枚成功する）。

## 検証

- node テスト全本・ブラウザテスト全本・compile-monsters --check・sim selftest が合格すること。
- 実施者が生成を直接たどり、1Fでは道が残り、2F以降では道筋上に罠が出るマップが生成されることを確認する。
