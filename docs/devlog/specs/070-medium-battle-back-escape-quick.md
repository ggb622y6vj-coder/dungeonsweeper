# 070 戦闘コマンド：「戻る」位置固定・「逃げる」を先頭メンバーのみ・「クイック攻撃」追加

対象コード: origin/main 076e70b（読み取りのみ）

## ユーザー要望（原文）
「戦闘中の「戻る」ボタンは、そのボタンより上にある戦闘コマンドボタンの数に左右されず、どのメンバーの選択肢でも同じ位置に表示されるようにしてください。また、「逃げる」ボタンは、戦闘メンバーの一番最初のメンバーのコマンド画面にしか表示しないようにしてください。戦闘中に、物理攻撃で戦えるメンバーは全員1列目を狙い、物理攻撃が届かないメンバーは全員守るを自動的に選択し、行動の確認も出ずに戦闘コマンドを開始する「クイック攻撃」機能を実装してください。「クイック攻撃」ボタンは「逃げる」ボタンと同様に、一番最初のメンバーの選択画面にだけ表示し、他のボタンとはハイライトやデザインを若干変えて、挙動が異なるものだってわかりやすい形にしてください。」

## 背景（現状のコード事実）
- `#battle` は render 時に `<div id="commandentry"></div><button id="flee">逃げる</button>` で作り直される（game.js）。`#flee` は boss／誤った旗で disabled。
- `renderCommandEntry()`（dist/combatui.js）
  - `commandMembers()` = `partyIncapacitated(i)`（死亡等で `!activeMember(i)` または麻痺）でないメンバーの index 列。`commandIndex` がその中の位置。
  - 行動画面のボタンは `.commandchoices`（2列グリッド）内に順に:
    戦う（`canWeaponAttack(i)` のときのみ。恐怖中は disabled で表示）／守る／呪いを解く（僧侶 job 2 のみ）／呪文（`hasSpells(i)`）／アイテム（`medicineSlots(i)` があるとき）。
    → ボタン数は職業・状態で 1〜5 個（グリッド 1〜3 行）。
  - 「戻る」(`.commandback`, `data-command-back`) は `.commandchoices` の**直後**に置かれる。グリッド行数が変わるため、メンバーごとに縦位置がずれる（要望の原因）。先頭メンバーでは disabled。
  - 列選択（`choosingRow`）・呪文対象（`pendingSpell`）でも同じ枠を使い、ボタン数は敵列数・対象数で変わる。
  - 全員入力後は「行動確認」画面（`#attack`「この行動で戦う」＋戻る、`#commandreviewpopup` に一覧）。
  - `#flee.hidden = busy || ready || !!allyTargetPick` → **現状は全メンバーの入力画面で「逃げる」が出る**（行動確認画面では非表示）。
- 物理攻撃の可否: `canWeaponAttack(i) = 恐怖でない && (i<3（前衛） || 装備武器が ranged)`。
  届く列: `reachableEnemyGroups(i)` = 生存敵のいる列のうち、遠距離武器なら全列、それ以外は先頭2列。
  → `canWeaponAttack(i)` が true なら「生存している先頭の列（表示上の1列目）」には必ず届く。
- 列の扱い: `enemyGroups()` は報酬処理済み（撃破）ユニットを除いて列を詰めるため、元の1列目が全滅していれば次の列が「1列目」表示になる。`s.attackRows[i]` に列 key を保存。
- `attack()`（game.js）は `s.commands` に従い、`partyIncapacitated` でないメンバーのみ行動。終了後 `resetCommandEntry()`/`resetPartyCommands()`。
- キーボード: dist/keynav.js が `data-key-default`／`data-key-back` とグリッド移動で操作。tests/keynav.cjs にボタン配置の固定座標テストあり。
- レイアウト: ブレークポイント max-width 700px / 420px。390幅はスマホレイアウト。
- シミュレーター（scripts/sim/combat.cjs `planTurn`）は `s.commands` を直接設定し UI を使わない → 本件の影響なし（推測ではなくコード上 UI 非依存）。
- 関連テスト: tests/battle-keys-browser.py, keynav.cjs, fear.cjs, silence.cjs, game.cjs, auto-reorder*.{cjs,py}, library-identify-browser.py, mobile-map-battle-browser.py（`#flee` や戻るを参照）。

## 仕様
### 1. 「戻る」の位置固定
- 行動画面・列選択・呪文対象選択の `.commandchoices` に、行動画面の最大ボタン数（5個＝2列×3行）分の高さを `min-height` で確保する。ボタンが少ないメンバーでも空きができるだけで、「戻る」の縦位置は変わらない。
- それより多い選択肢（列・呪文対象が7個以上など）が出る場合は、枠の高さは固定のまま枠内スクロール（`overflow-y:auto`）にする。
- 高さは 1280幅・390幅（ボタン min-height 44/40px、gap 7px）それぞれで CSS 変数等から算出する。
- 「戻る」の直下に、先頭メンバー専用の「クイック攻撃」「逃げる」を置く（下記）。「戻る」より上には何も追加しないので、位置は全メンバー共通になる。
- 行動確認画面（`#attack`＋戻る）も同じ位置に「戻る」が来るよう、同じ高さ確保を適用する。

### 2. 「逃げる」は先頭メンバーのみ
- `#flee` を `commandIndex===0 && !choosingRow && !pendingSpell && !allyTargetPick && !busy` のときだけ表示する。
- 「先頭メンバー」は `commandMembers()[0]`（行動可能な最初のメンバー）。1人目が死亡・麻痺なら次の行動可能メンバーの画面に出る。
- boss／誤った旗での disabled と title は現状どおり。

### 3. 「クイック攻撃」
- ボタン `#quickattack`「クイック攻撃」を、「逃げる」と同じ条件（先頭メンバーの行動画面）でだけ表示。「戻る」の下に「クイック攻撃｜逃げる」の横並び（390幅でも2列）。
- 押下時:
  1. `commandMembers()` の各 i について、`canWeaponAttack(i)` が true なら `s.commands[i]='fight'`、`s.attackRows[i]=` 生存敵のいる先頭列（`enemyGroups()` で生存ユニットのいる最初の列）の key。
  2. それ以外（後衛の近接武器・恐怖・武器なし等）は `s.commands[i]='guard'`。
  3. 行動確認を出さず、そのまま `attack()` を実行。
- 行動不能メンバー（死亡・麻痺）は対象外（`attack()` 側も現状どおりスキップ）。
- boss 戦や誤った旗でも使用可（逃走ではないため）。
- 物理攻撃できるメンバーが1人もいない場合は disabled（title「物理攻撃できるメンバーがいない」）。←質問2
- 見た目: 他ボタンと区別できるよう、アクセント色の枠線（例: 金色の2px枠＋薄い金色背景）と「⚡」等のアイコン、小さな補足文「全員1列目へ攻撃」を付ける。
- 連打防止: `logBusy()` 中は無効。

### 4. キーボード
- 「クイック攻撃」「逃げる」は既存のグリッド移動で到達できること。`data-key-default` は従来どおり最初の行動ボタン（戦う等）のままにする（誤って即開始しないため）。

## OKの判定方法
- ロジックテスト（新規 tests/quick-attack.cjs）:
  - 前衛近接・後衛遠距離 → fight＋先頭列、後衛近接 → guard、恐怖中 → guard、麻痺・死亡 → 対象外。
  - 元の1列目が全滅した状態で、次の生存列が狙われる。
  - クイック攻撃で確認画面を経ずに1ターン進む。
  - 1人目が麻痺のとき、2人目の画面にクイック攻撃・逃げるが出る。2人目以降（commandIndex≥1）では出ない。
  - 全員攻撃不可なら disabled。boss 戦でクイック攻撃は使え、逃げるは disabled。
- ブラウザテスト（Playwright、幅 1280 と 390）:
  - ボタン数が異なる職業（戦士・僧侶・魔法使い等）で、「戻る」の bounding box の y 座標が全メンバー・行動確認画面で一致する。
  - `#flee`・`#quickattack` が先頭メンバーでのみ visible。
  - クイック攻撃押下で `#commandreviewpopup` が出ずにログに「ターン開始」が出る。
  - 390幅で横スクロールが発生せず、ボタンが画面内に収まる。
- 実画面の目視確認: 1280/390 で各メンバーの画面のスクリーンショットを撮り、「戻る」の位置が揃っていること、クイック攻撃が他と見分けられることを確認。
- 既存テストすべて通過（keynav.cjs の座標・battle-keys-browser.py は配置変更に合わせて更新可。期待値の変更理由をコミットに記載）。

## 質問
1. 「クイック攻撃」「逃げる」を「戻る」の**下**に置く案でよいですか？（上に置くと先頭メンバーだけ「戻る」がずれるため）
   - おすすめ: 下に置く。
2. 物理攻撃できるメンバーが1人もいないとき（全員後衛扱い・恐怖など）は、「クイック攻撃」をどうしますか？
   - おすすめ: disabled にする（全員「守る」だけのターンを誤って始めないため）。
3. 恐怖で「戦う」が使えないメンバーは「守る」扱いでよいですか？
   - おすすめ: はい（要望の「物理攻撃が届かないメンバー」と同じ扱い）。

## Amendment (ユーザー回答 2026-11-04 13:11)
1. 「クイック攻撃」と「逃げる」は「戻る」の下に置く。
2. 物理攻撃できるメンバーが1人もいないとき、「クイック攻撃」は押せない（グレー表示）。
3. 恐怖状態のメンバーはクイック攻撃では「守る」。
