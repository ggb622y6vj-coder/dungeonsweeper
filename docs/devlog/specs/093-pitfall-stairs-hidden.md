# 093: 落とし穴で落ちた階の上り階段が地図に見える問題の修正

## ユーザーの依頼（原文）

> 落とし穴で下の階に落ちたんですけど、上り階段が地図上で見えるようになってました。再現できますか？

再現確認の報告後、ユーザーが「指示書093として修正する」と決定した。

## 再現結果（現行 main 26b2ed4、実経路で確認）

- 下の階が未生成の状態で落とし穴（床罠・宝箱罠の両方）で落ちると、着地マスとは別の場所にある開始マス（上り階段）が探索済み（open）になり、地図に ⇧ が表示される。
- 保存済みの階への落下では発生しない。昇降機で未生成の階へ着いた場合も発生しない（076 で修正済み）。

## 原因

階の生成（fresh）が開始マスを open=true で作る。階段到着は開始マス自体に着くため正しいが、落とし穴の着地先は型のない通常マスから選ばれ開始マスにはならない（候補がない場合のフォールバックを除く）。travelElevator は生成直後に開始マスを閉じ直すが、descendPitfall（088 で追加）にはその処理がなかった。

## 修正

- dist/traps.js の descendPitfall() で、到着した階が新規生成だった場合（enterFloor の generated が真）に限り、着地先が開始マスでないときは開始マスを閉じる（s.cells[s.start].open=false）。travelElevator の既存処理と同じ考え方。
- フォールバック（着地候補がなく開始マスに着地した場合）は開始マスを開いたままにする（現行の保存済み階フォールバックのテストが固定している挙動と揃える）。
- 保存済みの階の復元には触れない。fresh() 自体も変更しない（階段到着が開始マスの open に依存している）。

## 回帰テスト（tests/pitfall.cjs に追加）

- 床の落とし穴で未生成の階へ落ちたとき、開始マスが閉じていて、地図（盤面 HTML）に ⇧ が出ないこと。着地マスは開いていること。
- 宝箱の落とし穴で未生成の階へ落ちたときも、開始マスが閉じていること。

- node tests/game.cjs 全件、ブラウザテスト全件、scripts/compile-monsters.py --check、sim selftest、MANIFEST 照合。
