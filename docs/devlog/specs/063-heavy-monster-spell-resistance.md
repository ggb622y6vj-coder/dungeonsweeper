# 063 [heavy] モンスターの呪文抵抗率（魔法使い呪文／僧侶呪文で別々）

## 背景
- 今のゲームには、呪文そのものを無効にする抵抗率がありません（report/monster-spell-resist.md）。
- 原作 #1 では、モンスターごとに「魔法抵抗率 %」があります。判定に当たると、その呪文はそのモンスターに丸ごと効きません（Data Driven Gamer「The bestiary of Wizardry」）。
- ユーザーの要望：モンスターごとの抵抗率を、魔法使いの呪文と僧侶の呪文で別々に設定する。実装後に、Notion にも 2 つの列を追加する。

依存：062 の後（追加された 2 体にも値を入れるため）。

## 仕様
### データ
- CSV の末尾に 2 列を追加します：`魔法使い呪文抵抗`、`僧侶呪文抵抗`。値は 0〜95 の整数（%）です。
- compile で `mageResist` と `priestResist`（0〜0.95 の小数）を出力します。範囲外や空欄はエラーにします。
- 初期値は下の表のとおりです【Q1】。

### 対象の呪文
- パーティーが**敵に向けて**唱える呪文のうち、効果が damage・sleep・silence・death・threshold-death のもの。対象は次のとおりです。
  - 魔法使い：ハリト・カティノ・マハリト・ダルト・マカニト・ラカニト・ティルトウェイト
  - 僧侶：モンティノ・ロルト・マリクト
- AC を下げる呪文（ディルト・モーリス・マモーリス）を含めるかは【Q2】で決めます。
- 識別・回復・味方への補助・ミルワピックは対象外です。
- どちらの抵抗率を使うかは、呪文の系統（job 1 か 2）で決まります。術者の職業ではありません。
- 敵が唱える呪文には関係ありません。

### 判定の順番
1. 対象のモンスター 1 体ごとに、`Math.random() < 抵抗率` で判定します。成功したら、その個体にはこの呪文が**まったく効きません**（ダメージ 0、状態異常なし、即死なし）。
2. 抵抗されなかったときだけ、既存の判定に進みます：属性半減 → ダメージ、または レベル差による成功率、即死判定など。
- 守護者やボスにも同じ判定をします。「睡眠や沈黙が効かない」などの既存の無効ルールはそのまま残します。

### ログと画面
- 抵抗したときのログ：「{表示名}は呪文をはね返した！」。今の「効かなかった」「耐えた」とは別の文言にします。
- 戦闘画面に抵抗率は表示しません（原作どおり）。図書館に表示するかは【Q3】で決めます。

### 初期値（おすすめ案）
階ごとの基本値（魔法使い呪文と僧侶呪文で同じ値）：

| 階 | 基本値 |
|---|---|
| 1〜2F | 0% |
| 3〜4F | 5% |
| 5〜6F | 10% |
| 7〜8F | 20% |
| 9〜10F | 30% |

種族による補正（推測：原作の傾向を参考にしたもの）：
- 悪魔：魔法使い呪文 +20、僧侶呪文 +20
- 不死：僧侶呪文 +10
- 竜：魔法使い呪文 +10
- 構造体：魔法使い呪文 +15
- 守護者：さらに両方 +10
- 迷宮の主：両方 70%

上限は 95% です。初期値は、ゲームにある全モンスターの値として CSV に直接書き込み、あとから個別に調整できるようにします。

### セーブ互換
- 値はモンスターの定義側にあるため、セーブデータの変更や移行は不要です。戦闘中のセーブを読み込んでも、そのまま動きます。

### Notion
- 実装後、モンスター DB に数値の列「魔法使い呪文抵抗」「僧侶呪文抵抗」を追加し、全行に CSV の値を書き込みます。これは別の作業として、ユーザーの承認を得てから行います。

## OKの判定方法
1. compile が新しい列を検証すること（96 や -1 を入れるとエラーになる）。
2. テストを追加します（tests/spell-resist.cjs、乱数は固定）：
   - 抵抗率 100% 相当（スタブ）にすると、ダメージ呪文・睡眠・沈黙・ラカニト・マカニトのどれも効かず、「はね返した」のログが出ること。
   - 抵抗率 0% にすると、今までと同じ結果になること。
   - 魔法使い呪文は mageResist だけを、僧侶呪文は priestResist だけを使うこと。
   - 列攻撃で、個体ごとに判定が分かれること。
3. 属性半減のモンスターに抵抗されなかった場合、今までどおり半分のダメージになること。
4. ライブの 1280 と 390 の幅で、10F の悪魔にティルトウェイトを撃つと、一部の個体がはね返すこと。ログが読みやすいこと。
5. sim（scripts/sim）で、深い階の勝率がどう変わるかを報告すること（NG 扱いにはしない）。
6. 全テストが通ること：tests/*.cjs、ブラウザテスト、compile --check、selftest。
