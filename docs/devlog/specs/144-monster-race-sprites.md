# 指示書144: モンスターの種族ドット絵表示（未確定時は種族の画像）

日付: 2026-11-26
ブランチ: hold/144
根拠: Notion 実装予定DBの試案「モンスターのドット絵表示（階層テーマカラーで色付け）」（2026-11-24作成、2026-11-26更新）。オーナー決定済み事項は試案の第8節のとおり。本指示書はその第1段階で、使う画像は種族の10枚のみ（固有画像は後続の指示で追加する）。

## 1. 目的

戦闘画面の敵表示を、枠＋icon文字から、48×48・4段階グレーのドット絵に置き換える。画像は階層テーマカラーで色付けし、正面の壁の上に縦横比1:1のまま大きく描く。未確定（identified でない）の間は種族の画像を使い、確定後も固有画像がないモンスターは種族の画像を使う。

## 2. アセット（配置済み）

種族の画像10枚は本ブランチに配置済み（dist/assets/monsters/unknown/）。すべて48×48・グレー4値（0／85／170／255）のみ・背景透明であることを確認済み。ファイル名は実ファイルどおり（shokubutu は shokubutsu ではない）。

種族（ENEMIES の race の値）とファイル名の対応（コード内に固定表として持つこと）:

| race | ファイル |
| --- | --- |
| 不定形 | futeikei.png |
| 不死 | fushi.png |
| 獣 | kemono.png |
| 人型 | hitogata.png |
| 虫 | mushi.png |
| 構造体 | kouzoutai.png |
| 悪魔 | akuma.png |
| 魔獣 | majuu.png |
| 竜 | ryuu.png |
| 植物 | shokubutu.png |

現在の114種すべての race がこの10種の範囲内である（照合済み）。

## 3. 表示の優先順とフォールバック

各グループの代表個体（現行 drawEnemies と同じく、rewarded でない先頭個体）について:

1. 個体が identified で、かつモンスターIDが固有画像の一覧（MONSTER_SPRITES、初期状態は空）にある場合 → dist/assets/monsters/<モンスターID>.png。本指示書では固有画像は1枚も置かないため、この分岐は実際にはまだ発動しない。一覧の仕組みだけ用意すること。
2. それ以外 → 種族の画像（dist/assets/monsters/unknown/<対応ファイル>）。
3. 画像の読み込みに失敗した場合 → そのグループは従来の枠＋icon文字で表示する（フォールバック）。

制約:
- 未確定の間、固有画像のファイル名（モンスターID）を画面に出してはならない（src・alt・title 等にIDや確定名を含めない）。alt は不確定名または空にすること。
- race が対応表にないモンスターが現れた場合は種族の画像なしとして扱い、従来表示にフォールバックする（検出用のテストを第7節に用意する）。

## 4. 描画方法

- 対象は現行どおり戦闘画面の先頭2グループ（drawEnemies の範囲）。
- 画像が表示されるグループについては、SVG内の枠（rect）と icon 文字を描かない。
- 画像はシーンSVGの中ではなく、#scene（position:relative）に重ねる HTML の img 要素（position:absolute、pointer-events:none）で表示する。シーンSVGは preserveAspectRatio="none" で伸縮するため、SVG内に置くと画像がゆがむ。
- 横位置: 画像の中心を、viewBox座標で1グループなら x=320、2グループなら x=240／x=400 に合わせる（#scene の実寸へ換算）。
- 縦位置: 画像の下端を正面の壁の下端（viewBox y=300）にそろえる。
- 大きさ: 目標サイズ = min（正面の壁の高さ（viewBox 200単位を実寸換算）の95%、横150 viewBox単位を実寸換算）px。
- 条件付きの丸め（オーナー決定）: 目標サイズに devicePixelRatio を掛けた画素数について、48の整数倍で最も近いものを求め、その差が目標の ±15% 以内なら、その整数倍になるよう表示サイズを調整する。±15% を超える場合は丸めず目標サイズのままにする。
- image-rendering: pixelated を指定し、縦横比は常に1:1に保つ。
- 画面幅・向きの変化や #scene の大きさの変化に追従して、位置と大きさを再計算する（ResizeObserver 等）。
- .scene-enemies（左上の列一覧）と重ならないこと。
- 遭遇通知（.encounter-notice）は現行どおり画像より手前に表示する（通知が出ている間は画像がその下になる。現行の枠表示と同じ重なり順）。

## 5. 色付け（階層テーマカラー）

- 4段階グレーを、テーマの中間色から作る次の4色に置き換える:
  - 0 → 黒と中間色を10%混ぜた色
  - 85 → 黒と中間色を45%混ぜた色
  - 170 → 中間色そのもの
  - 255 → 中間色と白を60%混ぜた色（白寄り）
- 中間色は SCENE_PALETTES から取る: green は corridorLine（#829079）、blue は guardianLine（#7d86b5）、yellow は guardianLine（#b59a5e）、orange は guardianLine（#c08d54）、red は guardianLine（#bd7268）、purple は guardianLine（#9a7fc0）。テーマと階層の対応は currentFloorTheme の現行どおり。
- 実装方式は SVG の feComponentTransfer（R・G・B それぞれ type="table" で4値を指定）をテーマごとに定義し、CSS の filter: url(#…) で img に適用する方式とする。アルファは恒等のまま（透明を保つ）。canvas で画素を読み出す方式は使わない（file:// で開いたときに getImageData が失敗するため）。
- 色付けは表示時の一度きりの処理とし、アニメーションは追加しない。

## 6. 戦闘中の正面のマス表示

- scene() では現在、戦闘中に正面・左・右の3面すべてについて数字の記号だけを消している。これを変え、戦闘中は正面のマスの記号をすべて（「？」「✓」「⚑」「▣」「⇩」など）表示しない。左・右は現行どおり（数字だけ消す）。
- 戦闘が終われば元の表示に戻る（描画のたびに導出される現行の仕組みのまま）。
- 記号を描いたまま画像で覆う方式にはしない（描画自体をしない）。
- 遠見（透視、distantSight）の左右斜め前の記号も、戦闘中は表示しない（オーナー決定、2026-11-26）。敵が2列のとき記号の位置が画像と重なり、絵の透明部分から透けて見えるのを避けるため。戦闘が終われば戻る。

## 7. テスト

- node テストに次を追加する:
  - 全モンスターの race が対応表にあり、対応する画像ファイルが dist/assets/monsters/unknown/ に存在すること。
  - 画像ファイルが48×48・グレー4値のみであること（PNGの画素を読む検証が難しければ、ファイルの存在と寸法の確認までに留めてよい。その場合は理由を報告に書くこと）。
- ブラウザテスト:
  - enemy-display-browser.py を新しい表示仕様へ更新する（枠の座標などの期待値は新仕様に合わせて置き換え、検証の強さは落とさない）。
  - 画像が表示されること、1グループ・2グループの位置、縦横比1:1（画面幅1280pxと390px）、戦闘中に正面のマスの記号が消えて戦闘後に戻ること、未確定時は種族の画像（/unknown/ のURL）であることを確認するテストを追加する。
  - テーマごとの色付けは scene-theme-browser.py 側で、テーマに応じて異なる filter が適用されることを確認する（画素色の厳密な一致までは求めない）。
  - 画像の読み込みを失敗させた場合に従来の枠＋icon文字へフォールバックすることを確認するテストを追加する（リクエストの遮断などで再現する）。
- 既存テストで旧表示（枠・icon文字）を前提とするものは、新仕様への追従として期待値を更新してよい（検証の強さは落とさない）。
