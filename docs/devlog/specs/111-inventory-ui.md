# 指示書111：呪文ウィンドウの表記整理・アイテムウィンドウの配置変更・捨てる新設・売却の個数選択

- 起点：オーナーの依頼（2026-11-13）。基準 main は c857a90（110 完了直後）。
- 対象は4件。いずれも UI とアイテム操作の範囲で、セーブ形式・ゲームバランスは変えない。

## 1. 呪文ウィンドウの行から習得情報を外す

- `renderMagic()`（dist/spells.js）の呪文行 `<small>` は現行「習得済み · Lv.{level} · {確定習得|習得率50%}（· 理由）」。
- 変更後：「Lv.{level}（· 理由）」のみにする。「習得済み」「確定習得」「習得率50%」をすべて出さない。
- 理由：このウィンドウに出るのは習得済みの呪文だけで、習得可否の情報は不要なため。図鑑（図書館、dist/library.js）側の表示は変更しない。
- 空リスト時の文言「習得済みの呪文がありません」は行の表記ではないので対象外（現行のまま）。
- 旧文言を固定しているテスト（tests/spell-list.cjs、tests/makanito.cjs、tests/makanito-browser.py 等）は新表記に追随させること。

## 2. アイテムウィンドウの行の配置変更

- 対象：所持アイテムウィンドウ（`renderInventory()`、dist/game.js）の `.slot` 行。現行は横並び flex で、名前（`<b>`、flex:1）が効果テキスト（`<span>`）に押されて潰れ、縦書き状になる。
- 変更後の構造：左側のブロックに名前を見出しとして置き、その下に効果テキストを段落として左寄せで置く。ボタン類（使う／装備／外す／売却／捨てる）は右端に残す。
  - 例：`<div class="slot"><small>{番号}</small><div class="slotmain"><b>{名前}</b><span>{説明}</span></div>{ボタン群}</div>` とし、`.slotmain` は flex:1 の縦積みにする。正確なマークアップと CSS は実装時に既存の見た目（色・字サイズ・区切り線）を保って決めてよい。
- アイテムボックスのダイアログ等、他の一覧の配置は変更しない。

## 3. 探索中に「捨てる」を新設

- 現在、アイテムを捨てる手段は存在しない。アイテムウィンドウに「捨てる」ボタンを追加する。
- 表示条件：`s.area === 'dungeon'` かつ `idle()`（戦闘中・宝箱前・ボス／階段の確認中などは押せない）。町では出さない（従来どおり売却のみ）。
- 装備中のアイテムは捨てられない（売却と同じくボタン無効）。
- 押下後の流れ：確認ダイアログを必ず出す。行の個数が1なら「{名前}を捨てますか？」、複数なら個数（1〜行の個数）を選ばせてから確定する。キャンセルで何もしない。
- 捨てたアイテムは消滅する（どこにも残らない）。確定後は render() と renderInventory() で再描画する（売却と同方式）。

## 4. 売却の個数選択

- 現行の `sell(i, slot)` は行の先頭スロットを1個だけ売却する。行の個数が複数の場合（薬のスタック行）に、売却前に個数（1〜行の個数）を選ばせる。合計金額（単価×個数）が分かる表示にする。
- 個数が1の行は従来どおり1クリックで即売却する。
- 売却の確定後は従来どおり render()、renderInventory()、renderShop() で再描画する。

## 個数選択ダイアログ（3と4で共用）

- 捨てる（複数個）・売却（複数個）・捨てる（1個の確認）で使う共通の小さなダイアログを1つ新設する。既存ダイアログ群と同じ作法（`<dialog>` 要素、showModal、閉じたら元のウィンドウに戻る）。
- 中身：対象アイテム名、個数の選択（1〜所持個数）、確定ボタン（文言は用途で「捨てる」「売却する」）、キャンセルボタン。売却時は合計金額も示す。
- キーボード操作（keynav）の既存作法を壊さないこと。

## アイテム削除の mechanics（3と4で共用）

- 所持は ID のフラット配列。行は itemRows() が ID ごとにまとめたもの（薬はスタック上限まで1行、装備は stackMaxOf=1 のため常に1行1個）。
- n 個の削除は、行に対応する同 ID のコピーを n 個取り除く。各削除で既存 sell() と同じ装備インデックス追随（s.equipped[i] と s.armor[i] の位置調整）を行う。装備中チェックを通過した行だけが対象になるため、装備中コピーを消すことはないが、インデックスのずれは正しく直すこと。
- 共通の削除ヘルパーに切り出して sell／discard の両方から使うのが望ましい（重複実装は避ける）。

## テスト

- node テスト：捨てる（個数分の削除・装備中は不可・町では不可・戦闘中は不可）、売却の個数（合計金額・部分売却後の残数と装備インデックス）、呪文行の新表記（「習得済み」「確定習得」「習得率」を含まない）を検証するテストを追加または更新し、`node tests/game.cjs` に登録する（新規ファイルを作る場合）。
- ブラウザテスト：旧表記・旧構造を前提にしたものは追随させ、新ダイアログの基本フロー（探索中に捨てる確認→消滅、町で複数売却）が確認できるものを追加する。
- 全スイート（node、ブラウザ全件、compile-monsters、sim selftest）が合格すること。
