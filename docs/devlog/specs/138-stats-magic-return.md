# 指示書138: パーティー欄の呪文ボタンの戻る挙動をアイテムボタンに揃える

日付: 2026-11-25
ブランチ: hold/138

## 1. 問題

パーティー欄（#statsdialog）の各メンバーのボタンから開く画面のうち、アイテム画面は「戻る」でパーティー欄へ戻るが、呪文画面は戻るとパーティー欄ごと閉じてしまう。

原因: dist/game.js の #statsbody クリック処理で、アイテムボタン（data-stat-inventory）はパーティー欄を開いたまま openInventory を呼ぶのに対し、呪文ボタン（data-stat-cast）は `$('#statsdialog').close()` でパーティー欄を閉じてから openMagic を呼んでいる。

## 2. 修正内容

1. 呪文ボタンから開く場合も、パーティー欄を閉じずに呪文ダイアログ（#magicdialog）を重ねて開く（アイテムボタンと同じ形）。
2. 呪文ダイアログを閉じる操作（×ボタン、Esc、背景クリック）では呪文ダイアログだけが閉じ、下のパーティー欄に戻ること。
3. パーティー欄から開いた呪文ダイアログで呪文を唱えた場合、呪文ダイアログが閉じてパーティー欄に戻り、パーティー欄の表示（MPなど）が最新の値になっていること（render() には statsdialog が開いているときに renderStats() を呼ぶ既存処理があるので、それが働く形にすること）。
4. 対象選択（「パーティー欄で対象を選ぶ」、pickFieldSpell → beginAllyTargetPick）の扱い:
   - beginAllyTargetPick は仕様上すべてのダイアログを閉じてメイン画面で対象を選ばせる（現行どおりでよい）。
   - ただし、パーティー欄→呪文ダイアログから対象選択へ進んだ場合、対象選択をキャンセルしたら、呪文ダイアログだけでなくパーティー欄も下に復帰すること（現行は呪文ダイアログだけが再表示される）。
   - 対象を選んで発動が完了した場合は、現行どおり全ダイアログを閉じてメイン画面へ戻る（薬の使用後と同じ）。
5. 戦闘中のコマンド入力から開く呪文ダイアログ（combatui 経由）の挙動は変更しない。パーティー欄の呪文ボタンは戦闘中は無効化されている（現行どおり）。

## 3. テスト

- 新規ブラウザテスト（例: tests/stats-magic-return-browser.py）を追加する:
  - パーティー欄 → 呪文ボタン → 呪文ダイアログが開き、パーティー欄も開いたままであること。×で閉じるとパーティー欄だけが残ること。
  - パーティー欄 → 呪文 → 探索呪文を発動 → パーティー欄に戻り、MP表示が減っていること。
  - パーティー欄 → 呪文 → 味方対象の呪文で「パーティー欄で対象を選ぶ」→ キャンセル → 呪文ダイアログとパーティー欄の両方が復帰していること。
  - 回帰確認: パーティー欄 → アイテム → 閉じる → パーティー欄が残ること（従来どおり）。
- 既存テストで「呪文ボタンを押すとパーティー欄が閉じる」前提のものがあれば、新仕様への追従として期待値を更新してよい（検証の強さは落とさない）。

## 4. 対象外

- 盗賊の罠解除ボタン（data-stat-disarm）がパーティー欄を閉じる挙動（メイン画面での操作が前提のため現行どおり）。
- 薬・アイテムの使用後の遷移（現行どおり全て閉じる）。
