# 指示書121：アイテム鑑定と呪いの装備

## 根拠・決定事項

- 根拠は Notion 実装予定DBの試案「アイテム鑑定・呪いの装備（司教・鍛冶屋／Muse向け改訂試案）」（2026-11-21改訂版）。方向性（司教鑑定の原作準拠化と呪いの同時導入）はオーナー決定済み。
- オーナー決定（2026-11-21）：**鍛冶屋の鑑定料は原作準拠で売却額の100%**とする（試案の暫定25%は採用しない）。それ以外は試案の推奨どおり。
- 呪い解除料は試案どおり売却額と同額（100%）、解除は原作型（品を取り除き消去する）。
- 呪い付き装備の初期セットと数値は本指示書の表で確定する。出現は宝箱限定。
- 拘束された武器の解除後に代替武器がない場合は、職業の初期武器を自動装備させる（第6節）。

## 1. 個体状態（トークン方式）と共通処理

- 所持品・ボックスの装備エントリは文字列トークンで個体状態を持つ。実IDそのもの＝鑑定済み・未拘束、`unid:ID`＝未鑑定・未拘束、`bound:ID`＝鑑定済み・拘束、`unid-bound:ID`＝未鑑定・拘束。薬は常に実ID（対象外）。宝箱の `items` は従来どおり実IDのままで、変換は受領時に行う。
- 共通ヘルパーを用意し、全経路で使う：実IDの解決、未鑑定か、拘束か、呪い属性か（マスターの `cursed`）、表示名の解決（未鑑定は部位別の不確定名：武器＝「正体不明の武器」、頭＝「正体不明の兜」、胴＝「正体不明の胴防具」、足＝「正体不明の足防具」）。
- `weapon()` の呼び出し箇所を全数監査する。戦闘・AC等の効果解決では実定義へ解決し、表示・分類・売却額・装備可否などの情報側では未鑑定の実ID・性能・実売却額を露出させない。未鑑定品の実IDを DOM（id属性・データ属性・タイトル等）へ出さない。
- 既存の実IDは鑑定済み・未拘束として扱い、既存セーブの所持品・装備・図書を遡及変更しない。セーブキー `ash-v1`、`rosterVersion: 1` は維持。
- セーブ検証・インポートでは不正トークンを拒否する：薬への接頭辞、存在しないID、呪い属性のない品への `bound:` 系接頭辞、接頭辞の重ね掛け等。正当な未鑑定・拘束トークンは読込救済で削除・解除しない。職業不適合の非装備拘束品は有効な状態として保持する。

## 2. 入手経路と配布

- 宝箱報酬（新方式・旧方式とも）と直接ドロップで受け取る装備は `unid:ID` で所持品に入る。店での購入品、初期装備、導入前の所持品は鑑定済みのまま。
- 受領ログ・通知は不確定名で出す（例：「正体不明の武器を入手。○○が受け取った。」）。
- 未鑑定装備の戦利品配布は職業適性で推測させないため空き枠順とする。薬・鑑定済み品は従来ルール。全員満杯時は不確定名で通知し、図書館へ登録しない。
- 図書館へのアイテム登録は鑑定成功時（司教・鍛冶屋とも）のみ。入手・装備・売却・呪い解除では登録しない。

## 4. 司教の鑑定

- 現職が司教（job 7）で行動可能なメンバーの詳細（ステータス画面）に「鑑定」ボタンを追加する。対象はその司教自身の所持品の未鑑定装備のみ（他メンバーの品は先に譲渡させる）。控えメンバーは対象外。
- 使用可能条件は町・通常探索の操作待ち時（`idle()` 相当）。戦闘中・ログ再生中・宝箱確認中・行動不能時は不可。MP・呪文は不要で、沈黙・反呪文の結界内でも使用できる。無料・回数無制限。
- 確定時の処理順：(1) 鑑定成否を1回抽選する。成功率 p = clamp(10＋5×Lv, 0, 100)%。(2) 対象が先天的に呪い付きで未拘束なら、成否と独立に接触判定を1回行う。接触率 q = clamp(35−3×Lv, 0, 100)%。
- 成功したらその個体を鑑定済みにし、図書館へ登録する。ログは結果のみ（成功「正体不明の武器は○○だった！」、失敗「正体が分からなかった」等）。成功率・接触率の数値はログや画面に出さない。
- 接触したら第6節の拘束処理を司教へ適用する。失敗して拘束された品は呪いだけが判明し、名前は未鑑定のまま。拘束品の再鑑定は可（再接触は発生しない）。鑑定済み品への再実行は不可。
- 結果は即時保存し、ロードで再抽選しない。確定時に対象の所有者・添字・トークンを再検証し、古いダイアログが別の品に効かないようにする。

## 5. 鍛冶屋の鑑定と呪い解除

- 鍛冶屋に「鑑定」と「呪い解除」の入口を追加する（既存の購入・売却と区別する）。
- 鑑定：パーティー全員の未鑑定装備を一覧表示する（所有者・不確定名・鑑定料のみ表示）。料金は **max(1, 実売却額) G（100%）**。成功率100%、接触判定なし。成功時に図書館へ登録する。
- 呪い解除：パーティー全員の拘束品を一覧表示する（所有者・表示名・呪いタグ・解除料）。料金は **max(1, 実売却額) G**。実行すると対象個体は消去される（ボックス・店在庫へは移らない）。未鑑定のまま拘束された品も対象で、先に鑑定する必要はない。解除だけでは図書館へ登録しない。
- どちらも見積を事前表示し、確認後に実行する。金貨不足・キャンセル・対象消失・所持者変更・既鑑定品では料金を消費しない。実行直前に条件を再検証し、二重課金を防ぐ。成功時のみ金貨と状態を同時に更新して保存する。
- 武器の解除で装備中だった場合は第6節の後処理を行う。

## 6. 呪いの拘束

- 拘束の発生は2経路のみ：呪い付き装備を自発的に装備したとき、司教の鑑定で接触したとき。
- 接触時の処理：同部位に拘束品がなく、司教がその品を装備できる職業なら、その部位へ強制装備する（元の装備は所持品に残る。本作の装備は所持品への添字参照なので、参照を対象個体へ付け替える）。職業不適合、または同部位に別の拘束装備がある場合は、装備せず所持品として拘束する（その部位の通常装備・AC・攻撃に影響しない）。
- 拘束中の禁止操作：装備解除、同部位の他装備への変更（装備中の拘束品のみ）、売却、破棄、譲渡、ボックスへの預入、転職（拘束品が1点でもあるメンバーは転職不可）。敵の盗難等のアイテム除去処理でも拘束品を対象から除外する。禁止時は理由（呪い・解除不可）を表示する。
- 拘束は町帰還・レベルアップ・薬・回復呪文・寺院では解除されない。死亡・搬送・蘇生・全滅・遺体回収・酒場の加入離脱でも個体の拘束を保持する。
- 自発的装備：未鑑定品も職業適合を満たせば装備できる（初回に注意を出す）。装備しても正体は隠れたままで図書館へ登録しないが、戦闘効果・ACは実データで適用する。呪い付きなら装備した時点で拘束する。
- 武器の呪い解除後の後処理：装備可能な鑑定済み・未拘束の武器が所持品にあればそれへ差し替える。なければ職業の初期武器（キャラクター生成時に付与されるものと同一ID）を鑑定済み・未拘束で追加し装備させる。拘束武器の消去で空いた枠を使うため所持枠は溢れない。この救済で金策が成立しないこと（解除料100%に対し初期武器の売却額は僅少）をテストで確認する。防具の解除後は該当部位を空欄とし、装備参照・添字を正しく補正する。

## 7. 売却・譲渡・ボックス等の共通ガード

- 未鑑定・未拘束の装備の売却額は一律1G。鑑定済み・未拘束は通常価格。拘束品は売却不可。
- 未鑑定・未拘束品の譲渡・破棄・ボックス預入／取出は従来どおり可。拘束品はすべて不可。
- 譲渡・売却・破棄・預入の確認ダイアログ（111の個数ダイアログ含む）でも拘束ガードと表示名解決を通す。装備中の未鑑定品の扱いは既存の装備中ガードに従う。

## 8. テスト

新規テストを追加し、既存テストは新仕様への追従のみ行う（検証を弱めない）。

- 司教鑑定：Lv境界（1・11・12・17・18・30）の成功率・接触率と乱数境界（一致時は失敗）。成功／失敗×接触の有無の4パターン。通常品では拘束しない。自分の品のみ・無料・MP0可・非司教／控え／行動不能／戦闘・確認中は不可。失敗時は未鑑定保持。拘束品の再鑑定で再接触なし。
- 接触・拘束：強制装備（元装備を失わない）、同部位拘束あり・職業不適合では非装備拘束。弱体化した性能とACが戦闘・表示へ正しく反映される。
- 自発的装備：未鑑定・鑑定済み呪い装備の装備と拘束。未拘束品の譲渡／廃棄／売却可。拘束品の解除／交換／譲渡／廃棄／売却／預入／転職／盗難に抜け道がない。
- 鍛冶屋：鑑定は安全・確定成功で料金100%（ちょうど／不足／キャンセル／対象消失／二重確定）。解除は拘束品のみ・消去・料金100%。武器解除時の代替差し替えと初期武器救済、金策不成立。防具解除後の参照補正。
- 個体管理：同IDの4状態が同時に存在しても対象個体だけが更新される。薬スタック、10／100枠、装備添字、他部位の拘束が壊れない。
- 入手：新／旧宝箱・直接ドロップの未鑑定化、満杯処理、抽選済み中身の不変。呪い付き4品が宝箱ランク抽選の候補に入り、直接ドロップには入らない分布確認。
- 保存：死亡搬送・控え・全滅／遺体回収・帰還・階移動・保存／再読込・JSON往復で全状態を保持。旧セーブの既存所持・装備・薬・図書を維持。不正トークンの拒否。
- 図書館：鑑定成功のみ登録。誤装備・未鑑定売却・呪い解除で名称が判明しない。ログ・各画面で正式名・性能・実ID・通常売価が漏れない（装備による観測可能な変動と鍛冶屋料金は手掛かりとして許容）。
- 回帰：宝箱抽選、薬スタック、購入・通常売却、転職、装備効果、戦闘・キーボード操作。
