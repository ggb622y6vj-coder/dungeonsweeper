# 指示書116: 地図ブラインド時の通知と、透視中のゾーン枠表示

## 目的
指示書115で導入した 3F の「地図が見えない」ゾーンに、2つの表示を追加する（オーナー指示、2026-11-18）。

1. ゾーン内にいる間に地図ダイアログを開くと、地図の上に「地図が反応しない！」というメッセージが出る。
2. 3F で透視の呪文が効いている間、ゾーンの範囲が地図上で枠に囲まれて見える。

## 前提（115 の定義をそのまま使う）
- ゾーンは 3F のみ。中心 (5.5, 5.5) からユークリッド距離3以下、32マス。判定は既存の `isMapBlind()` と同じ計算（階と座標から描画時に導出、セーブ変更なし）。
- ゾーンの外周マス（4近傍のいずれかがゾーン外であるゾーンマス）は16マスある（実測で確認済み）。

## 変更内容

### 1. 「地図が反応しない！」の表示
- 地図ダイアログ（#mapdialog）内に、メッセージ要素（例：`#mapblindnotice`、文言は正確に「地図が反応しない！」）を置き、ダイアログ内の地図の中央に重ねて表示する。
- 表示条件は「地図ダイアログが開いている」かつ「ブラインド中（isMapBlind()）」の両方を満たすときだけ。ゾーン外で開いたとき、ダイアログを閉じたとき、PC 側の常時表示マップ（#mapdock）では出さない。
- 表示状態の同期は render() と、地図を開く処理（#maptoggle の onclick）の両方で行う（ダイアログを開く操作自体は render() を呼ばないため）。
- 別モーダルにはしない。地図を閉じる操作（#mapclose、キー操作）を妨げないこと（必要なら pointer-events を切る）。
- 見た目は既存パレットのトークンのみで作る（新しい色が必要なら :root にトークンを追加し、tests/css-structure.cjs を通すこと）。半透明の背景は従来どおりリテラル可。

### 2. 透視中のゾーン枠
- 「透視状態」の定義はゲーム内の既存定義と同一とする：`s.milwaSteps > 0 || s.light`（透視 milwa の効果中、または大透視 lomilwa の効果中）。発動中呪文リストの表示条件と同じ。
- 3F の盤面描画で、透視状態の間だけ、ゾーンの外周16マスについて、ゾーン外に面した辺に枠線を付ける。枠は紫系の既存トークン（透視のモチーフ色に近い --purple-76 を推奨）で、太さは控えめ（2px 程度）。
- 枠を付けたセルには目印のクラス（例：`zoneframe`）も付ける（テスト可能性のため）。
- ブラインド中でも通常描画でも付ける。ブラインド中は中身は見えないまま、枠だけが見える。通常描画ではセルの内容は従来どおり＋枠。
- 透視が切れたら枠は消える。3F 以外では付けない（ゾーン自体がない）。

## 変えないこと
- ゾーンの定義、ブラインド描画そのもの、一人称視点、移動・戦闘・呪文の挙動。
- ログへの追加はしない。セーブ形式は変更しない。
- 115 の新規テスト（tests/115-dark-zone-browser.py）の前提を壊さない（透視が無い状態では従来の描画と一致すること）。

## テスト
- 新規ブラウザテスト tests/116-map-blind-notice-browser.py を追加する。最低限：
  1. 3F ゾーン内で地図ダイアログを開くと「地図が反応しない！」が見える。ゾーン外で開くと見えない。閉じれば消える。
  2. 3F で透視状態（milwaSteps>0 または light）にすると枠付きセルが16個になる。透視が無ければ0個。
  3. ブラインド＋透視では、全セルがブラインド描画のまま枠付きセルが16個ある。
  4. 2F で透視状態でも枠付きセルは0個。
- 既存テストが新仕様で壊れる場合は、元の検証意図を弱めない範囲で追従修正してよい（判断したら報告に明記）。
