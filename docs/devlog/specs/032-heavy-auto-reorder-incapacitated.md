# 032 heavy: 行動不能メンバーの自動後退（前衛⇔後衛の自動入れ替え）

## 共通ルール
- 既存テストを弱めない。dist と MANIFEST を更新し、全テスト（tests/*.cjs、compile-monsters --check、sim selftest、browser テスト 1280/390）を通してから push。
- オーナー依頼 pt76u。

## 現状（6501fd7 で調査）
- 前衛／後衛は並び順のみで決まる（index 0–2 が前衛、3–5 が後衛。game.js の statcard、party パネル、training.js）。
- 自動並べ替えは無い。前衛が死んでも枠に残る。
- 敵の攻撃対象は「HP>0 の前衛」から選ばれる。前衛の生存者がいない場合、または後衛攻撃「可」の敵の場合は生存者全員から選ばれる（game.js の swings ループ）。このため前衛2人が倒れると、残る1人に攻撃が集中する。
- 並べ替えは手動の applyPartyOrder（party.js）だけ。PARTY_FIELDS=['members','hp','mp','inventory','equipped','armor','ailments'] を並べ替え、resetPartyCommands→refreshNames→render する。
- 戦闘中の予約（magicPlans / itemPlans / attackRows、味方対象の target）は index で持っている。

## 目的
Wizardry と同じく、行動できなくなったメンバーを自動で後ろへ下げ、動けるメンバーを前衛に詰める。

## 変更内容
- 「行動不能」の定義は、status が dead / ash / lost / stone（033 で追加）、HP≤0、または ailments.paralysis>0 のいずれか。
  - 睡眠は含めない。そもそも味方に睡眠を与える手段が現状は無い。
- 共通関数 `autoReorderParty(reason)` を追加する。
  - 並べ方は安定ソートで「行動可能 → 行動不能」。それぞれのグループ内の相対順は保つ。
  - 順番が変わったときだけ PARTY_FIELDS を並べ替え、refreshNames と render を行い、save する。
  - 戦闘中の magicPlans・itemPlans・attackRows と、味方を対象にした予約 target は、member id を使って新しい index に付け替える。予約は消さない。
  - 前衛（index<3）から後衛へ移ったメンバーごとに、ログ「{名前}が後列に下がった。」を1行出す。
  - 後衛から前へ詰めたメンバーのログは出さない（ログを短くするため）。
- 呼び出すタイミング:
  - 戦闘: 各行動（味方の1行動、敵の1体分の攻撃、毒・麻痺の tick）を処理した直後と、戦闘終了時（勝利・逃走・全滅以外）。
  - 探索: 罠、毒の歩行ダメージ、宝箱罠、呪文・薬の使用の後。
  - 町: enterTown の後とロード時（029/029b の搬送の後）。
  - 全滅時は呼ばない。030 の遺体処理の順序を変えないため。
- 麻痺が解けても自動で前へは戻さない（Wizardry と同じ）。戻すのは手動の並べ替えか、他のメンバーが行動不能になって押し出されたとき。
- ログのスナップショット表示（displayVitals.members）は、並べ替え後の順で記録する。前のログ行を再生するときに表示が食い違わないこと。
- アニメーションは必須ではない。順番とログが正しければ OK。入れる場合はカード位置の 150ms 程度のトランジションに留め、prefers-reduced-motion では無効にする。

## OKの判定方法
- 6人（前衛 A,B,C／後衛 D,E,F）で戦闘中に B が死亡すると、順は A,C,D,B,E,F になる。ログ「Bが後列に下がった。」が1回出て、party パネルとステータスの前衛/後衛表示が一致する。
- 続けて A が麻痺すると C,D,E,A,B,F になる。後ろへ回ったメンバーの間では元の順（A,B）を保つ。
- 敵の攻撃は新しい前衛（C,D,E）に向かう。node テストで乱数を固定して確認する。
- 戦闘中の予約が付け替えられている。例: Dの予約呪文と、Bを対象にした回復予約が、並べ替え後も同じ人物を指す（予約がある場合）。
- 探索中に罠で前衛が死亡したときと、町への帰還時も並べ替わる。リロード（ash-v1）後も順が保たれる。
- 行動不能者が前衛にいないときは並べ替えもログも起きない。全滅フロー（030/031）の挙動とテストは不変。
- 1280/390 の browser テストで party パネルの順・前衛/後衛ラベル・ログを確認する。JSエラーと横スクロールが無いこと。
- tests/auto-reorder.cjs と tests/auto-reorder-browser.py を新規追加し、既存テスト全 PASS。
