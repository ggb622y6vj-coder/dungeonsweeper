# 087 実施報告：昇降機で戻ったとき、探索済みの階段は見えたままにする

## 原因

- 076 の修正で `travelElevator()` が到着時に開始地点（階段）を無条件で未探索へ戻していた。新規生成の階では階段が生成都合で探索済みになるため閉じる必要があるが、保存済みの階でも同じ処理が走り、実際に踏んで探索済みにした階段まで巻き戻っていた。
- 076 の報告時に実施者が「過去に階段を踏んだことがある階でも閉じる仕様」と伝えていたが、ユーザーから今回、正しい仕様は「探索済みにした階段は見えたまま、未探索の階段は見えないまま」と訂正された。

## 実装（実施者が直接実施）

変更は到着処理の条件1箇所と既存テストの前提更新に限られるため、Codex は使わず実施者が直接実装した（モデル・トークン消費なし）。

- `dist/game.js` の `travelElevator()`：到着階が今回の移動で新規生成された場合（保存状態がなく `fresh(n)` を呼んだ場合）に限って、開始地点を未探索へ戻すよう条件を変更した。保存状態から復元された階では、階段マスの探索状態を保存どおりに保持する。到着地点（昇降機マス）を開く処理、`s.start!==s.pos` のガード、その他のマスの保持、セーブ形式は不変。

## テストの追随

- `tests/elevator.cjs` の往復復元アサーションが旧仕様（保存済みの階でも到着時に階段を閉じ、比較時に階段マスだけ未探索へ正規化）を前提にしていたため、新仕様どおり「全マスを開けた1Fへ戻ると、階段を含めて保存どおり完全復元される」前提へ更新した。
- 同ファイルに 087 の回帰ブロックを追加：新規生成の階では階段は未探索のまま、未探索のまま保存された階を往復しても未探索のまま、階段を踏んで探索済みにした階を往復すると見えたまま。

## 検証（実施者）

- 修正前再現：現行 main（e2e9e21）で、階段を踏んで探索済みにした2Fへ昇降機で戻ると階段が未探索へ戻ることを再現。修正後は同手順で見えたままになることを確認。
- node テスト 41/41、ブラウザテスト 37/37、compile-monsters --check（100種）、sim selftest、すべて合格。
- 実経路（ブラウザ実操作）：新規の2Fへ昇降機で到着したとき地図の階段マスは未探索表示、階段を踏んだ後は探索済み、昇降機で往復した後も地図に「⇧」が表示されたままであることを確認した。
