# 140 睡眠の回復判定

実施日 2026-11-25。対象ブランチ `hold/140`。[指示書140](../specs/140-sleep-recuperation.md)

## 実装

- 味方は戦闘が続くラウンドの末尾に、眠っている各人が 10%×本人のLv（上限50%）で目覚める。逃走失敗でも判定し、戦闘終了時に残った睡眠は探索へ持ち越す。
- 敵は自分の手番で、毒ダメージ処理の後に 20%×モンスターLv（上限50%）で目覚める。成功すると「○○は目を覚ました。」の後に通常行動へ進む。失敗すると「○○は眠っている。」と記録して行動を休む。味方・敵とも失敗時は睡眠値を保持する。
- 誘睡の説明をゲームとNotionスナップショットの両方で更新した。新規テストでは回復確率の境界、ログの順序と状態、逃走時の判定、旧睡眠値での連続失敗、目覚めた敵の攻撃、守護者への誘睡無効を確認した。

## レビュー

Claude Code（--model opus、読み取り専用）で実施。判定は「統合可・必須修正なし」。

- 味方の判定確率・タイミング・呼び出し箇所（attack() 末尾と flee()、沈黙/恐怖の tick の直後）が仕様どおりで、戦闘終了の3経路（勝利・全滅・逃走成功）では s.enemy が null のため判定が走らないことを確認。
- 敵の判定は行動順に1回だけ行われ、成功時はそのまま行動し、失敗時は休む。e.sleep を減らす処理は dist/ に残っていない。毒処理との前後関係も従来どおり。
- 目覚めログは値を0にしてから出されるため、ログ再生の表示がそのコマから切り替わる。
- 誘睡の説明文は MAGIC と notion-spells.json の両方で仕様 §3.4 と完全一致。
- 既存テストの追従は検証を弱めていない（固定2回の前提を、乱数を固定して判定を失敗させる形に置換）。

任意提案（将来候補）: 誘睡の旧文面「2回の敵行動を停止」が docs/DATA_CATALOG.md、data/catalog.snapshot.json、SPELLS.md に残っている（SPELLS.md は参照資料のため据え置き可。DATA_CATALOG.md は「現コードから抽出した全データ」と説明されているため、将来の文書整理で合わせるとよい）。また新規テストの敵Lv境界は CSV 上のLvに依存しているため、将来のLv変更に弱い。
