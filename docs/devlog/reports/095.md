## 経緯

## 実装内容（仕様：docs/devlog/specs/095-elite-jobs.md）

- CLASSES に上級4職を追加（dist/balance.js）。侍（hp30／xp1.40／mpFromLevel 4）、君主（hp32／xp1.50／mpFromLevel 4）、忍者（hp27／xp1.45）、司教（hp24・mp18／xp1.60）。忍者の即死、司教の鑑定、新規呪文は入れない。新規作成では上級職を選べないまま（generateRecruit の job 0〜3 検証はそのまま）。
- 転職条件の拡張（dist/recruits.js、dist/training.js）：転職先を 0〜7 に広げ、上級職には前職条件を設けた（侍＝戦士または魔法使い、君主＝戦士または僧侶、忍者＝戦士または盗賊、司教＝魔法使いまたは僧侶）。満たさない場合は理由を表示して拒否する。訓練所の候補一覧を8職に広げ、CLASS_FEATURES に4職分の説明を追加した。
- 装備互換（dist/weapons.js の canEquipJob、dist/items.js の lootRecipient）：アイテムデータの classes は書き換えず、上級職の読み替えを持たせた（侍→戦士、君主→戦士・僧侶、忍者→盗賊、司教→魔法使い・僧侶）。lootRecipient の受取先判定を canEquipJob に切り替えた。starterWeapon は上級職は読み替え先の先頭職の武器にする（所持品が空のときの救済処理）。
- 能力値フォールバック（dist/game.js の strengthFor／agilityFor）：基礎値表を8職分に拡張（STR：侍13・君主14・忍者12・司教9、AGI：侍10・君主9・忍者14・司教9）。
- 成長：MP 成長の開始レベル（dist/game.js の levelUp）：侍・君主は Lv4 で最初の MP上限加算を行う（mpFromLevel: 4）。転職時の MP上限は 094 の規則どおり max（転職前, 新職の mp 基準値）。
- 呪文習得の拡張（dist/spells.js の magicLearning）：侍・君主は Lv4 から有効習得Lv1（⌊(level−2)/2⌋）、司教は両系統を ⌊(level+1)/2⌋（Lv1 で1、Lv3 で2）、忍者は新規習得なし。呪文タブの初期系統は職→優先系統の対応で判定する（魔法使い・侍・司教→魔法使い系、僧侶・君主→僧侶系）。
- 戦闘・特殊能力の一般化：物理攻撃の回数は戦士 1+⌊Lv/5⌋、侍・君主 1+⌊Lv/6⌋、忍者 1+⌊Lv/8⌋、その他1回。命中成長の上位グループを [戦士, 僧侶, 侍, 君主] に広げた。解呪コマンドは僧侶と君主が使える（司教は使えない）。床罠解除は盗賊と忍者、宝箱の解除は盗賊85%・忍者75% で担い手の職業名をボタンに動的に出す。
- 転職履歴の修復と呪文補完の判定根拠（094 レビューの申し送りA）：ensureCareerHistory の修復を「不正な要素だけを取り除き、有効な履歴を残す」に変えた。メンバーに classChanged（転職したことがあるか）という真偽値を持たせ、転職確定時に true にする。読込時は有効な履歴が残っていれば classChanged を true に補完する（一度 true になったら false に戻さない）。補完の可否判定は「classChanged が true、または履歴が1件以上ある」のどちらかで止める。
- セーブ互換：キー ash-v1 と rosterVersion:1 を維持。旧セーブ（職業0〜3のみ）はそのまま読み込め、自動で転職したり呪文を再抽選したりしない。読込の繰り返しで known・xpTargets・装備・履歴・classChanged が変化しない。

## テスト是正2件（ゲームコード変更なし）

いずれも期待値の緩和ではなく、診断に基づく準備データと前提の是正である。

1. tests/elite-jobs-browser.py：司教シナリオの魔法使いフィクスチャの known を `['halito','dumapic']` から `['halito','dumapic','identifyfoe','makanito']` に変更し、転職・再読込後の known の期待値も同じ並びに合わせた。理由：フィクスチャの render() で旧セーブ向け補完（ensureMagic）が働き、Lv10 の魔法使いには識別（レベル条件なし）とマカニト（Lv9以上）が付与されるのが現行仕様であり、実測でも転職前後で4呪文が正確に保持された。実在の Lv10 魔法使いの習得状態に合わせる是正。
2. tests/class-change-browser.py：「武器不足」フィクスチャ（僧侶 Lv10、所持品はメイスのみ）は、095 で君主・司教が僧侶の装備互換を読むようになったため正しく転職可能になり、094 時点の前提が崩れた。registerRecruit の後に当該控えレコードの inventory を空（`s.reserve.find(r=>r.members.id===noWeapon.members.id).inventory=[]`）に変更した。「転職ボタンが押せず、理由に『武器』を含む」という検証はそのまま維持する。理由：仕様変更に伴う前提の是正。武器が1本もなければ全転職先が武器条件で拒否される。
