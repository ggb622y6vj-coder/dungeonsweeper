- 日付：2026-11-18
- ブランチ：hold/117（基準 main 5b1aa45）

- 経緯：ユーザーの発案。4F の中心部（3F と同じ半径3・32マス）を呪文が使えないゾーンにする。Muse の解釈（解除対象は発動中の魔法欄の4種、打ち消しは castMagic と敵呪文分岐で一括、枠は赤の破線、ログ文は「反呪文の結界に打ち消された！」）をユーザーが承認し、実装担当に Codex を指定。

## 変更内容
- ゾーン判定：isAntimagicZone()（floor===4 かつ現在地が inMapBlindZone 内）。3F の幾何を共用。
- 解除：dispelAntimagicEffects() が milwaSteps・light・watchful・flagSight・teppeki を無言でクリア。位置変更を setPlayerPosition() に集約し（通常移動・戦闘・転移呪文・落とし穴・転移罠）、travelElevator は到着位置の確定後に呼び、render() も既定で（settledPosition）解除する。階復元時の fresh は着地点が後から決まるため settledPosition:false で内部 render の早期解除を避ける。奇襲判定は解除後の状態で評価される。
- 発動中の魔法欄：activeSpellEffects() にゾーン内のみ「反呪文の結界」（説明・残り「このマスにいる間」）を追加。
- 味方の打ち消し：castMagic で使用可否チェック通過後・コスト消費前に判定し、ログ「反呪文の結界に打ち消された！」を出して false を返す。MP・血の代償 HP・使用回数カウンタは消費しない。spellReason にはブロックを足していない（選択はでき、唱えた時点で打ち消される）。
- 敵の打ち消し：monsterAction の呪文分岐で沈黙チェックの後に判定し、同じログを出して行動を消費（return true）。ブレス・仲間呼びは対象外。
- 透視枠：render の枠クラス選択を階で分岐（3F=zoneframe 紫・実線、4F=antiframe 赤・破線）。mapZoneFrame を枠名パラメータで共用化し、透視判定には既存の hasLight() を使用。CSS 4規則を追加（--red-75、2px dashed）。
- tests/117-antimagic-zone-browser.py：新規。解除の無言性と対象範囲（状態異常・使用回数は不変）、発動中欄の表示、探索・宝箱・戦闘・敵呪文の打ち消しと MP 不消費、枠の色・線種・階分離、5F で無効なことを 1280/390px で検証。
- 判断事項：descendPitfall の到着ログの出力位置を、位置確定（setPlayerPosition）の後ろへ移動（travelElevator の既存パターンに合わせたもの。ログの内容・順序に観測可能な変化はなく、移動系の特性テストも通過）。

## ChatGPT レビュー
- 2026-11-18、レビュー専用チャットで依頼。判定：**統合可・必須修正なし**。
- 評価：解除の同期箇所（setPlayerPosition・travelElevator・render の settledPosition）と奇襲判定の順序、castMagic の打ち消し位置（マハマンのレベル低下や旗消費などの特殊な代償も共通の早期終了で保護される）、敵呪文の return true による行動消費、3F との機能分離はいずれも妥当とされた。Amendment 1 は検証意図を弱めていないと確認された。
