# 090 実施報告：階層移動の骨格共通化リファクタリング

## 概要

- 指示書089（特性テスト）で固定した現行挙動を土台に、階層移動3経路（階段 travelFloor／昇降機 travelElevator／落とし穴 descendPitfall）に重複していた「現在階の保存→移動先の復元または新規生成」の骨格を、内部ヘルパー enterFloor() に共通化した。外部から見た挙動は変えていない。
- 実施範囲は、ChatGPT・Grok Bot 両レビューの統合結論（旧089下書き）どおりに限定した。到着後処理の共通化と罠効果の部品化（旧案B）は行っていない。

## 変更内容（dist/game.js、dist/traps.js のみ）

- enterFloor(next, {keepLog} = {}) を rememberFloor() の直後に新設。現在階を rememberFloor() で保存し、s.floors と s.scan を退避したうえで、保存済みなら structuredClone で復元して共通の状態整理（area、done、enemy、pendingBoss、pendingStairs）を行い、なければ fresh() で生成して floors/scan を引き継ぐ。新規生成なら true、復元なら false を返す。
- keepLog は落とし穴専用の例外：fresh() の前に logQueue を退避し、生成後にキューへ戻してポンプを再開する現行処理をそのまま移した。
- 3関数はヘルパーを使う形に変更。到着ログは復元時のみ、従来の条件（階段は町からと同一階を除く）のまま、ヘルパー直後の他のログが割り込まない位置で出すよう移した。
- 到着後処理はすべて各関数に残した：到着位置、階段マスの開閉（076・087）、milwaSteps のリセット条件（階段は階が変わったときだけ）、pendingElevator のクリア（昇降機と落とし穴だけ。階段が触らない非対称も維持）、clearNotice、render() の呼び出し（落とし穴は呼ばない）、戻り値（travelFloor は undefined のまま）。
- rememberFloor() の先頭に保存7項目（floor、size、cells、start、boss、relic、guardianKilledThisRun）の一覧と、追加時は特性テストの期待値も更新する旨のコメントを追加。保存項目自体は不変。
- triggerFloorTrap() と triggerChestTrap() の先頭に、針のダメージ式と締めの処理をもう一方と同期させる旨の相互コメントを追加。罠効果のコード自体は共通化していない。
