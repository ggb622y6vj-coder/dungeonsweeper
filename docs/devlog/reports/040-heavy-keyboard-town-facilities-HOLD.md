## 保留理由（指示書と既存チェックの矛盾）
指示書「町メニュー（2列）: 038 の位置移動でそのまま上下左右に動く」は、038 の位置移動（中心距離のみ）では成立しない。
- 1280: 訓練所で D → 酒場ではなく「迷宮への入り口」へ移る（入口: 距離²≈25,000、酒場: ≈82,000）。鍛冶屋で D → 入口、酒場で A → 入口。
- 390 も同じ（訓練所で D → 入口）。
- 2列の左右移動は、全幅の入口・図書館に取られてしまう。

hold/040 での修正案:
- KeyNav.nearest で、移動方向と垂直な範囲が重なる項目（同じ行・列の帯）を優先し、帯の中で中心距離が最小のものを選ぶ。該当がなければ従来どおり。
- これで 2列の上下左右が自然に動く。tests/keynav.cjs の既存チェックもそのまま全部PASS（町の配置の回帰を追加）。
- ただし 038 の tests/keynav-browser.py にある独自の期待値計算（move_in_town、中心距離のみ）は、新しいルールと合わない。このため、同じ厳しさのまま「帯優先」に書き換えた。既存チェックの期待値を変えることになるので、オーナー／試遊の承認待ち。

選択肢:
(a) 帯優先を採用（hold/040 をそのまま main へ）
(b) 038 の中心距離を維持し、2列の左右移動は諦める（town-keys-browser.py の D→酒場 などを削る）
(c) 町のレイアウト側で対処

## Codex の実装
- 町の既定フォーカスを「迷宮への入り口」に（無効時も論理フォーカス）。
- KeyNav:
  - タブ行の A/D 循環、Q/E 近道、S でリスト先頭、先頭の W でタブへ戻る。
  - リスト内の W/S は項目順。修飾キーは無視。
- 名前欄:
  - Enter で登録（未生成なら生成してから登録）。
  - Esc で「生成・再生成」へ抜け、2回目の Esc で閉じる。
- 酒場に「登録・加入・外す・抹消」ボタンを追加。訓練所の登録画面を重ねて開き、閉じると酒場のロスターを再読込する。
- 訓練所に「順番変更」dialog を追加:
  - Space でつかむ（破線と「選択中」の表示、aria-pressed）。
  - 移動先で Space を押すと reorderParty で入れ替える。
  - Esc は1回目で選択解除、2回目で閉じる。
- 寺院の既定は先頭の治療ボタン。抹消・リセット確認の既定ボタンの文言を「いいえ」に変更。
- 図書館:
  - 呪文タブ（全26呪文）を追加。
  - 各項目は role=button で、詳細 dialog を開く。
- 新規 tests/town-keys-browser.py（page.keyboard のみ。evaluate は確認だけに使用）。

   - 起きていたこと: Space 連打で抹消確認を閉じてすぐ開き直すと、古い close で pendingDelete が null になる。そのため D→Space で抹消されなかった（town-keys-browser が約半分の確率で失敗）。

3. town-keys-browser.py の搬送報告クリア確認を、close イベントの後まで待つように変更（同じ非同期の理由）。
4. docs（SPECIFICATION/HANDOFF）を更新。
