# 131　随伴連鎖と戦闘画面の敵表示

実施日 2026-11-23。ブランチ `hold/131` の作業ツリーで実装・自己検証。

## 実装

- 通常遭遇は同階の出現候補から先頭を選び、直前の種の有効な随伴抽選に失敗すると終了する。未設定・率0・随伴先が現階層で無効なら、同じ出現候補から選んで続ける。上限は1Fで2列、2Fで3列、3F以降で4列。撃破済み守護者の重複置換は連鎖の確定後に行う。
- 専用随伴のある守護者は2列目を確定し、その種から通常と同じ規則で続ける。専用随伴がない場合は従来どおりランダムな2列目が確定し、50%で3列目が出る。遭遇生成は4列目も個体・安定した列IDに展開する。敵データ・群れの数・セーブ形式に変更なし。
- アイコンは表示中の前2列に各1体。最初の未精算個体のUID・睡眠表示を使い、横中央に置く。左上には全列の未精算個体数と、そのうちHPが正で睡眠・麻痺・石化・恐怖のない個体数を表示する。沈黙・毒は除外しない。アイコンと一覧は同じ `visibleCombat()` の結果を参照する。

## 指示書と既存テストの照合

- §4.1 の例は全角括弧で、本文には「半角括弧」と明記されている。画面とテストには本文指定の `1列：ゴブリン ×3(2)` を使用した。
- 123の連続守護者抽選は、1Fでは旧期待の3列を生成できず、3F以降では未設定種が4列まで続く。実際の全10階で上限まで守護者を連続して引き、最初の1列だけ残ることを確認した。さらに各階の候補をテスト内だけ3列上限の2Fに配置し、元の2種類の期待配列、置換順、余分な抽選がないことを検証した。随伴率を0にするのは従来と同じ2種だけ。単独守護者の通常報酬テストはテスト内だけ1F守護者に随伴を設定し、失敗で1列にして元の報酬・進行の期待値を維持した。
- 130の随伴設定108種・無効な設定のフォールバックを引き続き確認する。新設の連鎖テストは率の境界、ランダム継続後の随伴、階ごとの有効性、専用随伴の有無、守護者の重複、4列目の実体化を固定乱数で確認する。072の3種の出現階テストも新しい乱数消費順に合わせ、実際の遭遇生成で各列の種と頭数を確認する。
- 既存の窒息ブラウザテストはログごとに表示中の前2列のUIDを照合する。新規ブラウザテストは3列の戦闘を使い、PC幅・スマートフォン幅で代表UID、配置、Zzz、全列の総数と行動可能数、先頭列消滅に伴う繰り上がりを検証する。
