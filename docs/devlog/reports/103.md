# 指示書103 実施報告：「呪いを解く」の対象列が1つのとき自動選択

## 依頼

僧侶の「呪いを解く」が、対象となる敵の列が1つしかない場合、選択肢を出さずに自動的にその列を選択する。Codex は利用上限のため使わず、Grok Build で実装する。

仕様： docs/devlog/specs/103-dispel-single-row-autoselect.md

## 実装（Grok Build：grok-4.7、reasoning medium）

- dist/combatui.js のコマンド確定処理で dispel 分岐を変更。livingUndeadGroups() が1つなら、その列のキーを s.dispelRows[i] に設定して confirmCommand(i)。2つ以上なら従来どおり列選択を表示。0の場合はボタンの無効化とハンドラのガードを維持。「戦う」の単一列の自動選択と同じ形。
- docs/SPECIFICATION.md の「呪いを解く」節に自動選択の仕様を追記。
- テスト：tests/dispel-row.cjs に実際の onclick ハンドラ経由の確認を追加（1列＝即確定・列選択なし・要約「→ 1列」、2列＝不死の列だけ選択表示、0列＝確定されない）。tests/dispel-row-browser.py は単一列の自動選択を実ブラウザで確認するよう更新。tests/battle-keys-browser.py は解呪のキーボード確認を2列の場面に寄せ、tests/elite-jobs.* は君主の解呪フローに追随。

### 経緯の記録

- Grok の1回目の実行は、ヘッドレスでは承認できないコマンド実行の承認待ちで中断し、変更なしで終わった（費用 $0.37）。再実行は --always-approve を付けて開始した。
- 再実行の途中で実行環境が再起動し、Grok のプロセスが中断された。実装とテストの編集は作業ツリーに残っていたため、調整役が差分を全件確認し、残りの検証・記録・コミットを引き取った（実装そのものは Grok の変更のみ）。
- tests/battle-keys-browser.py で、対象列ボタンの指定が2ボタンに曖昧になる不整合が1件見つかり、ユーザーの承認を得て調整役がセレクタを既定行に特定する1行を修正した。
