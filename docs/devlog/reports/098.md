# 098 実施報告：石化は町（寺院）でのみ治療可能にする ― Codex と Grok Build の比較実験

## ユーザー指示

「石化が町に帰るまで治療できないようにする」変更を題材に、Codex と Grok Build の両方へ同じ仕様書を別ブランチで実装させる比較実験として実施（2026-11-10）。Notion の DB は両方とも触らないようユーザー指示あり。

## 実験の進め方

- 共通仕様 `docs/devlog/specs/098-stone-cure-town-only.md` を、main `ebbf870` から分岐した `hold/098-codex` と `hold/098-grok` の両方へ同じコミット（`1e84fbb`）で配置。
- Grok Build 側は `docs/devlog/grok-build-notes.md`（096 の中断記録）の作法に従う：長いコマンドには `timeout`、フルスイート前にコミットして push、`--output-format streaming-json`、短いテストから実行、作業場所はリポジトリ内の worktree。
- 検証は Muse が両ブランチで同一条件（node・ブラウザ・compile・sim・MANIFEST）で実施。ChatGPT へ両ブランチの比較レビューを依頼し、最終判断はユーザーが行った。

## 仕様の固定事項（要約）

- 真回復（madi）で石化を治せなくする。真回復の他の効果は不変。
- 石化メンバーは真回復を含むすべての味方対象呪文・薬で対象に選べない。万一実行されても拒否文言を表示し、MP・アイテムを消費せず HP・状態を変えない。
- 寺院の石化解除、石化の付与、セーブ形式、真回復の説明文・SPELLS.md・data/notion-spells.json・Notion は変更しない。

## 実装結果

両者の実装はほぼ一致した。

- `dist/combatui.js`：戦闘時の対象選択から restore 例外を削除。**両者でバイト単位で同一**の変更。
- `dist/spells.js`：`castMagic` のガードと探索時の対象選択から restore 例外を削除する変更は両者同一。唯一の実質差は restore 処理で、Codex 版は到達不能になった `status='ok'` の代入を残し、Grok Build 版は restore 処理から status への操作自体を削除した（石化解除ログは両者とも削除）。
- `tests/petrify.cjs`：両者とも新仕様へ書き換え（対象に選べない、実行しても拒否され消費しない、戦闘中の予約でも同様、寺院解除は維持）。書き換え量は Codex 63 行、Grok Build 67 行。
- `docs/SPECIFICATION.md`：両者とも石化は寺院でのみ解除できる内容へ更新。

### 担当と消費

- Codex（`hold/098-codex`、gpt-6.1-sol＋medium）：実装 約3.3分・95,500トークン（コミット `e7bb282`）。サンドボックス制約のためコミット・push は Muse が実施。
- Grok Build（`hold/098-grok`、grok-4.7＋medium、セッション上のモデル ID は grok-4.7-build）：実装 約7.0分・$1.64（入力 275,796、キャッシュ読込 1,872,128、出力 25,666。計数方法が Codex と異なるため単純比較はできない）。作法どおり自力でコミット（`859cf63`）・push してからフルスイートを実行し、096 型の停滞は起きなかった。

## Amendment 1（ブラウザテストの新仕様化）

- 初回検証でブラウザテスト 2 件（`tests/petrify-browser.py`、`tests/battle-keys-browser.py`）が両ブランチとも落ちた。原因は実装ではなく、テスト側が旧仕様（真回復で石化を治せる）を固定していたためで、変更前の main では両方とも合格することを別途確認した。仕様書がブラウザテストの書き換えを実装範囲に含めていなかったことが実験側の不備。
- 両担当へ同一条件で書き換えを依頼。Codex：約2.9分・55,663トークン（コミット `42d4351`、ブラウザ実行はサンドボックス不可のため Muse が検証）。Grok Build：約9.2分・$2.02、自力でコミット（`dd7d7d1`）・push し、ブラウザテストも自力で実行して合格を報告。
- 書き換え後のブラウザテスト 2 ファイルは両ブランチで同一内容に収束した。なお Grok Build 側は worktree 共有の git 参照を通じて Codex 側の書き換えを参照できたため、Amendment 1 は完全なブラインドではない（実装本体に参照の形跡はない）。

## ChatGPT 比較レビュー（2026-11-10）

- 会話：https://chatgpt.com/c/6af2e6ce-7c90-83ee-8350-20346a867784
- 判定：両者とも合格。仕様適合とテスト品質は同等で、restore 処理の不要な状態変更を削除している分だけ Grok Build 版が僅差で優位とし、採用推奨は `hold/098-grok`。
