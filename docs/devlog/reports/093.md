# 093 実装報告：落とし穴で生成された階の上り階段を隠す

## ユーザーの依頼

「落とし穴で下の階に落ちたんですけど、上り階段が地図上で見えるようになってました。再現できますか？」→ 再現確認のうえ「指示書093として修正する」と決定。仕様は docs/devlog/specs/093-pitfall-stairs-hidden.md。

## 再現結果（着手前、現行 main 26b2ed4）

実経路（triggerFloorTrap / openChest → descendPitfall）で確認した。

- 未生成の階への落下（床罠・宝箱罠とも）：着地マスと別の開始マス（上り階段）が open になり、盤面に ⇧ が出る。再現する。
- 保存済みの階への落下、昇降機での未生成階への到着：発生しない。

## 原因

階の生成 fresh() が開始マスを open=true で作る（階段到着は開始マスに着くため正しい）。travelElevator は生成時に開始マスを閉じ直すが、descendPitfall にはその処理がなかった。

## 実装（Muse が直接実施）

変更は dist/traps.js の1条件のみで影響範囲が狭く、087（昇降機の同種の修正）と同じ形のため、Codex を使わず Muse が直接実装した（トークン節約）。

- dist/traps.js（604f415）：descendPitfall() で、到着した階が新規生成（generated）の場合に限り、着地先が開始マスでないとき開始マスを閉じる（`if(generated&&destination!==s.start)s.cells[s.start].open=false`）。着地候補がない場合の開始マスへのフォールバックは開いたまま（従来の保存済み階フォールバックの固定挙動と一致）。保存済み階の復元と fresh() 自体には触れていない。

## 回帰テスト（tests/pitfall.cjs に追加）

- 床の落とし穴で未生成の階へ落ちたとき、開始マスが閉じていて盤面に ⇧ が出ないこと（着地マスは開いている）。
- 宝箱の落とし穴で未生成の階へ落ちたときも開始マスが閉じていること。

### makanito-browser の失敗について（093 とは無関係の既存の揺れ）

- 症状：390px 側のシナリオで「獲得経験値＝敵3体分の合計」の検証が間欠的に失敗する。
- 切り分け：変更前の main（26b2ed4）の dist でも同じ検証が間欠的に失敗することを確認した（093 の dist と main の dist の双方で複数回実行し、両方で成功・失敗が混在）。
- 仕組み：テストの前提は「マカニト（Lv7以下を確実に即死）が敵3体全員に当たる」ことだが、092 で行動順が混ざった結果、ゴブリン（逃走40%・仲間呼び10%）が魔法使いより先に行動することがある。逃走すると経験値を落とさず、仲間を呼ぶと4体目が増えて、どちらも経験値の合計が合わなくなる。プローブで失敗時のログに「ゴブリンは逃げ出した。」が残り、経験値がゴブリン分（17）だけ少ないことを実測した。ゲーム側の挙動としては正しい（行動順どおりに逃げた／呼んだ）ため、テスト側の前提を直す話になる。
- 対応：ユーザーの指示で、本指示の中でテスト側を修正した。tests/makanito-browser.py の戦闘構築時に、対象の3体について逃走と仲間呼びを無効化する（このテストの対象はマカニトの詠唱であり、逃走・召喚ではない旨をコメントに明記）。修正後は12回連続（24シナリオ）で全合格し、揺れが消えたことを確認した。ゲームコードには触れていない。
